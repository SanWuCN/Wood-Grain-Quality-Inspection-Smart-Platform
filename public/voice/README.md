# 小木播报语音包（用外部 TTS 替换浏览器语音）

这个目录用来放**提前生成好的播报音频**。放进来就生效，不需要改代码。

## 一、机制（先说清楚，免得放进去不响）

- 播报时先拿"**正要念的那句话**"去 `manifest.json` 里**逐字匹配**：
  - 命中 → 播放对应音频文件；
  - 没命中 / 文件不存在 / 加载失败 → **自动回退浏览器语音**（`speechSynthesis`），界面文案不变。
- 为什么必须逐字匹配：同一意图的回答模板会随机挑同义说法，如果按"意图"硬播一段录音，
  就会出现**气泡里写 A、喇叭里念 B**，比声音不好听严重得多。所以宁可回退，也不播错。
- 想让它**稳定命中**，就把那句话的模板固定下来（去掉 `alternatives`），见第三节。

## 二、怎么生成（以 ttsmaker.com 为例）

1. 打开 https://ttsmaker.com/zh-cn ，语言选**中文（普通话）**，挑一个你喜欢的音色
   （建议语速略慢一点，小木是"助手"语气）。
2. 把下面第三节的句子**整句原样粘进去**（不要改标点，否则匹配不上）。
3. 生成后下载，**mp3 或 wav 都行**（两者都已实测可播）。体积换兼容性：wav 大但任何浏览器都稳。
4. 文件改名后放进本目录，命名规则：**按意图 id**，例如 `site_weather.mp3`。
5. 在 `manifest.json` 里加一行：`"<完整句子>": "/voice/<文件名>"`。
   - 注意：文件放在 `public/voice/`，但对外的路径是 `/voice/xxx.mp3`（`public` 不写进 URL）。
   - JSON 里如果句子本身带引号，记得转义；键必须**逐字**与播报文本一致（含全角标点）。
6. 刷新页面即可（`public` 下的静态文件由 vite 直接提供，不需要重启服务）。

> 提示：先用一句试通（例如下面的天气句），再批量做。改完刷新，听一下是不是录的那句。

## 三、优先录这几句（按价值排序）

**① 天气主回答（最高优先，AC-01 就是这句，且它是固定模板，必然命中）**

```
归档天气档案（2026-06-11 至 2026-09-10（近三个月））：梅雨期累计降水 412mm，8 月 3 次连续降雨过程，平均相对湿度 78%，日温差最大 11.4℃。数据来源：归档天气档案 · 非实时联网查询；这是归档数据，不是实时联网查询。
```

**② 失败/降级的固定提示**（这些也是固定文案，命中率高、用户最常听到）

```
没有听清，请再说一次。
```
> 其余降级文案见 `src/pages/MumaiDashboard/agent/degrade.ts` 的 `NOT_HEARD_TEXT` / `FALLBACK_SPOKEN`，
> 以那里的字符串为准（改过文案就要重新录，否则回退到浏览器语音）。

**③ 其余意图的主回答**：先跑一遍你要演示的流程，把气泡里出现的那句话整句复制出来，
再粘进 ttsmaker。要"以后每次都播录音"，就得把该意图的 `alternatives`（同义模板）收敛成一条固定文案——
那属于产品文案决策，改之前先确认。

## 四、验收（别靠耳朵猜，跑脚本）

在 `D:\平台\voice-module` 下（需 5173 在跑）：

```bat
node 验收语音包.mjs            :: 键是否逐字命中 + 音频能否加载 + 播报走录音还是合成音
node 诊断-播报媒体时间线.mjs    :: 打印每个 <audio> 的完整媒体事件时间线（排查"没响")
```

判据：`验收语音包.mjs` 结尾必须是 **`audio=1 synth=0`** —— 只要 `synth≥1`，就说明
那一轮退回了浏览器语音，按下面的顺序查。

- 想手动看：控制台里 `await fetch('/voice/manifest.json').then(r=>r.json())` 应能看到你的条目。
- 若仍是浏览器语音：① 键是否逐字一致（全角括号、`·`、`℃` 都要一样）；
  ② 文件路径是否为 `/voice/xxx.mp3`；③ 浏览器 Network 里 `xxx.mp3` 是否 200。

## 五、两个"看起来放好了但还是合成音"的真实坑（已修，留档备查）

**坑 1：同一意图有多个同义模板。** 回答是从 `alternatives` 里随机挑的，只录了其中一句，
另一句必然不命中 → 回退。表现是**时好时坏**。修法有二：把那句话固定下来（删掉
`alternatives`，`introduce_platform` 就是这么处理的），或者把每个变体都录一遍。

**坑 2：连着问两次时，作废的那一轮又合成了一遍旧文本。** 这一条是探针抓出来的硬故障：
第二轮的 `speak()` 一进来会 `silenceCurrent()` 把上一轮的 `<audio>` 清空，上一轮元素随即抛
`MEDIA_ELEMENT_ERROR: Empty src attribute` → 上一轮那个**早已作废**的 Promise 被兑现成
"音频没放成" → 于是合成了一遍**旧文本**，和正在播的新录音**叠在一起响**。
修在 `src/pages/MumaiDashboard/agent/tts.ts` 的共享函数里（不是补在某条调用路径上）：
`silenceCurrent()` 清 `src` 前先摘掉 `onended/onerror`；`playAudio()` 的 `finish()` 遇到
代次不匹配时按"已处理"收场（作废的轮次安静结束，**不回退合成音**）。
回归判据就是上面那条 `audio=1 synth=0`，以及连问两次后 `speechSynthesis.speaking` 仍为 `false`。

## 六、诚实边界

- 我**无法替你登录/操作 ttsmaker.com** 生成音频：那是一个需要人工在网页上点击的外部服务，
  我没有可用的浏览器操作手段，也不应该绕过它的使用条款。生成这一步必须由你完成。
- 如果你希望**完全不手动**，本机可用 Windows 自带中文语音（离线、一条命令生成 wav），
  声音明显不如 ttsmaker 自然，但胜在全自动。需要的话我把它做成一个脚本。

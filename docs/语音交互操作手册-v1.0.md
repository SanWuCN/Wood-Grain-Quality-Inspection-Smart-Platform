## 0. 一分钟上手

1. 打开平台任意已登录页面，看**右下角**：小木形象常驻在那里（默认待机，形象下方徽标写「待机」）。
2. 第一次使用先开常驻唤醒，两种点法任选：**点一下右下角小木形象**把气泡展开，再点气泡底部的「**开启常驻唤醒**」；或者展开右侧「小木助手」面板，点它头部的「**常驻唤醒**」按钮。页面弹出麦克风授权时选「允许」。
3. 说 **「小木小木」**（两遍，连着说），停一下（约 0.3–1.5 秒），再说命令，例如「**查近三个月天气**」。
4. 右下角出现气泡：先看到你说的字（绿色「正在听」），回答出来后会播报一次，气泡里有主回答、可折叠的「业务状态」「资料引用」和本轮时间。
5. 不想听了：按 **Esc**（停播报并收起气泡）；不想让它听：点气泡里的「**常驻唤醒：已开**」把它关掉。

> 记不住命令没关系：能听懂的话都在第 3 节，全部来自平台的意图语料，不是临时编的。

## 1. 三种进入方式

小木有三个入口，**发生的事不一样**，这点必须先分清。

### 1.1 说「小木小木」（默认、也是本次改造的主路径）

| 项目 | 说明 |
| --- | --- |
| 前提 | 必须先开启「常驻唤醒」。开法有两种：**点一下右下角小木形象**展开气泡，再点气泡底部的「开启常驻唤醒」；或点小木助手面板头部的「常驻唤醒」按钮（两者是同一个开关）。常驻唤醒不会因为页面加载自动开启 —— 一进页面就弹麦克风授权太打扰人，所以设计上要用户点一次；刚打开页面时气泡还不会自动展开（没有内容时只留形象），所以第一次要先点一下形象。 |
| 你说什么 | 连着说两遍「小木小木」，停顿约 0.3–1.5 秒，再说命令。 |
| 会发生什么 | 语音经本地服务判定唤醒 → 平台进入"收集命令"状态 → 你说的字**逐段变成文字**显示在右下角气泡里 → 说完后约 1 秒静音定稿 → 小木执行，结果只出现在**右下角气泡**里，主页面不被遮挡。 |
| 界面反馈 | 唤醒判定成功后**先没有任何变化**（徽标仍是「待机」）；第一段流式字幕到达时才变绿「正在听」并弹出气泡。原因与影响见 7.2。 |
| 不会发生什么 | 不会弹出覆盖屏幕的语音窗口（全屏控制台现在只是开发诊断入口，见 1.3）；不会因为你说的话和上一句一样就跳过不执行（同一句说两遍会执行两遍）。 |
| 说错了/没听清 | 见第 5 节。注意：唤醒成功后如果一直不说话，界面上**不会有任何提示**（7.5）。 |

### 1.2 点右下角的小木形象

| 项目 | 说明 |
| --- | --- |
| 前提 | 无。形象在所有已登录页面常驻，不需要麦克风权限。 |
| 会发生什么 | 点一次 = **收起或展开气泡面板**：面板正开着时点它 = 收起（走统一关闭），没开时 = 展开。形象带状态徽标（「待机 / 正在听 / …」），`aria-expanded` 与提示文字都跟着真实可见性走（开着时提示「点击收起」）。 |
| 面板里有什么 | 标题行（状态词 + 圆点、右侧一个意图/唤醒小标签、最右「×」按钮）、你那句话、小木的回复（主回答 + 可折叠「业务状态 N 项」「资料引用 N 条」+ 时间 + 语音包 + 置信度 + 「重播（Alt+R）」）、底部「常驻唤醒」开关与一句提示「两遍「小木小木」 → 停一下 → 说命令」。 |
| 重要限制 | **它不是"重新提问"的入口**：这里没有输入框，只说不了话。想说话就喊唤醒词，或去小木助手面板打字。 |
| 关掉它 | 点「×」或按 Esc（关掉后焦点会回到你唤起小木之前所在的那个控件）。被关掉的是**气泡（显示层）**，常驻唤醒继续在听 —— 要停止聆听必须点「常驻唤醒：已开」。 |

### 1.3 点小木助手面板里的入口

右侧「小木助手」面板（顶栏/右侧浮标「小木」展开）头部有三个按钮：

| 按钮 | 会发生什么 |
| --- | --- |
| 「**常驻唤醒**」/「**唤醒中**」（带波形图标） | 与右下角气泡的常驻唤醒开关**同一个东西**（都读写 `wakeChannel()` 单例）：点一下开始申请麦克风并常驻聆听，正在聆听时显示「唤醒中」，再点一下关闭并释放麦克风。 |
| 「**语音**」 | 打开**全屏语音控制台**。它是本次改造后保留的**开发诊断入口**，不是默认交互面：会出现覆盖大半屏幕的遮罩，里面有状态机徽标、麦克风电平、实时字幕、完整对话流、17 条示例问句（外加 1 个"多步任务"按钮）、按住说话、文本输入、清空对话、语音开/关和确认层。**点它会遮挡主业务页面**，日常使用请不要走这里。 |
| 「**×**」（关闭小木） | 收起整个小木助手面板，与右下角小木无关。 |

面板底部还有一个**文字输入框**（占位提示「例如：比较四根木柱 / 查今年五月示例寺巡检」），打字提问走的是面板自己的对话流；如果这句话对应的是**需要二次确认的高风险动作**，面板不会自己执行，而是**转去打开全屏控制台**让你在那里确认（原文提示：「…属于需要二次确认的动作（风险等级 3/4），已在语音控制台打开待确认；确认之前不会执行任何动作。」）。这条路径与语音气泡的确认面不是同一个界面，见 7.6。

### 1.4 三个入口的关系（一句话）

- 说唤醒词 → 结果落在**右下角气泡**（默认交互面）。
- 点形象 → 只是**看/收**最近一轮结果，不说话。
- 点小木助手面板 → 文字提问走面板；「语音」按钮进**诊断控制台**；「常驻唤醒」按钮控制麦克风。
- 另外，平台的 **COM4 串口语音设备**通道目前也是打开**全屏控制台**（不是右下角气泡），见 7.6。

## 2. 一次完整交互的步骤与时序

以下按"先开唤醒 → 喊两遍 → 停顿 → 说命令 → 看气泡 → 听播报"逐步写。时间数字来自实际实现（前端 `wakeChannel.ts` 与本地语音服务 `service/server.py` 的常量），不是估计值。

### 2.1 分步时序表

| # | 你要做的 | 界面上应该看到什么 | 背后发生了什么（简述） |
| --- | --- | --- | --- |
| 1 | 先点一下右下角小木形象展开气泡，再点「开启常驻唤醒」并允许麦克风 | 按钮变成「**常驻唤醒：已开**」（高亮）；若麦克风被拒或浏览器不支持 Web Audio，徽标变红「**出错了**」（具体原因只在浏览器控制台里能看到，见 7.8） | 开始 16kHz 单声道采集，与本地服务建立 `/voice-wake` 常驻连接；连接断开会按 0.5→1→2→4→8 秒退避重连 |
| 2 | 连着说两遍「小木小木」 | 暂时**没有变化**（仍「待机」）。说两遍的要求是硬要求：一次「小木」不唤醒 | 本地 KWS 判定。判定规则有两条分支，**都强制两遍**：① 1.5 秒窗口内命中 ≥2 次 → 直接唤醒；② 只命中 1 次 → 取命中点前 1.2 秒、后 0.6 秒的预滚音频交给 Whisper 复核，转写去标点后必须出现两次「小木」才唤醒 |
| 3 | 停一下（约 0.3–1.5 秒）再说命令 | 停顿期间一般仍无变化；如果你在唤醒词后立刻连着说，命令开头也不会被吃掉（唤醒前的预滚缓冲会接进命令音频） | 唤醒后进入"收集命令"状态，之后有 1.2 秒唤醒冷却，避免一句话被反复唤醒 |
| 4 | 说命令，例如「查近三个月天气」 | 气泡出现，先显示**你那句话**（蓝色用户气泡），状态词变绿「**正在听**」；文字是**就地更新**的，不会重复堆出好几条 | 服务端每约 300ms 推一次整句转写（音频不足 0.35 秒时不出字），前端整句替换 |
| 5 | 说完，停住不说话 | 约 **1 秒静音**后命令定稿（前端静音超过 1 秒就不再推流，服务端据此判定"说完了"）；一条命令最长 **8 秒**，超时按说完处理 | 定稿后转写文本交给平台执行器：规范化 → 意图匹配（规则优先，其次相似度）→ 槽位抽取 → 白名单工具 |
| 6 | 看气泡 | 状态词通常仍是绿「正在听」（原因见 7.3）；气泡里出现主回答；命中意图的 id 显示在标题栏右侧小标签里 | 查询类直接答（不会自动跳页，见 3.1）；操作类调用工具，"打开…/查看…"这类 ACTION 意图会真的跳页；风险 ≥3 的操作会先停下来等你确认（第 4 节） |
| 7 | 听播报 | 状态词变紫「**播报中**」 | 浏览器本地语音合成**只朗读主回答**，不逐项念字段名、来源定位和时间戳 |
| 8 | 播报结束 | 状态词回到绿「正在听」（若这次没有留下流式字幕，才是「待机」） | 小木说话期间前端暂停推麦克风音频（防自听回环）；命令交出后 **2.5 秒**自动恢复聆听，关掉气泡会**立即**恢复 |
| 9 | 接着问下一句 | 直接再说两遍「小木小木」即可 | 同一时刻只处理一条语音命令，新命令**排队**执行，不会两条交叉 |

### 2.2 状态词与颜色对照（形象徽标 + 气泡标题行圆点）

状态词来自气泡组件自己的七态（不是执行器的十个状态），颜色定义在 `xiaomuDock.css`：

| 状态词 | 颜色 | 什么时候出现 |
| --- | --- | --- |
| 待机 | 灰（徽标深蓝底、圆点 `#93a3bd`） | 没有待确认操作、没有错误、没有回复，且没有流式字幕 |
| 正在听 | **绿**（圆点 `#2fbf8f`，徽标 `#10674f`） | 有流式字幕（`wake.partial` 非空）或执行器状态为 LISTENING。**语音链路里最常看到的就是它** |
| 识别中 | 蓝（`#3f8ff0` / `#14477f`） | 只有诊断控制台里的"按住说话"会触发（执行器状态 RECOGNIZING）。**语音链路上不会出现** |
| 思考中 | 橙（`#b4791f` / `#6d4a0d`） | 执行器处于理解/规划/执行/等待工具。但只要这次留下过流式字幕，就会被「正在听」抢先覆盖（7.3） |
| 播报中 | 紫（`#7a5cf0` / `#3f2c8c`） | 语音合成开始到结束 |
| 等待确认 | **红**（`#d94a3d` / `#8c2119`） | 有未确认的高风险操作 |
| 出错了 | 红（同上） | 执行器报错（ERROR），或唤醒通道进入 `error`（麦克风被拒、浏览器不支持 Web Audio；**服务断开不算**，见 7.9） |

> 关掉动效（系统开启"减少动态效果"）时，动画会停，但**状态词和颜色仍在**，靠它们照样能分辨状态。
> 气泡最大宽度 420px、最高 46vh（矮屏 40vh），固定在右下角距边 24px，主页面始终可见可点。

### 2.3 气泡里各部分叫什么

- 标题行：状态词 + 圆点 → 右侧小标签（有回复时显示**命中的意图 id**，例如 `site_weather`；没回复时显示「常驻唤醒已开」或「待命」）→ 最右「×」（提示「关闭（Esc）」）。
- 你那句话：一个整体气泡，识别过程中实时改写。
- 确认卡片（只在等待确认时出现）：标题是一句问句，下面一行说明（工具描述 + 风险等级 N/4 + 参数 JSON），两个按钮：「确认执行」和取消按钮。
- 主回答：**永远不折叠**。归档/非实时联网这类声明就写在主回答正文里，所以只要主回答可见，声明就可见。
- 「业务状态 N 项 ▸/▾」：可折叠，展开是结构化字段（例如天气的 `weatherRange` / `weatherSummary` / `weatherSource`）。
- 「资料引用 N 条 ▸/▾」：可折叠；展开后每条是「标题 + 原文位置」，**点一下就地展开原文片段**。
- 底部：本轮时间（`HH:mm:ss`，是本轮实际生成时间，不是显示的当前时间）、语音包标签、置信度（规则命中不显示）、「重播（Alt+R）」。
- 备注行（`note`）：解释这一轮为什么这么答（低置信、未命中、工具失败等）。

## 3. 能问什么

以下清单由平台意图目录 `src/pages/MumaiDashboard/agent/intents.ts` 归纳：共 **29 条意图**（PRD 4.2 的 14 条 + 平台介绍与页面导航 5 条 + 小车与建图控制 9 条 + 1 条多步编排），背后是 **20 个白名单工具**。

### 3.4 多步编排（一句话里多个动作）

`robot_patrol_route`：平台会先**规划**成一条计划（理解任务 → 生成执行计划 → 逐条动作），界面显示 ✓/●/○ 步骤清单，**在执行前整条任务一次性确认**（不是每步都弹确认）。

语料原句（这些就是能听懂的说法）：

- 「让小车先去一号木柱，再绕一圈，然后回来」
- 「让小车去一号木柱拍摄一圈，然后回来」
- 「先去一号柱，再环绕一圈，最后返回起点」
- 「让小车去二号木柱绕一圈然后回起点」
- 「让小车先去一号木柱，再去二号木柱，然后返回起点」
- 「让小车沿四根柱子走一圈再返回起点」

> 多步编排内部用的工具是「去目标点 → 开始扫描 → 环绕目标点 → 返回起点」。因为含风险 3 的动作，整条任务必须确认一次。

### 3.5 说话习惯建议

- **一条命令说一件事**，说清对象：「让小车去二号木柱」比「去那边」好命中。
- 平台**不做多轮上下文**：上一句说过的柱子，下一句不能省（没有"它""那个"的指代解析）。
- 语料里有的说法命中率最高；同一个意思的其它自然说法靠相似度匹配，也可能命中，但**低置信命中的操作类指令不会执行高风险动作**。
- 槽位缺失时会如实回你「这条指令还缺一个必要参数，我没有执行。」并提示可选构件（Z01 / Z02 / Z03 / Z04），不会猜一个执行。

## 4. 哪些操作会要求二次确认（风险 ≥3）

风险分级是写在工具白名单里的固定属性：`0 查询 / 1 UI 操作 / 2 普通设备操作 / 3 机器人运动 / 4 危险或删除操作`；**风险 ≥3 的工具一律要求确认**，且**低置信命中时即便确认也不会执行**（见 4.4）。

### 4.1 会弹确认的操作清单

| 你说了什么（语料原句） | 确认卡片标题（原文模板） | 风险 |
| --- | --- | --- |
| 「让小车去一号木柱」「让小车去 Z02 观察点」 | 「确认让小车前往{构件号 构件名}吗？」 | 3/4 |
| 「开始巡检」「启动巡检任务」 | 「确认让小车开始执行巡检任务 {任务号} 吗？」 | 3/4 |
| 「取消当前任务」「取消巡检」 | 「确认取消巡检任务 {任务号} 吗？」 | 3/4 |
| 「让小车回来」「让机器人返回起点」 | 「确认让小车返回起点吗？」 | 3/4 |
| 「开始建图」「启动 SLAM 建图」 | 「确认让小车开始建图吗？建图期间请勿进入作业区。」 | 3/4 |
| 「装载地图版本」「把 MAP-SH-06 载入进来」 | 「确认把当前地图切换到 {地图版本} 吗？」 | 3/4 |
| 多步任务（3.4 的六句） | 「确认执行这条任务吗？（N 步）」 | 取计划里最高风险 |

卡片第二行是工具说明 + 风险等级 + 参数 JSON，例如「让机器人前往指定目标点（映射到种子里的巡检航点）（风险等级 3/4；参数 {"target":"Z04"}）」。

### 4.2 怎么确认

气泡里点**红色「确认执行」**。点下去后工具才真正执行（导航类会真的跳页），随后给出结果与播报。

### 4.3 怎么取消（四种都算取消）

1. 点确认卡片里的**第二个按钮**（当前它的按钮文字取自取消说明，显示为「已取消，未执行任何动作。」或「已取消，未执行任何步骤。」——文案异常，见 7.4）；
2. 按 **Esc**；
3. 点气泡右上角「**×**」；
4. 直接让气泡关闭（关显示层时，未确认的高风险操作一律按"取消"处理，**绝不会因为关了界面就当成已确认**）。

取消后小木会回你：「好的，这条指令已经取消，我没有执行任何动作。」（多步任务是「好的，这条任务已经取消。」）并播报一次。多步任务被取消时，步骤清单里还没跑的步骤会标成"用户取消"。

### 4.4 这些情况不会执行（也不会给你一个假成功）

| 情况 | 你会听到/看到 |
| --- | --- |
| 低置信 + 高风险 | 只回复不执行，并播报「我没有完全听清，如果确认要执行，请再说一次，例如「<该意图的标准说法>」。」 |
| 槽位缺失 | 「这条指令还缺一个必要参数，我没有执行。（可选构件：Z01 / Z02 / Z03 / Z04）」 |
| 意图未命中 | 「我没有理解你的指令，可以换一种说法。」+ 提示「可查询巡检资料、查看构件或启动当前业务流程」，**不猜答案、不执行工具** |
| 工具执行失败 | 如实说明「这一步没有成功：<工具原话>」，不播成功话术 |
| 意图声明的工具不在白名单 | 不执行，并说明工具不在白名单 |

## 5. 常见问题排查

先看右下角**状态徽标**，它是最快的线索来源。

### 5.1 喊了「小木小木」没反应

| 先看 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 气泡底部按钮是不是「开启常驻唤醒」（气泡没展开就先点一下形象） | 常驻唤醒没开 | 点它，并在浏览器提示时允许麦克风；也可以点小木助手面板头部的「常驻唤醒」。**麦克风只在用户点过之后才申请**，页面加载不会自动开 |
| 徽标是不是红「出错了」 | 麦克风被拒绝 / 浏览器不支持 Web Audio | 见 5.4；地址栏的麦克风图标里重新允许权限，然后重新点开启 |
| 只喊了一遍 | 设计如此：**一次「小木」不唤醒** | 连着说两遍「小木小木」 |
| 两遍间隔太长 | 判定要求两遍落在 **1.5 秒**窗口内（或由复核确认真出现两次） | 两遍连着说，中间别停顿太久 |
| 刚喊过一次 | 命令定稿后有 **1.2 秒**唤醒冷却，播报期间还会暂停推流、命令交出后 2.5 秒自动恢复 | 等 1–3 秒再喊；或按 Esc 关气泡（会立即恢复聆听） |
| 什么都没问题 | 唤醒依赖本地 KWS 模型与 `/voice-wake` 服务 | 让现场技术同学看服务是否在运行；模型缺失时服务会退化成"只收音频、不做判定"，表现就是永远唤不醒 |

### 5.2 唤醒了但"没听清"/命令丢了

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 唤醒了，气泡一直没出现，也没提示 | 唤醒后**一直没说话**：服务端会发一条空文本的命令，前端不派发事件，所以界面上**没有任何提示**（7.5） | 直接再说一遍「小木小木 + 命令」；这条已被记为待修问题 |
| 说了，文字只出来一半 | 命令定稿条件是"静音约 1 秒"；如果说话中间停顿超过 1 秒，会被当成说完了 | 一句命令连着说，词间别长时间停顿 |
| 说了很长一句，只执行了前半段 | 单条命令上限 **8 秒**，超时按说完处理 | 拆成两条短命令，或用多步任务的语料说法（3.4） |
| 开头一两个字丢了 | 唤醒词与命令之间几乎没停顿，或环境噪声盖住了 | 唤醒词后停 0.3–1.5 秒再说命令 |
| 字幕里有错字但意思对 | 流式字幕只是"让你看见它在听"，最终以定稿转写为准 | 看结果是否命中；如果整句都错，重说一遍 |

### 5.3 命令识别错了（执行了别的意图）

| 现象 | 怎么办 |
| --- | --- |
| 命中了隔壁意图（例如把"今天天气怎么样"当成了归档天气） | 换语料里的标准说法（第 3 节的示例句）。**查询类**答错了不影响任何状态；**操作类**答错时先用「停止」或「取消当前任务」纠偏 |
| 说了一句不在目录里的话 | 会走未命中：回「我没有理解你的指令，可以换一种说法。」不猜、不执行 |
| 低置信但确实想做 | 再说一次，尽量用第 3 节的语料原句；低置信 + 高风险不会执行，会提示你标准说法 |
| 想确认它到底听成了什么 | 气泡标题行右侧的小标签就是这个**命中的意图 id**；备注行会写命中方式（规则命中 / 相似度 Top1 与 margin / 低置信 / 未命中） |

### 5.4 服务断开 / 一直没反应

| 先看 | 说明 | 怎么办 |
| --- | --- | --- |
| 徽标红「出错了」 | 这是 `error` 态，只由两类原因产生：麦克风权限被拒绝（内部提示"麦克风权限被拒绝，唤醒不可用"）、浏览器不支持 Web Audio。**注意：本地语音服务连不上不属于这一类**（见下一行） | 在地址栏的麦克风图标里重新允许权限，然后重新点「开启常驻唤醒」；浏览器不支持 Web Audio 时改用文字入口 |
| 服务连不上或中途断线 | 前端会按 0.5 → 1 → 2 → 4 → 8 秒退避自动重连（状态名是"重连中"）。**但气泡的徽标不会因此变红** —— 只有 `error` 才会显示「出错了」，重连中在气泡上看起来就是「待机」或「正在听」，没有任何重连提示（7.9） | 先等自动重连；同时确认本地语音服务在运行。期间**文字入口仍然可用**（小木助手面板打字、诊断控制台文本输入），不会因为语音坏了就整体不可用 |
| 一直没反应，但徽标正常 | 服务端可能根本没在判定（例如 KWS 模型缺失，服务退化成"只收音频与统计"）；也可能是唤醒通道没建立 | 让现场技术同学用下面那行诊断命令确认通道状态与服务日志 |
| 地图/页面卡顿 | 唤醒在持续采集与推流 | 不用语音时点「常驻唤醒：已开」把它关掉，麦克风会被释放 |
| 想自己看通道状态（现场技术同学） | 浏览器控制台里有诊断挂点 `window.__mumaiWake` | `__mumaiWake.describe()` 一句话状态；`__mumaiWake.state()` 通道状态（`idle/starting/live/reconnecting/stopped/error`）；`__mumaiWake.lastWake()` / `__mumaiWake.lastCommand()` 最近一次唤醒与命令；`__mumaiWake.commands()` / `__mumaiWake.wakes()` 计数；`__mumaiWake.stats()` 帧数与峰值；`__mumaiWake.snapshot()` 完整快照 |

### 5.5 气泡关不掉 / 展开收不起来

**已修复（v1.1）**：按「×」或 Esc 之后气泡会真的消失，不需要刷新页面。
当时的症状、原因与修法保留在第 7.1 节。现在若遇到"关不掉"，先看两点：
① 页面里是否有别的弹窗开着 —— 那种情况下 **Esc 会先关弹窗**（这是有意的让路规则，
见 `docs/键控编排-v1.1.md` 第 3 节），再按一次才轮到气泡；
② 是不是只按了 Esc 而气泡其实由"本轮交互正在显示"撑着 —— 等这一轮结束、或点「×」。

### 5.6 播报相关

| 现象 | 说明 | 怎么办 |
| --- | --- | --- |
| 没有声音 | 浏览器的语音合成不可用或被系统禁用；**不影响文字结果**（代码里播报失败会被吞掉，不报错） | 看气泡文字；也可点「重播（Alt+R）」或按 Alt+R 再试一次 |
| 播报念得太久 | 只念主回答，字段名/来源/时间戳不念（这是硬要求） | 按 Esc 立刻停播 |
| 播报期间喊它没反应 | 小木说话时前端暂停推流防自听回环 | 等播报结束或按 Esc，2.5 秒内自动恢复聆听 |
| 想再听一遍 | 点气泡里的「重播（Alt+R）」或按 Alt+R | 重播的是**最近一轮的主回答** |

## 6. 它不会做什么（如实写）

1. **不联网、不接大模型。** 意图理解是本地规则 + 本地相似度匹配，回复是模板 + 真实工具结果；平台介绍的回答里也写明了"本平台不部署本地大模型，小木按意图目录调用白名单工具"。
2. **不把归档数据当实时数据。** 近三个月天气来自归档档案，主回答里逐字带着「数据来源：归档天气档案 · 非实时联网查询；这是归档数据，不是实时联网查询。」它**不能**告诉你今天的天气。
3. **未命中不猜。** 没有把握时只说「我没有理解你的指令，可以换一种说法。」并给出可选方向；不会编一个数字、也不会"顺手"执行一个工具。
4. **低置信不执行高风险动作。** 哪怕你确认了也不行 —— 它会请你用标准说法再说一次。
5. **不模拟点击。** 语音走的是和按钮/文字入口同一套意图、工具与公开处理函数（真跳转、真改状态），不是用脚本去点 DOM。
6. **不绕过白名单与确认层。** 风险 ≥3 一律停下来等确认；意图里写了一个不存在的工具会被拒绝执行。
7. **不逐项朗读。** 播报只念主回答，字段名、来源定位、时间戳都只在气泡里看。
8. **不做多轮上下文、不做闲聊。** 每句话都要自带对象与动作；没有指代解析、没有自由问答、没有知识库全文问答（资料引用是按关键词在本地知识库里检索出来的可追溯引用，不是问答生成）。
9. **不保存会话记录。** 气泡只显示**最近一轮**结果，完整历史只在诊断控制台可见，且刷新页面即消失（不落库）。
10. **不会自己在页面加载时打开麦克风。** 常驻唤醒必须由用户点一次；关气泡 ≠ 关麦克风。
11. **不做语音唤醒以外的唤醒方式。** 没有按键唤醒词、没有双击形象唤醒之类的旁路；不开常驻唤醒时，右下角小木只能看、不能听。
12. **不能代替 COM4 外接语音设备通道，也不与之合并。** 两条通道共用同一个执行入口，但界面落点目前不同（7.6）。

### 7.12 同一个问题在两个入口，引用可能一个有、一个没有（**已修复，保留原始记录**）

- **原现象**（`验收两入口输出一致.mjs` 的 `pin` 模式实测，把同义模板随机钉死后对比）：
  同一个意图 `introduce_platform`、同一句话，
  文字助手面板给出引用「环境补偿与 HH 平衡含水率方法说明（补偿与适配的分工 · m-03）」，
  右下角气泡给出的引用是 **空**（`[]`）。业务状态与主回答两边一致。
- **原原因**：`introduce_platform` 没有声明式引用（`response.sources` 为空），两个入口都走**检索兜底**，
  但喂给检索的文本不同：文字入口（`SmallWoodPanel.tsx`）用**意图示例句**
  `searchKnowledge(intent.utterance)`；语音入口（`agent/replyView.ts` 的 `buildReplyView`）
  用 `query + intentName`（那里是为了"问句字面捞不到"特意补上意图名的）。
- **修法（已落地）**：文字入口改为与语音侧同一口径 ——
  检索文本 = 「用户问句 + 意图名」，意图名从**共享意图表**取
  （`intentById(...).name`，与语音侧 `turn.intentName` 是同一个字符串）；
  只有在用户没给问句时才退回示例句。
- **复验**：`node 验收两入口输出一致.mjs` ——
  `free` 模式（真实行为、两边各自随机选模板）从 **1/3 提升到 3/3**，
  `site_weather` / `view_current_order` / `introduce_platform` 的主回答、业务状态、资料引用全部一致；
  `pin` 模式下逐条对比里两侧的引用列表也完全相同。
- **仍未闭环的**：该探针自身在 `pin` 阶段偶发中途退出（不打印 `pin：N/3` 汇总），
  与"间歇性打不开文字面板"是同一类**探针时序**问题，不是引用不一致；诊断字段已埋在探针里。
- **复核入口**：`验收两入口输出一致.mjs`（明细 JSON 落在 `shots/两入口输出一致-验收.json`）。

### 7.1 已经产生回复之后，气泡关不掉（影响最大）——**已修复，保留原始记录**

- 原现象：按「×」或 Esc 后，气泡仍留在右下角；按 Alt+E「收起」也收不起来。
- 原原因：可见性判据里含有"存在最近一轮回复"，而回复一旦产生就永远为真。
- **现状**：判据改为 `agent.open || expanded || 状态≠待机`；`close()` 走统一入口
  `closeAgent()`，由 `mumai:agent-close` 一次完成「停 TTS → 未确认按取消 →
  作废本轮 → 清识别残留 → 复位 store」。关掉之后气泡真的消失，历史仍留在 store 里，
  点一下形象可以回看上一轮。
- 复跑：`node 复现关闭与重复命令.mjs`（期望 0/3 缺陷）、`node 验收-关闭取消本轮.mjs`（21/21）。

### 7.2 唤醒瞬间没有「正在听」反馈

- PRD FR-06 要求"识别到唤醒词后立即进入正在听状态"，非功能要求"唤醒结束到可见反馈 ≤800ms"。
- 实际：气泡状态只由执行器状态与 `wake.partial` 推导，**唤醒事件本身不改变任何显示状态**；要等第一段流式字幕（语音满 0.35 秒后才会有字，服务端约每 300ms 推一次）才会变绿「正在听」并弹出气泡。
- 影响：用户喊完唤醒词后有短暂的"毫无反应"，容易重复喊，反而把命令说乱。
- 建议方向：把 `wakeCount`/最近唤醒事件作为"正在听"的判据之一（或提供一个 800ms 内的即时反馈）。

### 7.3 执行阶段的状态词常常停在「正在听」，看不到「思考中」

- 原因：状态推导里 `wake.partial` 的优先级**高于**「思考中」分支（`XiaomuDock.tsx` 第 216–218 行）；而唤醒链路的字幕在命令执行期间仍然非空。
- 实际表现：语音命令执行中徽标是绿「正在听」；只有这次没有留下过流式字幕（例如命令极短、字幕还没推上来就定稿）才会显示橙「思考中」。
- 附带：「识别中」（蓝）在语音链路上永远不会出现 —— 它只由诊断控制台的"按住说话"设置。

### 7.4 确认卡片上"取消"按钮的文字是取消说明

- `XiaomuDock.tsx` 第 262 行把按钮文字取成 `pendingConfirm.cancelText`，而该字段的内容是**取消之后才该说的话**（「已取消，未执行任何动作。」/「已取消，未执行任何步骤。」）。
- 对比：诊断控制台里同一个确认层，按钮文字是「取消」，把这句话放在下方小字里（`VoiceConsole.tsx` 第 777–781 行）。两处不一致。
- 建议方向：气泡按钮固定显示「取消」，`cancelText` 作为说明文字。

### 7.5 唤醒后不说话，界面上没有任何提示

- PRD FR-10 要求"未听清：显示'没有听清，请再说一次'，不执行任何工具"。
- 实际：服务端在静音结束或 8 秒超时时会发一条 `type=command` 的事件，但 `text` 为空；前端 `wakeChannel.ts` 第 562 行 `if (text)` 直接跳过派发，于是**既不显示提示、也不执行**（安全上没问题，但用户得不到任何反馈）。
- 建议方向：空命令也派发一个"没有听清"的提示气泡（不调工具）。

### 7.6 高风险确认面在三条入口之间不一致

- 语音（唤醒词）→ 右下角气泡内的确认卡片。
- 小木助手面板打字的**高风险意图** → 面板把命令转给全屏控制台（`SmallWoodPanel.tsx` 第 348 行 `openAgent(cleaned)`），确认在全屏控制台里做。
- COM4 串口语音设备 → 也是打开全屏控制台（`serial/SerialVoiceBridge.tsx` 第 64 行 `openAgent(command.prompt)`）。
- 另外，右下角小木的层级（`z-index: 9300`）**高于**全屏控制台（`z-index: 90`），所以控制台打开时右下角小木仍显示在最上层；此时同一个待确认动作会**同时**出现两个确认面（气泡里的卡片 + 控制台的确认模态），点任意一处都能确认/取消（两者调的是同一个 `resolveConfirm`）。
- 影响：与 PRD §2.2「两条输入通道最终复用同一个入口」和 FR-08「所有关闭入口走同一个生命周期」的口径不完全一致；演示时容易让人误以为有两套确认。

### 7.7 「想重新说」（Alt+M）在推流暂停期间不立即恢复

- `Alt+M` 调的是 `wakeChannel().start()`；而 `start()` 在通道状态已是 `live` 时**直接返回 true**，不会取消"暂停推流"（`suspended`）。
- 于是命令刚交出去、小木正在播报的那几秒里按 Alt+M，麦克风音频其实还没恢复推流；恢复靠的是 2.5 秒自动恢复或关闭气泡（关气泡会立即恢复）。
- 建议方向：Alt+M 先 `resume()` 再 `start()`（或直接把「重新说」绑到 resume）。

### 7.8 其它可改进项（不影响使用）

- 常驻唤醒的错误原因（麦克风被拒 / 不支持 Web Audio / 重连）只写在浏览器控制台警告里，气泡本体只显示「出错了」或什么都不显示，不给出具体原因。
- 气泡只显示最近一轮，没有"展开记录"查看历史（PRD FR-07 提到的历史记录入口暂缺）。

### 7.9 「重连中」在气泡上不可见

- 气泡的状态推导只把 `wake.state === "error"` 映射为红「出错了」，**不映射 `reconnecting`**（`XiaomuDock.tsx` 第 213 行）。
- 服务端断开时通道进入 `reconnecting`（0.5→8 秒退避重连），气泡上表现为「待机」或残留的「正在听」，既没有红态也没有"正在重连"的提示。
- 影响：与 PRD FR-10「本地语音服务断开：动态小木进入错误态并提供重连」有差距；现场只能靠控制台警告或 `window.__mumaiWake.state()` 判断。
- 建议方向：把 `reconnecting` 映射成一个可见的中间态（例如黄「重连中」），并把通道 `note` 显示在气泡里。

### 7.10 右下角「小木」浮标可能被常驻形象挡住（**未在浏览器实测，需视觉验收确认**）

- 两个元素都钉在右下角：打开小木助手面板的浮标 `.appshell__fab` 是 `right: 16px; bottom: 52px; 52×52px; z-index: 26`；常驻小木形象 `.xd__avatar` 是 `right: 24px; bottom: 24px; 76×76px; z-index: 9300`。
- 按数值算，两个圆心的距离约 26px，而半径之和是 64px，**重叠很明显**；形象层级更高，因此浮标有可能被遮挡、点不到 —— 这会直接影响第 1.3 节的入口（"点小木助手面板里的入口"）。
- 由于两者一个是 `absolute`（随容器）、一个是 `fixed`（随视口），实际遮挡程度还取决于滚动位置与容器高度，**必须在 1366×768 与 1920×1080 下做视觉验收**才能定论（PRD AC-05 本来就要求这两种尺寸验收）。
- 建议方向：把常驻形象让开浮标（例如形象上移、或浮标改到左下/顶栏），避免右下角两个入口互抢。

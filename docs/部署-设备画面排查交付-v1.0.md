# 部署后看不到小车 / 扫描仪画面：原因与配置清单（交付版 v1.0）

> 面向对象：拿到本仓库后自行部署的同事 / 他的 AI Agent。
> 交付物：本文 + `tools/smoke-devices.sh`（一条命令自检，只读，不改任何配置）。
>
> 一句话结论：**代码是全的，缺的是「三份不入库的本地配置」+「一种正确的启动方式」。**
> 换台机器部署时，小车地址、控制令牌、设备令牌、树莓派屏幕密钥都不会跟着 Git 走，
> 这是**故意**的（见 §1.1），不是漏提交。

---

## 0 先分清你看到的是哪一种「看不到」

| 现象 | 大概率原因 | 跳到 |
|---|---|---|
| 页面能打开，但**所有**实时数据都不动；顶栏「平台」那格是断线；换台电脑也一样 | 只部署了前端静态文件，后端没跑（`vite preview` / nginx / 只传了 `dist`） | §1.2 |
| 建图巡航页显示**「未配置小车地址」/「只读监视」**，两路视频是黑的 | `server/data/cart.json` 不存在（gitignore 掉了） | §3 A |
| 建图巡航页两路视频 502，地图位姿也是空的 | 小车地址配了，但后端**连不上小车**（网段 / 防火墙 / 小车服务没起） | §3 D |
| 硬件监看页读数、通道、批次**全是种子数据**或「等待设备上报」 | 扫描仪终端的 `platform_url` 没指到这台后端，或设备令牌不一致 | §4 |
| 硬件监看页「设备预览」一直「等待推流」 | 终端没有开预览上传（这一路是终端主动推的，平台不生成画面） | §4.3 |
| 采集工作台「采集设备画面」黑屏 | 树莓派桌面串流没配（`capture-screen.json` + Pi 上的 systemd 用户服务） | §5 |

**先跑自检**（只读，不改任何东西，约 25 秒）：

```bash
bash tools/smoke-devices.sh http://127.0.0.1:8000
# 换台机器：bash tools/smoke-devices.sh http://192.168.31.196:8000
# 设备号不是 handheld-02：加 --device handheld-01
```

它按 `0 平台服务 → 1 前端托管 → 2 小车 → 3 手持扫描仪 → 4 采集屏幕` 分节给出
`[ OK ] / [FAIL] / [WARN]`，每条 FAIL 下面直接写该改哪个文件、改完要不要重启。
退出码：`0` 通过 / `1` 有 FAIL / `2` 连不上平台（后面各项无法判定）。

下面 §1–§5 是它每条结论背后的完整原因与手工做法。

## 1 根因：三件事，缺一不可

平台和设备之间是**两条方向相反的链路**，加上前端必须和后端**同源**，一共三个条件。

```
        ┌───────────────────────── 浏览器（页面）─────────────────────────┐
        │  只认同源相对路径： /api/...  与  ws://<页面所在主机>/ws          │
        └───────────────────────────────┬─────────────────────────────────┘
                                        │ ① 必须由后端自己托管前端，才有同源
                        ┌───────────────▼────────────────┐
                        │  共享服务 node server/index.mjs │
                        │  （默认 0.0.0.0:8000）          │
                        └───┬────────────────────────┬────┘
        ② 平台 → 小车（下行）  │                        │  ③ 设备 → 平台（上行）
        小车状态 WS 2Hz / 地图 │                        │  注册 / 硬件上报 2s / 事件 / 预览帧
        MJPEG 两路 / 控制动作  │                        │
                ┌───────────▼──────────┐   ┌─────────▼──────────────┐
                │ 智能小车              │   │ 手持扫描仪（树莓派终端） │
                │ http://<小车IP>:8765  │   │ 终端自己 POST 到平台     │
                └──────────────────────┘   └────────────────────────┘
```

### 1.1 设备连接信息全部在 gitignore 里 —— 新克隆必然「没配」

`.gitignore` 第 42–43 行：

```gitignore
# 共享服务的运行期状态：SQLite 库与磁盘资产都由服务启动时重建，
# 入库会把「本机演示到哪一步了」带进仓库，换台机器反而对不上。
server/data/
server/assets/
```

`server/data/` 里恰恰放着**所有真实设备的连接信息**：

| 文件 | 内容 | 少了它，哪一块失灵 |
|---|---|---|
| `server/data/cart.json` | 小车地址 + 控制令牌 | 建图巡航页：状态、地图、位姿、**两路视频**、全部控制按钮 |
| `server/data/device-tokens.json` | 设备号 → 设备令牌 | 手持扫描仪（终端）**根本注册不上**，硬件监看页无真机数据 |
| `server/data/capture-screen.json` | 树莓派屏幕地址 + 密钥 | 采集工作台的「采集设备画面」 |

> 注：`server/data/` 整个目录在克隆后**不存在**，是服务启动时按需创建的。
> 所以「目录都没有」是正常状态，不代表部署失败。

### 1.2 前端必须由后端托管（同源），否则 `/api` 与 `/ws` 都不存在

前端**没有**任何构建期注入的服务地址，全部走同源相对路径
（`src/pages/MumaiDashboard/api/client.ts` 文件头写明了这个设计）：

- `fetch("/api/...")`
- `new WebSocket(`${protocol}//${location.host}/ws?...`)`

所以页面必须从**后端自己的 HTTP 端口**打开。以下做法都会导致「页面能开、设备全无」：

| 做法 | 结果 |
|---|---|
| 只把 `dist/` 丢给 nginx / `python -m http.server` / 只跑 `npx vite preview` | `/api` 404 或返回 HTML、`/ws` 升级失败 → 小车与扫描仪**全都没有** |
| `start-lan.sh`（它就是 `vite preview`，没有代理） | 同上 |
| 前端在 5173、后端在别的机器 | `vite.config.ts` 的代理写死 `http://localhost:8000` → 代理打空 |

**正确启动方式只有一条**（先构建，再由后端一起托管）：

```bash
pnpm install
pnpm build
node server/index.mjs --static dist      # 或 pnpm server:static
```

启动日志里认这两行，就是对的：

```
  HTTP      http://localhost:8000/api
  静态托管  /path/to/dist
```

### 1.3 后端必须在**同一局域网**里，而且要用局域网 IP 而不是 localhost

小车和终端都是**内网私有地址**（小车上就是 `http://127.0.0.1:8765`，
但那是在小车自己的机器上）。部署平台的机器必须：

1. 能 ping 通小车 IP、能 `curl http://<小车IP>:8765/api/health`；
2. 告诉终端自己的**局域网 IP**（`http://192.168.x.x:8000`），写 `127.0.0.1` 是终端自己，永远连不上；
3. 防火墙放行入站 TCP `8000`（WebSocket 与 API **共用这一个端口**，不需要再开第二个）。

> 平台默认 `MUMAI_HOST=0.0.0.0`，四台电脑 / 设备都能连 —— 这是默认值，不用改。

## 2 五分钟跑通清单（Agent 可直接照做）

```bash
# ── 0. 前提 ────────────────────────────────────────────────────────────
node -v            # 需要支持 node:sqlite 的版本（实测 22.22.1 可用）
pnpm install
pnpm build

# ── 1. 写三份本地配置（值必须与真实设备一致，见 §3/§4/§5）───────────────
mkdir -p server/data
cat > server/data/cart.json <<'JSON'
{ "url": "http://192.168.31.221:8765", "token": "<小车 control_token>" }
JSON
cat > server/data/device-tokens.json <<'JSON'
{ "handheld-02": "<与终端 device_token 完全一致>" }
JSON
cat > server/data/capture-screen.json <<'JSON'
{ "url": "http://192.168.31.12:8766", "token": "<与 Pi 上环境文件里的密钥一致>" }
JSON
chmod 600 server/data/*.json

# ── 2. 启动（同一个端口提供页面 + API + WebSocket + 设备通道）───────────
node server/index.mjs --static dist

# ── 3. 自检（另开一个终端）──────────────────────────────────────────────
bash tools/smoke-devices.sh http://127.0.0.1:8000

# ── 4. 设备侧（在小车 / 树莓派上做，见 §3.3 / §4.2）─────────────────────
#    小车：填平台地址与设备令牌（小车右上角设置页 → POST /api/settings/save）
#    终端：改 platform_url / device_id / device_token，然后**重启终端进程**
```

改完配置**必须重启后端**：三份 JSON 都是启动时读一次（`cart.mjs:120`、`index.mjs:44`、`capture-screen.mjs:9`），不热加载。

> **设备换 IP 是常事（2026-10-02 就发生过）**：现场那台精扫设备从 `192.168.31.60`
> 换成了 `192.168.31.12`，而 `server/data/*.json 里写的是**地址本身**，不是设备名 ——
> 改完只需改这三份 JSON 里的地址再重启后端（token/密钥不跟着变）。
> 判断"是换 IP 还是服务挂了"最快的两条：
>   1. `curl -H "Authorization: Bearer <token>" http://<新IP>:8766/stream.mjpeg -o NUL -w "%{http_code}"`（端口通不通）；
>   2. 平台内 `GET /api/capture/screen/status` —— 回 `online:true` 就说明地址与密钥都对。

环境变量可以覆盖（适合容器 / 不想写文件时），二选一即可：

```bash
MUMAI_CART_URL=http://192.168.31.221:8765 \
MUMAI_CART_TOKEN=<小车 control_token> \
MUMAI_DEVICE_TOKENS="handheld-02:<终端令牌>,mumai-car-01:<小车令牌>" \
MUMAI_SCREEN_URL=http://192.168.31.12:8766 \
MUMAI_SCREEN_TOKEN=<屏幕密钥> \
MUMAI_SECRET=<固定签名密钥，设了重启不用重新登录> \
node server/index.mjs --static dist
```

> ⚠️ `MUMAI_DEVICE_TOKENS` 一旦设置就会**完全覆盖** `device-tokens.json`，
> 两个来源只在 `index.mjs` 里做字符串拼接，最终按「设备号:令牌」逐个解析。
> 混用时容易漏掉某台设备，建议只用其中一种。

## 3 小车（建图巡航页 `#/mapping`）

### 3.1 数据是怎么走的（为什么浏览器不直连小车）

```
浏览器  ──(/api/cart/*、WS kind:"cart")──▶  平台后端  ──(HTTP/WS + 控制令牌)──▶  小车 :8765
```

浏览器不直连小车是**设计要求**，两条硬原因（`server/services/cart.mjs` 文件头）：

1. **控制令牌不能进前端包**——页面直连就得把令牌交给浏览器；
2. 小车对浏览器的 POST / WS 校验 `Origin === Host`，从平台域跨源打过去会被 **403**。

所以：**"页面里看不到画面" 永远先查后端这一侧，不要去改页面。**

### 3.2 配置：`server/data/cart.json`

```json
{
  "url": "http://192.168.31.221:8765",
  "token": "<小车 config.local.json 里的 control_token>"
}
```

- `url` 是小车在同一局域网里的地址（小车屏幕上显示 `127.0.0.1:8765`，但**别人要用它的局域网 IP**）。
- `token` 不给也行：**只读接口在小车上不需要令牌**，地图、位姿、两路视频照样能看，
  只是所有控制按钮置灰并提示「只读监视」（`configured` 为 true、`canControl` 为 false）。
- 对应环境变量：`MUMAI_CART_URL` / `MUMAI_CART_TOKEN`（环境变量优先）。

### 3.3 小车侧要做什么

小车端代码**不需要改**。要做两件：

**(a) 让平台能读到状态与视频** —— 小车控制台跑起来即可，验证：

```bash
# 在「部署平台的这台机器」上执行，不是在小车上
curl -s -m 3 http://192.168.31.221:8765/api/health
curl -s -m 3 -o /dev/null -w '%{size_download} 字节\n' http://192.168.31.221:8765/api/streams/rviz.mjpeg
curl -s -m 3 -o /dev/null -w '%{size_download} 字节\n' http://192.168.31.221:8765/api/streams/camera.mjpeg
```

两路各收到几万字节才叫「有画面」。收到 `0` 说明**小车自己那一侧**没出帧
（RViz 没起 / 摄像头没起），与平台无关。

**(b) 让小车把遥测推回平台（可选，但推荐）** —— 小车设置页填：

```json
{
  "platform_url": "http://<平台主机局域网IP>:8000",
  "platform_token": "<平台分配的设备令牌>"
}
```

平台侧对应令牌写在 `server/data/device-tokens.json`：

```json
{ "mumai-car-01": "<小车填的那个 platform_token>" }
```

### 3.4 平台侧暴露给页面的接口（排查用）

| 接口 | 说明 |
|---|---|
| `GET /api/cart/status` | 页面主数据源。`configured` / `link`(`unconfigured`/`connecting`/`online`/`offline`) / `live` / `ageMs` / `state` |
| `GET /api/cart/stream/rviz` | RViz 画面，`multipart/x-mixed-replace`，可直接 `<img src>` |
| `GET /api/cart/stream/camera` | 摄像头画面，同上 |
| `GET /api/cart/map.png` | 当前栅格地图（按 `revision` 判断是否重取） |
| `POST /api/cart/action` | 14 个控制动作的白名单转发（`X-Request-Id` 做幂等） |

> 两条 MJPEG 路由是 `auth:false` —— 因为 `<img>` 带不了 `Authorization` 头。
> 需要登录态的是 `/api/cart/status` 这类读取接口。

### 3.5 画面状态码对照（`/api/cart/stream/{rviz|camera}`）

| 返回 | 含义 | 该做什么 |
|---|---|---|
| `200 multipart/x-mixed-replace` | 正常，有真实出帧 | 无需处理 |
| `503 未配置小车地址` | `cart.json` 不存在或 `url` 为空 | 补配置 + 重启后端 |
| `502 该视频通道当前不可用` | 后端能连小车，但小车这一路没出帧 | 去小车上验证 §3.3(a) |

平台**不伪造图像**：上游没出帧就回 502，页面显示离线（约定见 §6）。

## 4 手持扫描仪 / 手持终端（硬件监看页 `#/hardware?tab=monitor`）

### 4.1 方向与小车相反：设备**主动上报**

```
终端（树莓派 Pi 5 · woodpulse）──POST/WS 到平台──▶ 平台后端 ──页面轮询──▶ 浏览器
```

平台是**接收方**。终端不改代码，只改一个配置文件。

硬件监看页的四块 —— 设备状态 / 设备读数 / 通道状态 / 采集接收 —— 读的就是终端每 2 秒
`POST /api/devices/{id}/hardware` 推上来的真机数据；**终端没连上时页面退回种子数据**，
所以"全是假数据"通常等于"终端没上报"。

### 4.2 终端侧配置（在树莓派上改）

```jsonc
// /var/lib/woodpulse/config.json
{
  "platform": {
    "platform_url": "http://<平台主机局域网IP>:8000",  // ← 不能是 127.0.0.1
    "device_id": "handheld-02",                        // ← 要与平台侧、页面常量一致
    "device_token": "demo-token",                      // ← 要与平台侧配的令牌一致
    "demo_session_id": "demo-01"
  }
}
```

```bash
sudo systemctl restart woodpulse     # ★ 必须重启：注册握手只在终端开机时做一次
```

> ⚠️ **注册握手只在终端进程启动时调一次**，之后它只重连 WebSocket。
> 不重启的话：设备数据、遥测、事件、命令都能通，但 `versions.config`、
> `readings.clock`（时钟偏差需要注册响应里的 `platformTime`）与台账 `appVersion` 会缺。
> 这是终端的设计，平台不替它编。

### 4.3 平台侧配置：设备令牌

两种来源（`index.mjs` 会把两者合并）：

```json
// server/data/device-tokens.json
{ "handheld-02": "demo-token" }
```

```bash
# 或环境变量
MUMAI_DEVICE_TOKENS="handheld-02:demo-token,mumai-car-01:<小车令牌>"
```

**这里有一个最容易踩的坑**：设备令牌表**默认为空**，而空表 = 任何令牌都拒绝。
终端会收到 `401 BAD_DEVICE_TOKEN`，表现就是"平台离线"、"设备一次都没上报过"。

确认方法（`/api/health` 里的 `devices.tokens` 就是令牌组数；启动日志也会打）：

```
  设备网关  令牌 1 组 · 已登记 2 台 · 在线 0 台
                  ↑ 0 组 = 终端必然连不上
```

规则细节：
- `"设备号:令牌"` → 只对该设备有效；
- 只写 `"令牌"`（不带冒号前缀）→ **任意设备**都可用（出厂值 `demo-token` 就是这么用的）；
- 页面常量的设备号是 `handheld-02`，也是设备台账主键。

### 4.4 「设备预览」为什么一直「等待推流」

这一路**不是平台去拉终端的画面**，而是**终端主动推**低帧率 JPEG 帧：

```
终端 ──POST /api/devices/{id}/preview（JPEG 直传，内存留最近 12 帧）──▶ 平台
页面 ──GET /api/devices/{id}/preview/latest（1.5 秒一次）──▶ 平台
```

所以：
- 终端没开预览上传 → `preview/latest` 回 `404 NO_PREVIEW` → 页面显示「等待设备推流」，**这是正常边界**；
- 终端推过帧 → 回 `200 image/jpeg`。

如果同事期望的是"看到扫描仪屏幕上正在扫的东西"，需要先在**终端侧**打开预览上传，
平台这一侧代码不需要改（接口已就绪）。

### 4.5 在线/离线的判定口径（页面按这个显示，不要自己另算一套）

**以硬件上报的新鲜度为准**（页面 `phaseOf()` 用的就是顶层 `ageSec`）：

| 距最后一份上报 | 页面显示 |
|---|---|
| ≤ 6 秒 | 在线（6 秒 = 3 × 上报周期） |
| 6—15 秒 | 延迟 |
| > 15 秒 | 离线 Ns（保留最后一份数据，**不回退种子**） |

> 别拿 `link.ageSec` 判硬件新鲜度：它是台账 `last_seen_at`，只在**注册**与
> **设备通道事件**时刷新；终端只 POST 数据不重连时它会一直涨，会误判成离线。

### 4.6 终端侧自检（在 Pi 上跑）

```bash
BASE=http://<平台主机IP>:8000
TOKEN=<平台侧配的同一令牌>

curl -s -m 5 $BASE/api/health && echo
curl -s -o /dev/null -w "register: HTTP %{http_code}\n" -X POST \
  $BASE/api/devices/register -H 'content-type: application/json' \
  -H "X-Device-Token: $TOKEN" -H "X-Device-Id: handheld-02" \
  -d '{"schemaVersion":"1.0","deviceId":"handheld-02","bootId":"boot-test","capabilities":{}}'
```

`register` 返回 200 才算通。返 401 就是令牌不一致；连不上就是网络/地址问题。

## 5 采集设备屏幕（采集工作台 `#/hardware?tab=capture`）

这一路和上面两条**都不是一回事**：它是**树莓派桌面**的只读串流
（X11 → FFmpeg → MJPEG → 平台鉴权代理 → 浏览器），不是扫描仪摄像头。

两侧都要配：

**树莓派侧**（`tools/capture-screen/README.md` 是完整安装说明）：

```bash
# ~/.config/mumai-screen/environment
MUMAI_SCREEN_TOKEN=<随机密钥>
MUMAI_SCREEN_WIDTH=1024
MUMAI_SCREEN_HEIGHT=600
MUMAI_SCREEN_FPS=10
MUMAI_SCREEN_PORT=8766

systemctl --user enable --now mumai-screen.service
```

**平台侧**：

```json
// server/data/capture-screen.json
{ "url": "http://192.168.31.12:8766", "token": "<同一密钥>" }
```

验证：`curl -s -H "authorization: Bearer <平台令牌>" http://<平台>:8000/api/capture/screen/status`
→ `{"configured":true,"online":true,...}`。

> 没配时接口回 `{"configured":false,"online":false}`，页面黑屏并提示信号中断 —— 属预期。
> 串流需要 X11 桌面（Wayland 要另配捕获源），且需要有已登录的图形会话。

## 6 常见误判（先说清边界，省得白查）

1. **"页面里显示的是假数据"不一定是 bug。** 硬件监看页在**终端没上报**时会退回种子数据并标来源；
   采集作业 / 异常排查两个页签本来就仍是演示工作台。判断依据：页面上的「来源」标记与顶栏「扫描仪」那格。
2. **"视频在播放" ≠ "车辆在线"。** 地图、位姿、RViz、摄像头四路各自判新鲜度，互不兜底。
3. **RTMP 的 running 不代表平台收到流。** 浏览器不能直接播 `rtmp://`，那两路需要自行转
   WebRTC/HLS/HTTP-FLV；**当前平台用的是 MJPEG 两路**（`/api/cart/stream/*`），别混。
4. **`null` 不是 0。** IMU / 里程计超过 2 秒未更新、电压字段 5 秒未更新时，小车返回 `null`，
   页面显示「—」，不参与计算。
5. **`/PowerVoltage` 是电压不是电量。** 页面上的剩余电量是按 3S 锂电池曲线本地推算的。
6. **`ok:true` 只代表"已接收"**，不代表动作完成（看 `state.mode` 与 `mission.state`）。
7. **`MUMAI_SECRET` 不设就每次启动随机** → 重启后旧登录令牌失效，表现为"要重新登录"。要避免就固定它。
8. **小车不需要 `MUMAI_DEVICE_TOKENS` 也能被平台读到**（下行只读不需要令牌）；
   `device-tokens.json` 管的是**小车/终端上行到平台**的方向。两件事别混。

## 7 完整环境变量表

| 变量 | 默认 | 作用 |
|---|---|---|
| `MUMAI_PORT` | `8000` | HTTP + WebSocket + 设备通道**共用端口** |
| `MUMAI_HOST` | `0.0.0.0` | 监听地址（局域网内多机访问保持默认） |
| `MUMAI_DB` | `server/data/mumai.db` | SQLite 库路径（换机自动重建） |
| `MUMAI_ASSETS` | `server/assets` | 磁盘资产目录（归档 / 更新包 / 样本，启动时补齐） |
| `MUMAI_SECRET` | 每次启动随机 | 登录令牌签名密钥；固定它，重启后不用重登 |
| `MUMAI_CART_URL` / `MUMAI_CART_TOKEN` | 读 `server/data/cart.json` | 平台 → 小车（§3） |
| `MUMAI_DEVICE_TOKENS` | 空 = **全部拒绝** | 设备 → 平台上行令牌（§4.3） |
| `MUMAI_CONFIG_VERSION` | `CFG-02` | 注册响应里回的配置版本 |
| `MUMAI_SCREEN_URL` / `MUMAI_SCREEN_TOKEN` | 读 `server/data/capture-screen.json` | 树莓派桌面串流（§5） |
| `MUMAI_API` | `http://localhost:8000` | **仅开发期** `vite dev` 的代理目标 |
| `MUMAI_VOICE` / `MUMAI_VOICE_HTTP` | `127.0.0.1:8780` | 本地语音桥接层（唤醒/ASR 服务**不在本仓库**） |

## 8 验收：部署完成的判定标准

按顺序全绿即算部署完成：

```bash
# 1) 一条命令自检（应输出「设备链路自检通过。」，退出码 0）
bash tools/smoke-devices.sh http://127.0.0.1:8000

# 2) 启动预检（端口/库/素材/构建产物）
node tools/preflight.mjs

# 3) 设备通道契约回归（无需真机）
node --test tools/test-device-gateway.mjs
```

人工核对四项：

- [ ] 页面从 `http://<后端IP>:8000/` 打开（**不是** 5173，也不是别的静态服务器）
- [ ] 顶栏四格状态里「平台」是通的；换一台同网段电脑打开，四格仍然一致
- [ ] `#/mapping` 建图巡航页：地图 / 位姿 / RViz / 摄像头有真实数据（不是"未配置小车地址"）
- [ ] `#/hardware?tab=monitor` 硬件监看页：读数带「实测/推算/估算」标记、有上报时间，
      且**不是**整块「模拟采集」

### 交付给部署方时，请一并说明

> 这个仓库**故意不包含**任何真实设备的地址与密钥（`server/data/` 被 gitignore）。
> 所以克隆下来直接跑，页面一定看不到小车和扫描仪 —— 这不是 bug。
> 按本文 §2 写三份 `server/data/*.json`、用 `node server/index.mjs --static dist` 启动，
> 再把小车和终端的 `platform_url` 指过来，两条链路就都通了。

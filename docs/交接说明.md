## 三、必须知道的坑

这些每一条都是实际踩出来的，不是理论。

### 1. `<Suspense>` 边界外不要用会挂起的资源加载

drei 的 `useTexture` 走 suspend-react：**只要有一个加载不 resolve，整个边界永远不 commit** —— 现象是地图整块消失、只剩 Canvas 背景，而且**完全静默**（无报错、无异常）。地图贴图一律用自写的 `mapDemo/useImage.ts`（普通 state）。

### 2. 雾的远近必须跟着取景距离走

Demo2 写死 `fog(color, 10, 30)` 是因为它的相机恒定在约 13 单位外。本项目取景距离由投影包围盒反解（中国约 96），固定 10~30 会让整幅地图落在雾区外被**全雾成纯黑** —— 现象是「地图乌漆嘛黑，只有放大才看得见」。

### 3. 「先隐藏再播放」的动画模式有致命失败面

只要隐藏发生了、播放那段因为任何原因没跑（挂载顺序、Suspense 让页面晚于外壳挂载、HMR 打断时间线），元素就**永远停在屏幕外**。所以入口动画一律带无条件兜底：到点强制清掉内联 transform/opacity。

### 4. Windows 上 chokidar 的 EBUSY 会把 dev server 打挂

编辑器（Word/WPS）打开文件时生成的 `~RFxxxx.TMP` 锁文件被 chokidar watch 到会抛 EBUSY，而 **Vite 没有捕获它 —— 整个进程直接退出**。已加过两次，`vite.config.ts` 的 `server.watch.ignored` 必须保留 `*.TMP` / `~RF*` / `~$*` / `*.swp` / `*~` 这些模式。

### 5. 无头 Chrome 的 rAF 只有约 1fps

`tools/shot.mjs` 截图时，入场动画可能看起来「没播完」。这是环境限制不是代码问题。另外**开发中改文件会触发 HMR 重放入场**，截图前要静置，或把 `--wait` 给足（首页至少 22s）。

### 6. 地图的两个几何事实

- `extrudeGeometry` 沿 **+Z** 挤出，外层 group 绕 X 轴 -90° 后 +Z 朝上，所以挤出体占 `z ∈ [0, slabDepth]`，**顶面就是 `z = slabDepth`**。
- 装饰尺寸统一乘 `deco = 地图投影半径 / 参考半径`，中国与上海跨度差 13 倍，不换算会一张「装饰看不见」一张「装饰糊住地图」。

## 五、两条必须遵守的原则

### 文案判据（用户明确要求）

> **一句话如果在向读者解释「这套系统是怎么想的」，而不是陈述「当前发生了什么」，它就不该出现在生产界面里。**

平台要包装成**一家公司真实投入使用的系统**。禁止出现：PRD 条款号、源码文件名、内部函数名、设计说明段落、教用户理解业务的长句。
面板标题必须是**名词短语**（`训练任务` 而不是 `用新采集的数据重训练`）。

### 数据判据

- 所有数字与文案来自 `seed/`，页面不硬编码。
- **未检测一律用 `null` 表达「未采集」，不用 0 冒充「无风险」。**
- **不要展示比赛当天才知道的信息。** 例如示例寺的四根柱子（Z01–Z04）是现场才见到的场地，总览页展示它们的「采集状态」等于自认数据是编的 —— 这就是「四柱构件状态」看板被删掉的原因。

# 补采录音清单 v1.0（用来闭合 AC-01 / AC-02 剩余 4 项）

整理日期：2026-09-14
适用对象：**说话人本人**（用户/演示者），用现场那台笔记本或同一支麦克风录
为什么需要：验收矩阵 51 项里现在 **通过 47 / 不通过 1 / 证据不足 3**，剩下这 4 项**全部卡在"缺样本"**，
不是代码没做，也不是脚本没写。这份清单给出**一次录完就能全部闭合**的最小采集要求。

## 1. 录之前：三条硬规矩（不遵守会导致样本不能用）

1. **每组必须是"一次连续录制"里的同一批文件**，不要今天录两条、明天录三条混在一起。
   原因写在清单里（`recordings/manifests/voice-intents-v2.json` 的 `datasetSplits.policy`）：
   同一次录制的底噪、距离、麦克风增益、说话人状态是共享的，按条拆开分别进训练/验证集会把同一条件放进两边，指标虚高。
   所以划分以**录音会话**为单位，**整批进同一个划分**。
2. **标定集必须换一个时间和环境**，不要和已有的 23 条（`recordings/raw02/`）在同一个会话里。
   那 23 条已经被冻结为验收集，且历史上被用于选阈值（清单里已如实披露）。新的 ≥20 条才是"允许调参"的那一批。
3. **不要读稿**。命令组（④）可以照着语料念；①②③ 要**自然说**，尤其是负样本——念稿的语调会让负样本失真。

## 2. 技术规格（设备与格式）

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 采样率 | 16000 Hz | 服务端固定 16k；不是 16k 也能收（仓库有转码脚本），但 16k 最省事 |
| 声道 / 位深 | 单声道 / 16-bit PCM | wav 或 m4a 都可以；**一个文件夹里别混格式** |
| 麦克风 | 与现场演示用同一支（含同一台笔记本内置麦） | 换设备要单独当一组新会话 |
| 距离 | 与演示时一致（约 0.5–1 m） | 请在每条前报一次距离更好 |
| 环境 | 组内保持同一环境；① 与已有的 23 条**不同房间/时段** | 负样本组建议**开着现场底噪**（空调/走廊声） |
| 单条时长 | ①②③ 见上表；**留头尾各 0.3s 静音** | 服务端靠静音判尾，切得太紧会把句尾吃掉 |

## 3. 逐组清单

### ① 标定集（≥20 条「小木小木」）

- 说法：就是唤醒词本身，两遍，连着说：**「小木小木」**。
- 变化一下更接近真实：音量（正常/偏小/偏大）、语速（正常/偏快）、距离（近一点/远一点）各来几条，
  但**都在同一次连续录制里**。
- 命名：`calib-01.m4a` … `calib-20.m4a`（或 wav，统一即可）
- 放：`D:\平台\voice-module\recordings\calib-01\`

### ② 整句验收样本（A1-8）

- 说法（**就是这一句**，与 PRD §8 AC-01 一字不差）：
  **「小木小木」** → 停一下（0.3–1.5 秒，也就是自然停顿，别拖长）→ **「查近三个月天气」**
- 最少 1 条，建议 3 条（同一句话连说三遍，中间隔 2 秒）。
- 命名：`accept-sentence-01.wav` …
- 放：`D:\平台\voice-module\recordings\accept-sentence\`
- 这一条是 PRD 里"必须 100% 通过"的那个样本，**它一直不存在**，所以 A1-8 只能记"证据不足"。

### ③ 真人负样本（A2-2，FAR 的分母）

按下面三类各来若干条，**累计说话+环境音时长 ≥90 秒**（时长是 FAR 的分母，越足越可信）：

1. **近音词**（各 2–3 条）：「小木」只说一遍、「小木桥」、「小木屋」、「小木马」、「木木木」、「小木小」。
2. **日常说话**（5–8 条）：随便说点正常工作对话，例如「这个构件今天先不处理」「把三号柱的记录发我」「下午两点开会」。
   要求：**不要**在里面夹「小木」两个字。
3. **现场底噪**（3–5 条，每条 10–20s）：不说话，就录现场环境（空调、走廊、键盘、翻纸）。

- 命名：`neg-once.wav` / `neg-xiaomuqiao.wav` / `neg-daily-01.wav` / `neg-noise-01.wav` …
- 放：`D:\平台\voice-module\recordings\negative-real\`

### ④ 命令识别集（可选，扩样本量）

现在"命令识别正确率"是在**冻结验收集的 9 条真人命令**上量的（9/9 = 100%）。
把下面 10 句各说 1–2 遍，可以让这个指标从"9 条单一意图"扩到多意图，可信度明显提高：

```
查近三个月天气 / 比较四根木柱 / 查今年五月示例寺巡检 / 打开地图 / 打开当时的高斯场景
还有几个没处理完 / 生成巡检报告 / 看一下当前工单 / 介绍一下这套系统 / 汇总一下异常
```

- 放：`D:\平台\voice-module\recordings\command-expand\`

## 4. 录完之后（这一步我来做，你只需要把文件夹放好）

1. **登记进清单**：把新会话按清单既有结构写进 `datasetSplits`
   （① → `calibrationSet`，③ → 新的 `wake_negative_real` 组，② → `command_weather_real` 组），
   并保留原始文件路径、录制设备、距离、环境。**已有 23 条验收集一个字节都不动。**
2. **重跑评估**：`评估语音.py` 会重新出 `recordings/reports/evaluation-v2.json`：
   - 唤醒：在**新的标定集**上选阈值 → 再在**冻结验收集**上出 FRR（这时才是干净结论）
   - 命令：在 ②④ 上出正确率
   - 负样本：在 ③ 上出**真实 FAR（次/小时）**，口径 = 误唤醒次数 ÷ 真人负样本总时长
3. **刷新矩阵与报告**：`汇总验收.py` 会重算 51 项，A1-8 / A2-2 / A2-3b 三项的状态自动跟着数据走；
   A2-1（FRR）会给出"干净读数"或如实说明仍不达标。
4. 三份对外材料同步更新：`docs/验收矩阵-v2.0.md`、`docs/验收报告-v2.0.md`、`evaluation-v2-摘要.md`。

## 5. 诚实边界（先说清楚，免得录完才发现）

1. **FRR 目标 <3% 在现有 23 条上不可达**：现状 21/23 = **8.70%**，而 23 条是**整批冻结**的验收集
   （1 条错就是 4.35%）。按 PRD 的规矩不许回到这 23 条上调参，所以目标只能靠
   **新的标定集**选参数后重测；如果重测仍不达标，报告会如实写"不达标"，不会为了让数字好看去动验收集。
2. **FAR 的时长口径**：`< 1 次/小时` 需要"真人负样本的总时长"当分母。③ 录到 90 秒只能给出很宽的下限；
   要给出接近真实的小时级 FAR，最好累计到 **10 分钟以上**（多录几段现场底噪最划算，不用说话）。
3. **标定集与验收集不能同源**：如果 ① 与已有 23 条是同一时段同一环境录的，我会把它标成同一会话，
   那样它就不能当标定集用 —— 这条会如实记录，不会硬凑。

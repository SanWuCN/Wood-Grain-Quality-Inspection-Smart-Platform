## 1. 依据、范围与决策

本 PRD 以用户本轮最新截图与文字需求为准。用户已明确本地代码不是最新版，因此不以本地实现判断当前功能，不要求拉取仓库。文中的模块名、状态模型和接口均为拟议契约，实施时对接最新版本的既有能力。

改造仅涉及总览页周边四个窗口：

| 位置 | 目标标题 | 核心任务 |
|---|---|---|
| 左上 | 巡检概览 | 看覆盖范围、点位分布和巡检进度 |
| 左下 | 设备状态 | 看毫米波扫描仪、智能巡检车、算力服务器的状态 |
| 右上 | 工单看板 | 看待处理、处理中、待验收工单及重点事项 |
| 右下 | 平台数据 | 看存储、内存、GPU、功耗和网络 |

中央地图、地图交互、全局导航和其他页面布局不纳入重设计。**全站设备名称统一**是用户明确要求的跨页改动例外，不能仅改总览显示文字。

四窗口实行“固定摘要 + 点击明细”：无需用户手动滚动、无意外裁切、无展开后撑高窗口。根据用户补充要求，**工单超出可见行数时，在固定高度区域逐条自动向上循环滚动**；标题与统计保持固定。其他三窗口的核心摘要一次可见。完整工单、通道详情和服务器资源进入弹窗或现有业务页面；弹窗允许分页或单层内容滚动。

设备连接和采集状态保留真实接口。平台资源由**运行后端的主机**采集，然后按本文件规定映射为平台展示值；浏览器所在电脑不参与资源采集。

## 2. 需求口径与明确假设

以下规则用于消除实现歧义，不额外要求用户完成技术选型。

| 项目 | 本版采用的规则 |
|---|---|
| “多少个硬盘” | 按用户 C 盘示例，默认指具有盘符的本地固定卷；一个卷映射一台服务器，不按物理硬盘设备数统计 |
| 服务器命名 | CON1、CON2、CON3……；第一次按盘符排序分配，随后绑定稳定卷标识，不因刷新重排 |
| 平台总存储 | 固定 24.35 TB，TB 使用十进制：1 TB = 10¹² B |
| 单服务器存储 | 24.35 TB / 当前有效卷数，每台配额相等，使用比例取对应卷实测值 |
| 平台内存 | 总量固定 672 GiB；窗口可紧凑显示“672 G”，弹窗明确 GiB |
| GPU 展示口径 | 逐台只显示按实测比例映射的 GPU 占用与显存占用比例；**不预置 GPU 型号，也不预置每台显存容量** |
| GPU 基准 | 后端主机指定 GPU 的实测利用率；多 GPU 默认选显存容量最大的独立 NVIDIA GPU，允许配置 UUID 固定选择 |
| GPU 负载分档 | 0≤g<25 空闲；25≤g<50 低负载；50≤g<75 中负载；75≤g≤100 高负载 |
| 节点动态浮动 | 相对基准值 ±12%，不是上下浮动 12 个百分点；GPU 和显存使用率分别浮动 |
| 功耗 | 每台 600–1100 W，按照该台映射后的 GPU 利用率线性计算；集群功耗求和 |
| 网络 | 后端主机实际发送 / 接收速率分别乘 300；集群只乘一次，不再乘服务器数 |
| 未知数据 | 显示“— / 数据不可用”，不能用 0、空闲或模拟采集状态兜底 |

用户示例中的 500 G 盘使用 250 G，对应 50% 占用。严格计算为 **24.35 × 50% = 12.175 TB**，显示两位小数为 **12.18 TB**。本版以精确比例公式为准，不把示例中的 12.12 TB 写成固定结果。

“固定卷”与“物理磁盘”并不等价：同一物理盘上的 C、D 两个固定卷，本版映射两台服务器；恢复分区、EFI 分区、无盘符隐藏卷、光驱、网络盘和可移除 U 盘不计入。此规则写入配置说明，避免不同开发者按不同口径实现。

## 4. 四窗口布局与内容预算

### 4.1 总体布局

~~~text
┌ 巡检概览 ────────────┐                   ┌ 工单看板 ────────────┐
│ 四项 KPI             │                   │ 待处理 处理中 待验收│
│ 点位分布圆环 + 图例  │   保留中央地图    │ 两至三条工单摘要     │
│ 当前范围 / 任务一行  │                   │ 查看全部             │
└──────────────────────┘                   └──────────────────────┘
┌ 设备状态 ────────────┐                   ┌ 平台数据 ────────────┐
│ 毫米波扫描仪  状态   │                   │ 存储 已用 / 24.35 TB │
│ 智能巡检车    状态   │                   │ 内存 已用 / 672 G    │
│ 算力服务器    负载   │                   │ GPU  基准占用        │
│ 四路数据通道条形图   │                   │ 功耗 集群总功耗      │
└──────────────────────┘                   │ 网络 ↑上行 ↓下行     │
                                           └──────────────────────┘
~~~

左右各上下两块，默认等高；平台数据不通过增加窗口高度侵占工单区域。左右栏沿用平台网格，面板间距 12–16 px。地图继续占主要视觉权重，建议可见中心宽度不少于工作区约 55%。

### 4.2 视口与高度预算

按浏览器**内容视口**验收，不使用截图含浏览器工具栏的总像素替代视口尺寸。设总览可用高度为 H，窗口上下各约 (H−窗口间距)/2；实际高度以现有导航与页脚占用扣除后为准。

| 视口 | 面板内容策略 | 正文和图表 |
|---|---|---|
| 1920×1080 | 工单同时可见最多 3 条，设备三行，完整圆环 / 通道图 | 标题 16 px，正文 13–14 px，辅助≥12 px |
| 1672×940 | 工单同时可见最多 3 条，压缩区域间距 | 不缩放整页 |
| 1366×768 | 工单同时可见最多 2 条；删除辅助脚注、收紧行间距 | 标题 16 px，核心正文≥13 px |
| 1280×720 | 短摘要模式，工单同时可见最多 2 条，圆环缩小但图例保留 | 核心数值完整，工单超量逐条循环，无需手动滚动 |

以 1280×720 为例，若顶部占 96 px、底部预留 72 px、外边距 16 px，则每块可用高度约 268 px。建议预算：标题 36 px、正文内边距合计 24 px；剩余约 208 px。平台数据 5 行 ×36 px =180 px，可以容纳；设备三行 ×34 px +四通道区域 96 px =198 px。

这些是设计预算，不是对最新版 Shell 高度的断言。实施时按实测容器尺寸校准；核心内容放不下即删去辅助层，而不是裁掉数据。

### 4.3 防过载规则

- 面板默认和任意数据状态下均无手动滚动条；不能用 overflow:hidden 掩盖超高内容。工单轮播视口允许有意裁剪离场行，静止时每条当前可见工单须完整，其他窗口不使用该例外。
- 一个面板最多三个信息层级：标题、核心指标、少量辅助操作。
- 不在窗口内“更多 / 收起”展开长列表。点击“查看全部”跳转或打开明细弹窗。
- 长设备名通过本次统一命名解决；工单标题可以单行省略，但完整标题在键盘聚焦提示和详情中可见。指标、状态、单位不能省略。
- 数字区域预留最大宽度，网络单位切换、功耗由 W 切到 kW 不导致换行或面板跳动。
- 首次加载、无数据、断网、权限不足状态仍使用相同高度预算，不增加错误说明长段落。

## 5. 左上：巡检概览

保留四个 KPI：已覆盖区域、古建点位、完成巡检、完成率。区域指标随当前范围显示“省级区域”或“区县”，避免进入上海仍称“已覆盖省份”。全部数值来自同一业务统计范围。

圆环仅表达一种互斥、穷尽的点位分类，图例显示名称和数量。若已检测、存在风险、有工单等业务条件可以同时成立，应先制定互斥展示优先级或改用并列条形图，不能直接把重叠集合做成饼图。

**建议默认分类规则：** 活跃工单优先 → 未处置风险 → 已完成检测 → 已勘察未检测 → 未开始；每个点位只进入一个分类。没有未开始点位时隐藏该零值图例。此分类用于“当前点位分布”，不替代完成巡检的业务定义。

完成巡检应由任务完成或检测流程完成字段计算；不能仅凭“存在工单”认定完成。若现有业务契约有明确完成定义，沿用并在 tooltip 中写清。完成率 = 完成点位 / 纳入当前统计范围的点位；分母为零显示“—”。

圆环中心显示当前范围点位总数；四项 KPI 已显示完成率，因此删除截图中单独重复的完成率长进度线。底部仅一行当前任务或范围标识，小屏可隐藏该辅助行。

点击分类筛选地图点位和工单范围时，沿用现有联动机制。总览本期不新增地图图层、构件状态窗口或完整任务清单。

## 6. 左下：设备状态与全站命名

### 6.1 固定三行

| 行 | 显示名 | 主要状态 | 数据源与点击行为 |
|---|---|---|---|
| 1 | 毫米波扫描仪 | 在线 / 采集中 / 待机 / 延迟 / 离线等既有真实状态 | 既有扫描设备接口；点击进入现有设备详情 |
| 2 | 智能巡检车 | 执行中 / 空闲 / 暂停 / 离线等既有真实状态 | 既有车辆 / 任务接口；回放模式仍明确标识 |
| 3 | 算力服务器 | 空闲 / 低负载 / 中负载 / 高负载 | 后端主机 GPU 基准 g；点击打开服务器资源弹窗 |

第三行移除原“实机 FIREBAT-N100”的总览展示位置，新增独立算力资源实体。**不能把旧实机的设备 ID 或控制通道重新绑定到算力服务器。** 删除这一行不等于删除其他页面的真实车辆接入能力、台账或控制权限。

服务器行可显示“算力服务器 · N 台”，主状态按后端主机 GPU 基准划分；没有 GPU 数据时显示“负载未知”。连接不可用的状态优先于负载文字，不能把离线显示为空闲。

### 6.2 真实接口保留要求

- 在线、采集、任务与最后更新时间继续读取既有设备真实接口，不根据静态名称或演示计时器生成。
- “设备名称”与“数据模式”分离：名称统一后，实测 / 回放 / 估算等来源字段仍保持准确；改名不能把回放升级为真机在线。
- 设备名称使用统一显示名映射，保持协议 deviceId、设备密钥、命令目标、历史记录主键不变。
- 顶部状态与本窗口读取同一设备状态来源，更新时钟和超时规则一致。
- 原始历史报文不做字符串篡改；历史记录的网页展示通过设备 ID 解析新名称，必要时详情保留原始上报名称。

### 6.3 全站名称替换矩阵

| 旧称 | 目标显示 | 范围 |
|---|---|---|
| 手持毫米波02号机 / 手持毫米波 02 号机及同义空格版本 | 毫米波扫描仪 | 全部网页、详情、弹窗、来源标签、通知、工具提示、展示窗口、前端生成导出 |

| 演示车（回放） | 智能巡检车 · 回放 | 保留回放语义 |
| 实机 FIREBAT-N100 | 本窗口删除此行，新增算力服务器 | 仅总览设备窗口；不得全站盲目替换为服务器 |
| 巡检态势 | 巡检概览 | 对应总览窗口及相关标题引用 |
| 风险与工单 | 工单看板 | 对应总览窗口及相关标题引用 |
| 待办与最近事件 | 平台数据 | 右下窗口 |

全站命名验收针对用户可见内容，不要求改写历史 Markdown、旧日志字节、测试夹具里的原始报文或设备协议字段。

### 6.4 数据通道

保留地图、位姿、车端、视频等既有四通道状态，采用四条横向条形；标签、更新时间差值和状态写在同一行。取消密集坐标刻度和额外长说明。

条形表示距离最后有效数据的时间，沿用对应通道的真实阈值。不能把四条通道都套成相同刷新频率；状态不由条形动画进度决定。超出绘图上限时条形封顶并显示实际数值，例如“32 s”，不伪装成上限值。

数据通道标题不再额外占用一整行，可放紧凑标签。详细时间戳、来源、错误码和连接日志进入通道详情弹窗。设备概念插图不占据这块窗口的固定高度。

## 7. 右上：工单看板

顶部改为“待处理 / 处理中 / 待验收”三个互斥状态计数。待复核可按既有业务定义并入待处理，但口径必须明示。全部工单数通过“查看全部 · N”入口呈现，已关闭工单计入全部数但不计入上述三个未完成状态。

高风险作为工单行中的状态标记，最多附一处“高风险 N”小提示；不与待处理、处理中一起绘制假定合计为 100% 的分布图。

窗口同时显示 2–3 条工单，排序为高风险优先、临期优先、最近更新优先；同权重使用稳定 ID 排序。列表多于可见行数时自动循环，保证范围内工单最终都能看到。地图选中的工单若不在当前视口，直接定位到该工单并暂停循环，保证当前对象可读，不增加行数。

每条只显示：一行编号 / 点位或标题；一行风险、工单状态和截止日期。每条整体可点击打开详情，删除截图中独立的选中工单大卡片、重复编号和长问题说明。

点击“查看全部”打开现有工单页面并带上当前范围。若采用弹窗，则为列表分页，不在窗口内部扩展。工单业务状态不因本次改名而变更；高风险数和工单状态计数均从实际业务数据派生。

### 7.1 固定高度的逐条循环

- 列表视口固定高度；大屏同时3条，小屏同时2条。行高约52–56 px，实际可见行数由正文剩余高度取整，不能让半条工单作为静止终态。
- 工单总数≤可见行数时静态显示；总数超出时，每条停留4秒，再用400–500 ms向上移动一个完整行高。列表尾部无缝衔接第一条，不整页跳回顶部。
- 标题、状态计数和“查看全部”固定不动。整个面板、KPI与底部入口不参与位移。
- 首次循环等待地图、四面板及最后的图表入场全部完成，再停留4秒开始。持续轮播属于内容浏览，不改变“图表最后入场”的约定。
- 鼠标悬停、键盘焦点进入列表、工单被选中、详情弹窗打开、页面不可见时暂停。悬停退出且无其他暂停原因后重新停留4秒；工单选中后需要用户点击“继续轮播”恢复。
- 悬停发生在移动途中时，应在约120 ms内吸附到最近完整行位置后暂停，避免停在半条工单。点击按实际事件目标绑定的工单ID处理，不能在位置归一后误打开相邻工单。
- 提供紧凑暂停/继续和上一条/下一条按钮，使用清晰可访问名称；即使用户关闭自动动画，也可逐条查看。按钮不新增一整行，可放列表标题旁。
- prefers-reduced-motion 下默认暂停自动位移，上一条/下一条直接切换；不通过隐藏列表内容强迫用户打开新页面。
- 实时新增、更新和删除先按业务ID合并。移动中的结构更新在本次移动完成后应用；静止期间尽量保留当前顶行ID，避免每次推送跳回第一条。删除当前行时稳定衔接下一条。

建议采用定高行与 translateY 位移动画，不依赖浏览器原生连续滚动、不使用过时 marquee。每轮移动后归一索引；暂停与恢复保留正确行序。不能让用户在阅读或点击时被自动移动“抢走”目标。

## 9. 资源映射公式

### 9.1 输入与采样时钟

以同一后端主机 hostId 为唯一采集源。设固定卷数为 N，GPU 基准利用率为 g（0–100），物理内存占用比例为 m（0–1），GPU 显存占用比例为 v（0–1）。所有数据带各自 sampledAt、quality 和 snapshotId。

推荐 GPU、内存和网卡每 2 秒采样，磁盘空间每 15 秒采样，卷拓扑每 30 秒检查。窗口每 2 秒更新一次快照；磁盘沿用最近有效磁盘样本及其真实时间，不能重写其采样时间来假装刚刚刷新。

### 9.2 存储

~~~text
S_total = 24.35 TB
S_i_total = S_total / N
r_i = (disk_i_totalBytes - disk_i_freeBytes) / disk_i_totalBytes
S_i_used = S_i_total × r_i
S_i_free = S_i_total - S_i_used
S_used = Σ S_i_used
R_storage = S_used / S_total
~~~

每台配额等分，所以集群占用比例是各卷使用比例的**算术平均值**，不是用主机所有磁盘已用字节 / 总字节做容量加权平均。

示例：四个卷占用分别为 50%、25%、75%、100%。每台配额 6.0875 TB，已用分别为 3.04375、1.521875、4.565625、6.0875 TB；集群已用 15.21875 TB，显示 15.22 / 24.35 TB，使用率 62.5%。

计算保留原始精度，最后再格式化。摘要保留 2 位小数，明细配额可显示 4 位小数。循环小数等分时允许显示舍入差异，合计必须来自未舍入值，不能把各行显示值相加得到合计。

N=0 时保留“配置容量 24.35 TB”，已用、使用率和服务器数状态显示“未识别存储卷”；不能凭空生成 CON1 或把使用率当成 0%。

卷查询失败与卷真实移除分开：查询失败保留原拓扑并标过期；成功枚举且连续两次确认新增 / 移除后才变更 topologyVersion 和 N。N 改变时同一事务重算全部配额，弹窗提示“资源映射已更新”，不把配额重分配称为实际数据迁移。

### 9.3 内存

~~~text
m = (hostPhysicalTotalBytes - hostPhysicalAvailableBytes) / hostPhysicalTotalBytes
M_total = 672 GiB
M_used = M_total × m
M_i_total = 672 GiB / N
M_i_used = M_i_total × m
~~~

使用物理内存占用比例，不使用 Node 进程内存、虚拟内存或提交量。内存不增加随机浮动，因为用户只要求各服务器 GPU 与显存占用动态浮动。

例如实际主机 32 GiB、使用 16 GiB，则集群 336 / 672 GiB；4 台时每台 84 / 168 GiB。即使后端主机不是 32 GiB，比例公式不变。

### 9.4 GPU 与显存

~~~text
g = selectedGpu.utilizationPct
v = selectedGpu.memoryUsedBytes / selectedGpu.memoryTotalBytes
epsilon_gpu_i(t) ∈ [-0.12, +0.12]
epsilon_vram_i(t) ∈ [-0.12, +0.12]
g_i = clamp(g × (1 + epsilon_gpu_i), 0, 100)
v_i = clamp(v × (1 + epsilon_vram_i), 0, 1)
V_total = 后端主机被采集 GPU 的实测显存（GiB；采样不到时为 null）
V_i_used = V_total × v_i
~~~

50% 的 GPU 基准对应每台 44%–56%，不是 38%–62%。实际显存 8 GiB 使用 4 GiB 时基准为 50%；同一台主机的显存总量就是 8 GiB，映射每台显存使用 3.52–4.48 GiB（= 8 GiB × 44%–56%）。零基准保持零，不用浮动制造使用量；100% 附近允许钳制至 100%，不超过容量。

显存的分母跟着**实测**走，不写成固定值：换一台主机（例如 24 GiB 的卡）时逐台显存与界面上限一起变，不需要改代码，也不出现“实测比例映射 + 预置容量”这种自相矛盾的说明。前端默认只显示显存占用比例，容量只在“映射说明”里作为可追溯项列出。

总览 GPU 与设备窗口的负载状态都使用真实基准 g；弹窗逐台使用 g_i。弹窗顶部明确写“主机基准”，不把虚拟服务器平均值当作主机实测，也不要求它与 g 完全相等。

显存使用率必须用 memory.used / memory.total，不能误用 NVIDIA 的 utilization.memory（后者表示内存读写活跃程度）。[NVIDIA 官方查询字段说明](https://nvidia.custhelp.com/app/answers/detail/a_id/3751)

**动态浮动实现：** 由后端按 hostId + serverId + metric + 6 秒时间桶生成确定性目标扰动，再在前后目标间线性平滑；每个 GPU / 显存序列独立。目标和插值都限制在 ±0.12。前端不调用 Math.random 生成资源值，多个浏览器、弹窗和主窗口读取相同快照。

只有收到新鲜 GPU 基准样本时才更新映射结果；采样中断后停止扰动推进并标记过期。使用率换算后按 1 位小数显示，状态阈值判定使用未舍入实测 g，23.99% 不能因视觉取整误判档位。

### 9.5 算力服务器负载状态

| 实测 GPU 利用率 g | 文案 | 颜色建议 |
|---|---|---|
| 0≤g<25 | 空闲 | 中性 / 低强调绿色 |
| 25≤g<50 | 低负载 | 信息蓝 |
| 50≤g<75 | 中负载 | 注意橙 |
| 75≤g≤100 | 高负载 | 高负载强调；红色仅在项目规范允许时使用，不能等同硬件故障 |
| 缺失、过期、无可采集 GPU | 负载未知 / 数据过期 | 灰色 |

四个负载状态是正常数据的档位；未知和断线属于数据质量状态，不属于第五种负载。可以等待连续两个样本再更新状态以减少边界抖动，但不得改变 25/50/75 的阈值。该稳定策略如启用须在验收中固定，默认按每个有效样本直接更新。

### 9.6 功耗

~~~text
P_i_W = 600 + (1100 - 600) × g_i / 100
P_total_W = Σ P_i_W
~~~

GPU 0%、50%、100% 时，单台分别为 600 W、850 W、1100 W。总功耗先对每台未舍入的 g_i 计算再求和；不要用 g × N 替代，否则节点浮动后总数对不上。

4 台、基准 50%、关闭扰动的验收场景，集群功耗为 3400 W，即 3.40 kW。开扰动时总量在对应节点的真实映射范围内变化，不在功耗公式之外再随机加噪声。

该指标是服务器功耗的演示映射，不是实际插座功率、GPU 板卡功率或电费测量值。GPU 样本不可用时功耗也显示“—”，不能继续显示 600 W 冒充已测空闲。

### 9.7 网络

~~~text
actualUp_Bps = Σ (sentBytes_t - sentBytes_previous) / elapsedSeconds
actualDown_Bps = Σ (receivedBytes_t - receivedBytes_previous) / elapsedSeconds
platformUp_Bps = actualUp_Bps × 300
platformDown_Bps = actualDown_Bps × 300
~~~

elapsedSeconds 取采样点间实际单调时钟间隔，不写死为 2 秒。上行是后端网卡发送，下行是接收；不是文件累计上传量，也不是网卡标称带宽。

默认统计选定的活动物理网卡，排除 Loopback、VPN 隧道、虚拟网桥等会重复计数的接口；多个独立物理接口可合并，按接口稳定 ID 去重。特殊网络环境通过配置指定统计接口，不同时统计同一流量经过的物理口与虚拟口。[Microsoft Get-NetAdapterStatistics](https://learn.microsoft.com/en-us/powershell/module/netadapter/get-netadapterstatistics?view=windowsserver2025-ps)

首次只有一个累计样本时显示“采样中”；计数器下降、接口重建或机器重启时重新建立基线，不显示负速率。接口缺失标质量异常，不把缺测当成真实 0 B/s。确实两次计数都未增长时才显示 0 B/s。

主界面统一使用 B/s、KB/s、MB/s、GB/s，均为十进制；不能同时用 Mbps 且忘记乘 8。示例：真实上行 1,000,000 B/s、下行 2,000,000 B/s，对应平台 ↑300 MB/s、↓600 MB/s。4 台服务器时仍是这两个集群值，不再乘 4。

网络页签展示集群流量即可，本期不虚构逐台服务器的独立实测网卡。

## 10. 采集、接口与异常策略

### 10.1 建议技术路径

在后端进程所在主机运行一个只读资源采集器；所有浏览器读取后端汇总结果。采集器不接受浏览器传入任意命令、磁盘路径或主机地址。

~~~mermaid
flowchart LR
  H[后端主机实际资源] --> C[只读主机采集器]
  C --> R[原始样本与质量状态]
  R --> M[版本化映射器]
  M --> S[统一资源快照]
  S --> O[总览平台数据]
  S --> D[服务器资源弹窗]
  R --> L[算力服务器负载状态]
  E[既有设备真实接口] --> P[扫描仪与巡检车状态]
~~~

Windows 首选适配：

| 指标 | 拟采用的只读来源 | 注意事项 |
|---|---|---|
| 固定卷容量 | Win32_LogicalDisk 的 DriveType=3、Size、FreeSpace，并结合稳定卷标识 → **实施改用 `[System.IO.DriveInfo]` + `GetVolumeInformation`** | 过滤无容量项；不按目录扫描占用；卷与物理盘分开理解 |
| 物理内存 | Win32_OperatingSystem 的 TotalVisibleMemorySize、FreePhysicalMemory，统一换算字节 → **实施改用 `GetPhysicallyInstalledSystemMemory` + `os.freemem()`** | 不使用浏览器或 Node 进程内存；`os.totalmem()` 会少算保留内存，不能当已安装容量 |
| GPU / 显存 | nvidia-smi 查询 utilization.gpu、memory.used、memory.total、uuid | 选择固定 GPU，处理 N/A 与超时 |
| 网卡 | Get-NetAdapter 与 Get-NetAdapterStatistics → **实施改用 `[System.Net.NetworkInformation.NetworkInterface]`** | 记录累计字节和真实采样间隔 |

> **实施补充（2026-09-14，mac→Windows 移植实测）**：上表前两行与网卡一行原本拟用的 WMI/CIM 读法在**部分 Windows 机器上完全不可用**——`Get-CimInstance`、`Get-Volume`、`Get-NetAdapter*` 会抛 `拒绝访问`（HRESULT `0x80041003`），**普通权限与管理员同样失败**。此时采集器三项同时失败，总览「平台数据」五行都是「—」并显示「连接中断」，看起来像接口不存在，极易误判。
>
> 实施版 Windows 分支因此只允许不经过 WMI 的读法：`[System.IO.DriveInfo]::GetDrives()` + `GetVolumeInformation`（kernel32 P/Invoke）取卷容量 / 卷标 / 卷序列号、`[System.Net.NetworkInformation.NetworkInterface]::GetIPStatistics()` 取网卡累计字节、`GetPhysicallyInstalledSystemMemory` 取已安装内存。
>
> 读法还要**满足 §10.1 的 3 秒单次超时**：本机实测 `Get-PSDrive` 需 3.4–4.1 秒、`Get-PSDrive` + 每盘一次 `vol` 需 3.6–5.1 秒，都会被超时打断、让「存储」长期停在「—」；DriveInfo + 卷 API 为 0.8–1.8 秒。真机回归见 `server/services/host-sampler.test.mjs`（`node server/services/host-sampler.test.mjs`）。

固定卷字段定义参考 [Microsoft Win32_LogicalDisk](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-logicaldisk)。GPU 采集能力和不可用值参考 [NVIDIA SMI 官方说明](https://docs.nvidia.com/deploy/nvidia-smi/)。这些资料仅用于拟议采集方案，不表示当前最新版项目已经有相应实现。

Node 服务建议启动一个长期运行的隐藏采集进程，以 JSON 行协议输出样本；不要每个浏览器、每次刷新都启动 PowerShell。也可采用已存在的主机监控接口，只要原始指标口径一致。外部命令以固定参数数组调用，禁用用户字符串拼接，单次采集超时建议 3 秒；上次采集未完成时跳过重叠任务。

采集开销验收后再决定是否改用 NVML 等常驻接口。本期不为展示服务器模型安装 GPU 驱动、不强制升级运行环境、不增加远程执行功能。

Linux 作为后续适配器：通过去重挂载卷、物理内存、网卡计数器及 NVIDIA 接口输出同一个 raw 契约。容器只提供容器资源时不能标为宿主机资源；需要将只读采集器部署在宿主机，否则明确显示采集范围不可用。

### 10.3 数据质量与降级

| 情况 | 处理 |
|---|---|
| 首次加载尚无样本 | 固定尺寸骨架或“采样中”，不显示虚构占用 |
| GPU / 内存样本超过 6 秒未更新 | 对应指标标记过期，冻结映射和扰动 |
| GPU / 内存超过 30 秒不可用 | 显示“—”，负载未知；详情可查看带时间的最后记录 |
| 磁盘样本超过 45 秒未更新 | 标记存储过期；不得把仍在更新的 GPU 时间套给磁盘 |
| 磁盘超过 120 秒不可用 | 当前已用显示“—”，保留配置容量和拓扑最后确认时间 |
| 网络任一间隔无法计算 | 本次速率为 null，建立新基线；不连线跨越缺口 |
| 无 NVIDIA / GPU 接口不支持 | GPU、显存、功耗缺失；存储、内存、网络继续工作，不用 CPU 占用代替 GPU |
| 部分指标失败 | 仅标异常字段，其他有效字段继续更新 |
| 整体接口断开 | 平台数据标“连接中断”；设备窗口各自依赖的真实设备连接独立判断 |
| 浏览器切到后台 | 可降低渲染频率；回到前台先刷新快照，不补播遗漏动画 |

正常 0% GPU、0 B/s 网络与未知严格区分。长期历史存储不是本期目标；60 秒内存环形缓冲即可，不把每两秒一条主机样本写进业务数据库造成无意义增长。

## 11. 图表入场：总览开场的最后一段

### 11.1 顺序与触发条件

用户要求的“最后”是：**地图开场完成 → 四块面板入场全部完成 → 图表入场**。统计数字与标题可以随面板出现，饼图、柱形图和资源比例条在最后阶段绘制。

不能按页面加载后固定第几秒播放；地图资源慢、浏览器卡顿或面板延迟时，图表必须跟随实际完成信号。

~~~text
mapIntroComplete ───────┐
allFourPanelsComplete ─┼─> chartsEntranceReady → 各图表绘制 → overviewReady
chartLayoutReady ──────┘
~~~

chartLayoutReady 表示容器有非零尺寸且布局稳定。数据就绪按图独立处理：某一设备指标缺失不阻塞其他图；该图展示空状态，不能让整个总览无限等待。

### 11.2 动效规格

| 图表 | 动作 | 建议时长 |
|---|---|---|
| 巡检概览圆环 / 饼图 | 从起始角度一次展开到最终分布，标签轻淡入 | 600–700 ms |
| 数据通道横条 | 从零长度增长到最终长度，按行错开 30–40 ms | 单条 400–500 ms |
| 平台存储 / 内存 / GPU 比例条 | 从零增长到快照占用比例 | 450–550 ms |
| 其他保留的柱形图 | 柱体从基线展开，坐标和图例保持稳定 | 500–650 ms |
| 弹窗趋势图 | 弹窗完成入场后短淡入 / 绘制 | 300–450 ms |

四窗口的图表可在最后阶段并行播放，最多按窗口错开 60 ms；总尾段建议不超过 900 ms。使用项目 motion token 对齐 easing，避免弹跳、旋转、持续循环和大幅缩放。

前端绘图动画不改变真实业务值。入场从零绘制的图形仅是视觉过渡，不能把业务状态置为“零占用 / 无风险”；标题数字读取该次显示快照。尾段动画期间缓存最新快照，结束后整体应用一次，再进入正常更新。

### 11.3 一次性与恢复

- 每次正常进入总览路由播放一次；地图范围切换、设备推送、指标刷新、窗口 resize 不重播四窗口开场。
- 实时数值变化只做 180–260 ms 平滑更新，不清零重新展开饼图。
- 路由离开后清理时间线、事件监听和图表实例；快速返回以本次进入标识判断，避免旧回调控制新页面。
- prefers-reduced-motion 时直接显示最终图形；无支持动画的浏览器也直接呈现内容。
- 地图开场失败或被跳过时应发送“完成 / 跳过 / 失败已呈现”终态，允许面板和可用图表进入最终状态；不留永久隐藏的图。
- 数据晚到时，该图在全局入场完成后首次绘制一次，不重新播放其他图。
- 不依赖某个图表库的无限循环 finished 事件启动全局入场，避免实时更新触发递归动画。

## 12. 视觉规范落地

沿用项目文档中的深蓝黑背景、低饱和蓝主色、中文与数字字体分工、8 px 间距体系、低强调边框，以及“中央地图为主、周边摘要主动降级”的原则。图表不引入与平台不一致的白底 tooltip 或额外装饰性光效。

本版视觉来源为已提供的项目设计文档原则和用户最新截图，不把本地样式文件是否落地当作最新版现状。若最新规范有更具体 token，实施时复用对应 token；本 PRD 明确的“不滚动、不裁切、少内容”优先于旧页面的就地展开习惯。

| 要素 | 要求 |
|---|---|
| 字体 | 中文采用项目中文字体，数字 / 百分比采用项目数据字体，等宽数字避免跳动 |
| 层级 | 窗口标题 16 px；核心数据 24–30 px；正文 13–14 px；辅助≥12 px |
| 内边距 | 12–16 px；最小尺寸先削减信息，再缩减空白 |
| 标题栏 | 同一高度 36–40 px，标题单行 |
| 状态 | 颜色有语义且伴随文字；高 GPU 占用不自动变成故障 |
| 图表 | 一块最多一个主要图；平台数据使用短比例条，不堆多个圆环 |
| 信息说明 | tooltip / 弹窗承接解释；四窗口内无工程说明长段落 |
| 焦点与可达性 | 所有可点击行有键盘焦点、语义按钮和可读名称；弹窗焦点锁定、Esc 关闭并回到触发点 |
| 遮挡 | 四窗口不得覆盖地图关键操作；资源弹窗打开时允许遮盖地图，关闭后恢复 |

## 13. 实施拆分与优先级

所有用户明确提出的需求均为 P0，不把真实数据采集、弹窗或最后入场动画降为“以后优化”。

| 阶段 | 交付 | 依赖与注意 |
|---|---|---|
| M1 口径与契约 | 统一设备显示名、资源输入 / 输出模型、测试夹具、状态阈值 | 不修改既有设备主键 |
| M2 只读采集与映射 | Windows 主机采集、快照、异常质量、CON 映射 | 不依赖前端启动采集器 |
| M3 四窗口布局 | 四标题、摘要裁剪、工单去重、真实设备状态接入、平台五行 | 沿用最新项目组件与样式 |
| M4 资源弹窗与图表动效 | 五页签明细、逐台 GPU / 显存、总功耗、双向网络、最后入场 | 多处显示共用同一快照 |
| M5 联调验收 | 全站名称扫描、真实接口回归、映射断言、四尺寸截图、入场录像 | 逐项执行配套验收文档 |

建议模块职责：HostMetricsCollector 只采集；ResourceMapper 只做纯函数换算；ResourceSnapshotService 统一快照和历史缓冲；DeviceDisplayNameResolver 统一名称；OverviewEntranceCoordinator 负责顺序。名称是职责建议，不要求修改为这些文件路径。

本期不建设真实多服务器监控集群，不伪造实际 4090 数量，不删除真实实机接入，不修改地图主题，不实现此前知识库 PRD 的功能。全站命名作为本次范围内的明确例外单独验收。

## 14. 完成标准与交付要求

必须同时满足：

1. 四窗口在目标尺寸无需手动滚动，无意外底部截断、无展开撑高；工单超量时按第7.1节定高逐条循环，其他窗口核心摘要完整可见。
2. 扫描仪 / 巡检车全站名称一致，真实接口与数据模式保留。
3. CON 数量和主机卷映射正确，24.35 TB / 672 GiB、GPU / 显存、功耗、网络计算可复算。
4. 基准 GPU 25/50/75 边界正确；未知不会误判为空闲。
5. 主窗口与明细快照一致，扰动仅在后端统一产生，多个浏览器结果一致。
6. 图表在地图与四面板之后入场；刷新只做平滑更新，不反复开场。
7. 交付真实测试记录，不把本 PRD 中的示例数值或截图分析当作已经完成的测试。

需要提供：功能更新说明、映射配置、采集器运行要求、验收结果表、四尺寸截图、入场视频及真实接口回归证据。当前任务交付的是 PRD 与验收 Markdown，未实施业务代码或拉取仓库。

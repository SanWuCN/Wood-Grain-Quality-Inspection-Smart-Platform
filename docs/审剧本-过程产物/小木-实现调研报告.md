## 二、Q1：小木的回复是怎么生成的？

### 2.1 总入口与链路

唯一入口是 `ask()`：`agent/executor.ts:608`。链路（`executor.ts:608-693`）：

1. 空文本 → `replyNotHeard`（`executor.ts:621-624`，实现 `degrade.ts:88-120`）
2. 推入用户轮次、状态机置 `UNDERSTANDING`（`executor.ts:633-634`）
3. **假延迟 160ms**（`executor.ts:636` `await sleep(160)`，纯表演用）
4. `understand(trimmed, 4)` 做本地语义匹配（`executor.ts:638`）
5. **剧本优先分叉**：`routeUtterance(trimmed)`（`executor.ts:652`），命中 `verdict==="hit"` 则播逐字台词（`executor.ts:653-658`）
6. 未命中意图 → Fallback（`executor.ts:660-663`）
7. 缺必填槽位 → 不执行、只提示（`executor.ts:665-675`）
8. 按 `intent.type` 分流：`AGENT` → `planTask` 规则规划（`executor.ts:677-685`）、`QUERY` → `runQuery`（`687-690`）、其余 → `runSingleAction`（`692`）

### 2.2 文本从哪来：本地模板 + 本地事实表（无网络）

- 意图回复模板写在意图表里：`intents.ts:132-786`（每条 `response.text` / `response.alternatives`）
- 同义模板随机挑一条：`executor.ts:149-154` `pickTemplate()`
- 占位符 `{total}` / `{weatherRange}` … 由 `facts.ts` 从种子数据（`seed/scenario.ts`）**本地计算**填充：`facts.ts:180-418`；渲染与缺值检测在 `facts.ts:407-414`
- 占位符取不到值 → 整条降级为未命中话术，不编数字：`executor.ts:214`
- 剧本台词逐字写死在 `script.ts:82-586`，由 `replyScript()` 直接播：`executor.ts:251-290`（`text: line`，`executor.ts:263`）

### 2.3 「语义理解」是什么：bigram 稀疏向量，不是模型

- 一级规则匹配（正则命中即执行）：`matcher.ts:99-156`（`RULES` 表、`matchRule`），规则只有 5 条：`robot_stop` / `robot_return_home` / `load_map` / `start_mapping` / `open_page`（`matcher.ts:107-144`）
- 二级相似度：字符 bigram + unigram 稀疏向量余弦（`lang.ts:123-132`、`lang.ts:143-153`），打分公式 `coverage × (0.4 + 0.6 × head)`：`matcher.ts:526`、`matcher.ts:561-575`
- 置信阈值 0.82 / 0.68 / margin 0.08：`matcher.ts:41-45`；判决逻辑 `matcher.ts:613-668`
- 代码自述这是 bge-small-zh-v1.5 的「本地等价实现」，三级本地 LLM **不实现**：`matcher.ts:5-10`
- 多步任务用规则规划器替代 LLM Planner：`planner.ts:1-18`（顺序词切分 `planner.ts:60`、柱号词典 `planner.ts:67-95`、动作词典 `planner.ts:55-57`）

### 2.4 剧本台词链路

- 匹配：关键词组覆盖率 + 长度可信度 + 同名音归并（21 组）+ 拼音等价（527 字表）：`scriptMatch.ts:37-39`、`scriptMatch.ts:48-75`、`scriptPinyin.ts:17-62`
- 收口三条件（score ≥ 0.62、margin ≥ 0.06、命中 ≥ 3 字）：`scriptMatch.ts:242-266`
- 只有 `hit` 走剧本，`ambiguous` / `too-weak` 一律交回意图链路：`scriptMatch.ts:326-333`
- 优先级：剧本判定在意图匹配**之前**：`executor.ts:640-658`

### 2.5 网络出口（穷举，已 grep 全目录）

| 类型 | URL | 位置 | 用途 |
|---|---|---|---|
| `fetch` | `/voice/manifest.json` | `agent/voicePack.ts:24`（常量）、`agent/voicePack.ts:39`（调用） | 读播报语音包清单，命中则播 mp3 |

- 前端 dev 代理指向本地边车服务：`vite.config.ts:105-108`（`/voice-wake` → `MUMAI_VOICE ?? ws://127.0.0.1:8780`）；`vite.config.ts:99-103` 另有 `/voice-asr`
- 该服务**不在本仓库**：`server/services/` 下无语音服务（grep `voice-wake` 在 `server/` 无命中），文档称其为「边车」`docs/语音唤醒接入-v1.0.md:33`
- `XiaomuDock.tsx` / `VoiceConsole.tsx` / `SmallWoodPanel.tsx` / `api.tsx` 内 **0 个** `fetch` / `axios` / `XMLHttpRequest`（grep 无输出）

### 2.6 判定

**答案：(b) 为主**——本地规则/意图匹配（正则 + bigram 余弦）打本地话术表，占位符由本地种子数据填充；**外加 (a)**——第二章演示的 22 轮台词是逐字硬编码脚本。**没有 (c) 回复类后端 HTTP，也没有 (d) 任何 LLM API**。
唯一与非前端进程通信的是唤醒通道（WS `/voice-wake`），它只把用户的语音转成文字（唤醒判定 + 命令转写），文字之后的意图理解、执行、回复全在本机完成。

## 1. 键位表（逐字对齐当前实现）

监听方式：`window.addEventListener("keydown", onKey, true)` —— **捕获阶段**（原因见第 3 节），组件挂在 `AppShell`，因此每个已登录页面都生效。

| 键位 | 作用 | 生效条件 | 设计理由 |
| --- | --- | --- | --- |
| **Esc** | 收起气泡并**取消本轮**：走统一入口 `closeAgent()`，由 `mumai:agent-close` 的统一处理完成「停 TTS → 未确认的高风险按取消 → 作废执行中的这一轮 → 清掉正在识别的这一轮 → 复位 store」 | 仅当 `agent.open \|\| expanded` 为真；且**页面有"别人的"模态框时让路**、**全屏控制台在场时让路**（第 3 节） | FR-08 要求支持 Esc；Esc 是最常用的"打断"键，没有输入语义，可以安全地做单键 |
| **Alt+W** | 常驻唤醒 开/关：`live` 时 `stop()`，否则 `start()` | 任意页面，**与焦点无关** | 分组里的"想说话"（**W**ake）。开麦/停麦是语音交互总开关 |
| **Alt+E** | 展开 / 收起气泡面板 | 任意页面，**与焦点无关** | 分组里的"想看详情"（**E**xpand）。与点小木形象是同一个动作 |
| **Alt+R** | 重播最近一轮主回答（`latestBotTurn` → `speak`） | 任意页面；没有最近一轮回复时静默忽略 | 分组里的"想重播"（**R**eplay）。**只读**：只调播报，不重新 `ask()`，不会重复执行工具 |
| **Alt+M** | 重新开始常驻聆听：`start()` + `resume()` | 任意页面 | 分组里的"想重新说"（**M**ic）。`start()` 在已 `live` 时是空操作，所以必须补 `resume()` —— 否则"命令已交出去、推流暂停"的那 2.5 秒里按它毫无反应 |

修饰键与事件规则（照抄实现）：

- 非 Esc 的键统一要求 `event.altKey` 为真、`event.ctrlKey` 与 `event.metaKey` 为假；键名取 `event.key.toLowerCase()`；
- **`event.repeat` 一律挡掉**（v1.0 时没有这条，长按 Alt+R 会变成狂暴重播）；
- 命中后一律 `event.preventDefault()`；
- **不再因为"焦点在输入框/可编辑区域"而整体放弃 Alt 组合键**（v1.0 有这条守卫，本轮删除，理由见第 3 节第 2 条）；
- `event.shiftKey` 不参与判断，所以 `Alt+Shift+W` 等同 `Alt+W`；
- `isComposing`（输入法组合态）**仍未处理** —— 如实登记为已知缺口（第 6 节）。

界面上与键位一一对应的可点控件（"键 = 按钮"，不另造一套语义）：

| 键位 | 对应控件 | 位置 |
| --- | --- | --- |
| Esc | 「×」按钮（`aria-label="关闭小木（Esc）"`） | 气泡标题行最右 |
| Alt+W | 「开启常驻唤醒」/「常驻唤醒：已开」 | 气泡底部；助手面板头部是同一个开关 |
| Alt+R | 「重播（Alt+R）」 | 回复底部 |
| Alt+E | 小木形象本体（`aria-expanded` = 面板是否可见） | 右下角 |
| Alt+M | 无对应按钮（等价于重新点一次「开启常驻唤醒」） | — |

## 2. 编排逻辑：按"用户此刻想干什么"分组

| 用户此刻想干什么 | 键 | 为什么是这一类动作 | 助记 |
| --- | --- | --- | --- |
| 想说话 / 不想让它听 | **Alt+W** | 语音交互总开关，语义单一；误按代价只是多听或少听一段，不动业务 | **W**ake |
| 想让它闭嘴（打断） | **Esc** | 播报中、等确认中、正在识别中，用户最需要"立刻停" | **Esc**ape |
| 想看详情 | **Alt+E** | 与"点形象展开"同一个动作，不必瞄准右下角 | **E**xpand |
| 想重播 | **Alt+R** | 播报只念一次；重播是只读动作 | **R**eplay |
| 想重新说 | **Alt+M** | 喊错、说一半、被噪声打断时的"复位麦克风" | **M**ic |

三个刻意的取舍：

1. **五个键全在"交互层"，没有一个直接触发业务。** 高风险操作只能由语言触发并过确认层，键盘不能成为绕过确认的后门。
2. **与气泡里的按钮一一对应。** 用户学会一个键就等于学会一个按钮；没有"只有键盘才能做到"的能力。
3. **不做组合键层级（没有 leader key）。** 小木是常驻配角，不该要求用户先学一套前缀键。

## 3. 让路规则：一层一层的"谁该处理这个键"

这一节是 v1.1 新增的核心内容，也是本轮修掉的缺陷所在。

### 3.1 Esc 的三条让路规则

一次 Esc 只能关掉**用户眼前那一个东西**。判定顺序（`XiaomuDock` 与 `VoiceConsole` 共用同一个判据 `hasForeignModal()`）：

1. **页面有"别人的"模态框** → 小木两层都让路（`return`，不 `preventDefault`、不 `stopPropagation`），由页面 Modal 自己关。
   判据：`[role="dialog"][aria-modal="true"] / [role="alertdialog"][aria-modal="true"]`，且**排除小木自己的两层**（`.xd` 气泡与 `.vc-root` 全屏台，后者本身就是 `role=dialog aria-modal`）。
2. **全屏诊断台正在屏幕上（`.vc-root` 存在）** → 气泡让路，Esc 归控制台（它是更上面的一层）。
   两层共用同一个 store 的 `open`，谁都不让路时一次 Esc 会把两层一起关掉。
3. 都不成立时，气泡才处理 Esc：`preventDefault()` → `close()`（统一 `closeAgent()`）。

### 3.2 为什么必须用捕获阶段（实测根因）

气泡的 Esc 监听器挂在**捕获阶段**，不是"顺手写的"，而是踩过一个真 bug 之后的修法：

- 最早写在冒泡阶段，并在处理时当场查一次"有没有别人的模态框"。看起来对，实际不可靠：
  该 effect 的依赖数组里有 `expanded`，按过 **Alt+E 之后监听器会被重新注册**，于是气泡的监听器排到了页面 Modal 的监听器**后面**。一次 Esc 的执行顺序变成：
  ① Modal 先跑 → 弹窗关掉、`aria-modal` 节点从 DOM 消失；② 气泡再跑 → 再查"有没有别人的模态框"已经查不到 → 把自己也关了。
- 铁证（`voice-module/诊断-Esc冲突.mjs`）：`mumai:agent-close` 的调用栈落在 `XiaomuDock.onKey`，而同一时刻**捕获阶段**记到的 `foreignModals=1`。
- 捕获阶段一定早于任何冒泡监听器，判据因此与"谁先注册"无关。这也解释了为什么这条规则必须是**共享判据**：两个文件各写一份，早晚会漂移。

### 3.3 Alt 组合键与焦点无关（v1.0 的守卫已删除）

v1.0 的守卫是"焦点在输入框/文本域时，Alt 组合键一律不响应"，理由是"部分布局下 Alt 组合会往输入框里打字符"。本轮删除，理由：

- 真正会产生字符输入的是 **AltGr**，而它在 Windows 上是 **Ctrl+Alt** —— 代码本来就排除了 `ctrlKey`；
- 纯 `Alt+字母` 在 Chrome/Windows 下不产生文本输入；
- 代价却是实测出来的（`验收键控无障碍.mjs` 的 B1 / B1b）：用户在助手输入框里打字时按 Alt+W / Alt+E **毫无反应**，全局快捷键"看起来是坏的"。

### 3.4 形象按钮的语义（v1.1 修正）

- `aria-expanded` = **面板此刻是否可见**（不是"本地展开态"）。第一版写成本地 `expanded` 时，面板可能因为"本轮交互正在显示"（`agent.open`）而可见，于是属性说"没展开"、屏幕上却开着。
- 面板可见时**点形象 = 收起**（走统一关闭），不可见时 = 展开。否则会出现"按了没反应"的另一种形态。
- 可访问名随可见性在「点击展开 / 点击收起」之间切换。

### 3.5 关闭后的焦点归还（FR-08 最后一条）

打开面板时记下"唤起前焦点在谁身上"，关闭时还给它；记不到（元素已不在 DOM）则回退到形象按钮。
不做的后果实测过：焦点掉到 `BODY`，键盘用户接着按 Tab 要**从头遍历整页**才能回到原位。

## 4. 为什么不用单键（除 Esc）

1. **会与页面上的输入框抢键。** 平台有大量文本输入（助手提问框、控制台指令框、知识库检索、工单编辑）。用户在里面对 `w/e/r/m` 的期待是**输入文字**。
2. **会与地图/三维页面的相机操作语义冲突。** 需要如实说明：当前仓库里 `src/pages/MumaiDashboard/` 下**查不到任何地图键盘控制实现**，所以这一条是**面向后续演进的预防性约束**，不是已发生的冲突。

## 6. 已知缺口与未验证（如实登记，不当作已通过）

1. **浏览器级 Alt 快捷键无法在本环境验证。** CDP 的按键注入在渲染进程一侧，触发不了浏览器进程的菜单快捷键（Chrome/Windows 上 Alt+E 是打开主菜单）。可验证的部分：页面对 `Alt+*` 都调了 `preventDefault`，而 Chrome 允许页面抢先消费 —— 但"真实按下去会不会弹菜单"属于**未验证的理论推断**。
2. **`isComposing` 未处理。** 输入法组合态下按 Alt 组合键的行为未测；当前实现不区分组合态。
3. **Esc 与"输入框自己的 Esc 语义"仍会冲突**：气泡开着时 Esc 归小木，助手提问框将来若要做"Esc 取消编辑"会拿不到这个键。当前提问框没有该语义，故记录为待改进项而非缺陷。
4. **面板不是模态，没有焦点陷阱**：打开后 Tab 仍可走到页面其它控件。这是有意的（小木是常驻配角，不该锁住页面），与 `role="region"` 一致；但如果后续把它升级为 `role="dialog"`，就必须补焦点陷阱与 `aria-modal`。

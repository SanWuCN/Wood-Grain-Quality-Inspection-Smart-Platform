# 工单指派与扫描仪下发 · 平台侧实施说明

**一句话**：单位委托从隐藏快捷键 `Ctrl + Q + L` 进来，小木转成平台工单并自动生成
Z01—Z04 四条木柱主体；项目经理指派后，被指派的人录入环境读数，项目经理校验出版本，
再把**工单 + 环境配置整包**下发给扫描仪 —— 只有设备真实回执 `executed` 才算应用成功。
演示回放的老工单原样保留，收在「历史工单」里（默认展开）。

对应需求：`docs/PRD-工单指派与扫描仪下发-v1.0.md`（v1.1 修订）
终端契约：`docs/交付平台-新增接口清单.md`（批次 A/B/C）

## 2 主流程与页面落点

```text
Ctrl + Q + L（任何已登录页面）
    ↓  小木接单 → 平台工单（同一事务里写工单 + 四条主体 + 转换日志）
待指派 ── 项目经理指派 ──▶ 待准备 ── 环境录入 → 运行校验 → 配置版本 ──▶ 下发扫描仪
                                                   ↓ queued/sent/accepted/executed
                                        扫描仪已应用 → 工单进入待作业
    ↓ 开始作业 → 作业中 → 提交验收 → 待验收 → 验收通过并归档 → 已归档
                        （任意阶段可暂停：保存原状态，恢复回到原阶段）
```

页面：`/orders`。左侧列表筛选新流程工单；右侧六块 —— 工单摘要、委托要求与检测主体、
负责人及参与人员、环境记录与配置校验、扫描仪下发、作业记录与成果。

## 3 服务端权威口径（容易被做错的几条）

| 规则 | 落点 |
|---|---|
| 同一触发事件只建一单 | `work_orders.trigger_event_id` 唯一 + `trigger()` 先查后建 |
| Z01—Z04 由服务端确定性生成，位置未知就「待定位」 | `trigger()` 循环 1..4；不猜方位、不灌演示数据 |
| `subjectId` 不可变、`subjectCode` 工单内唯一 | `UNIQUE (work_order_id, subject_code)`；两张工单的 Z01 是不同主体 |
| 指派权只属于项目经理 | `allows(actor, "workorder:assign")`；不给「全权限」集合 |
| 按单职责授权 | `dutiesOf(orderId, accountId)`：负责人按岗位默认职责 + 成员勾选的职责 |
| 读全量 vs 只读摘要 | `detail(orderId, actorId)`：未指派时清空委托正文与随单附件（`restricted: true`） |
| 空值 ≠ 0 | `isBlank()` 先判空；数值只认 `typeof === "number" && Number.isFinite` |
| 大气压显式单位 | `pressure: { value, unit }`；`hPa/kPa/Pa` → hPa，原始值与单位一起留档；不默认 1013.25 |
| 测量时间时钟 | 不得晚于服务端时间 60 秒以上 |
| 校验通过 ≠ 设备收到 | 通过只生成不可变 `configVersion`；`accepted` 与 `executed` 分开 |
| 改读数必须重校验 | `needs_revalidate`；旧版本不可原地改，也不能借它下发 |
| 换人 / 归档让旧包失效 | `supersedeDispatches()`；设备已应用的包保留历史 |
| 回执要对得上 | 设备 ID、包 ID、工单修订、指派修订、配置版本逐项比对，不符不推进 |
| 幂等 | 触发按事件 ID、下发按 `idempotencyKey`、事件按 `messageId` |
| 删除是级联硬删 | `deleteOrder()`：同一事务里删主体 / 指派 / 环境草稿与版本 / 下发包与回执 / 日志；**不按岗位设限**（产品口径 2026-09-14），破坏性由界面二次确认兜；设备之后再取已删包会拿到 404，不会应用一张已删除的工单 |

工单状态：`待指派 / 待准备 / 待作业 / 作业中 / 待验收 / 已归档 / 已暂停`
下发状态：`none(待下发) / queued / sent / accepted / executed / failed / expired / superseded`

| 方法 | 路径 | 谁用 | 说明 |
|---|---|---|---|
| POST | `/api/work-orders/trigger` | 页面（快捷键） | 事件 ID 幂等；返回工单 + 详情 |
| GET | `/api/work-orders?filter=&q=` | 页面 | 列表（`all/assign/active/archived`）+ 筛选 + 单号搜索 |
| GET | `/api/work-orders/{id}` | 页面 | 详情 + 当前账号能力 + 指派候选 + 可下发目标 |
| PUT | `/api/work-orders/{id}/assignment` | 项目经理 | 指派 / 调整；带 `expectedRevision`，冲突 409 |
| POST | `/api/work-orders/{id}/status` | 项目经理 | `start/submit/accept/archive/pause/resume` |
| PUT | `/api/work-orders/{id}/environment-draft` | 被指派（环境录入职责） | 保存草稿（允许不完整） |
| POST | `/api/work-orders/{id}/environment/validate` | 项目经理 | 校验并生成不可变配置版本 |
| POST | `/api/work-orders/{id}/dispatches` | 被指派（下发职责）/ 项目经理 | 生成整包 + 命令；幂等键去重 |

| GET | `/api/devices/{id}/work-order-bundles/pending` | 终端 / 页面 | 只返回下发给这台设备且仍有效的包 |
| GET | `/api/work-order-bundles/{bundleId}` | 终端（设备令牌） | **固化字节**下载，附 `x-bundle-sha256` |

### 4.1 下发给终端的 `assign_task`

`args` = 终端工单页九项（`orderId / scheduledAt / site / createdAt / assignee / department / scope / risk / rescanPlan`）
+ 作业绑定（`componentIds`、`subjectIds`、`round`、`configVersion`、`modelVersion`、`taskRevision`）
+ 整包引用（`bundleId`、`bundleUrl`、`bundleSha256`）。

- `assignee` 与 `department` 都给**岗位**（例如「全栈开发工程师」）。本平台没有部门实体，
  PRD §5.2 要求「责任部门」这一格按岗位口径显示，所以两格同源，不是笔误。
- `risk` 给「未评估（本单为现场检测委托，无来源风险结论）」；`rescanPlan` 给「未生成」。
  新单没有来源风险，也不把历史演示结论灌进来。
- `site` 截到 20 字（终端那一格宽度有限）。

### 4.2 整包

`schemaVersion: "work-order-bundle/1.0"`，字段与 PRD §9.2 示例一致：
`bundleId / deviceId / workOrder{...subjects, responsible, requirementsText} / environment{...} / issuedAt / expiresAt`。
摘要算的是**响应体字节**（`GET /api/work-order-bundles/{bundleId}` 原样返回，平台不重新序列化）。

## 6 真机联调记录（2026-09-14，Pi 5 `handheld-02` 在线）

跑通了一次真实的「下发 → 接收 → 应用」：

```
平台下发 BND-20260914-0004（配置版本 CFG-WO-20260914-0001-003）
  → 终端 command.accepted   05:55:19Z
  → 终端 command.executed   05:55:19Z
  → 平台：扫描仪已应用；工单状态 待准备 → 待作业
```

联调过程抓到两个平台侧的真问题，都已修并进了回归：

1. **命令参数层级错位**：接口清单 §4.1 写业务字段放 `payload.args`，而终端
   `woodpulse/app.py::_cmd_assign_task` 读的是 `command["payload"]`
   （平台 WS 信封 payload 里再嵌一层的 `payload`）。只发 `args` 时真机回
   `command.failed / code = missing_order_id` —— 平台这边看着「命令已发出」，
   设备一个字都没绑上。现在两个键给同一份内容（`device-gateway.issueCommand`
   新增 `body`，落在信封 `payload.payload`），终端不用改一行。
2. **「原样再存一次」被误判成改动**：草稿里存的是录入的原样时间串
   （`2026-09-14T05:52`），配置版本里存的是解析后的 ISO（`…T05:52:00.000Z`），
   直接比字符串会把没改动的保存判成「需重新校验」，工单从此发不出旧版本。
   现在比较前先归一化测量时间。

终端的**整包下载与摘要校验**还没做（设备侧目前按 `assign_task` 的九项信息绑单，
忽略 `bundleId`/`bundleSha256`）；等终端实现后即可按 PRD §9.3 走验包链路。

## 7 没做 / 边界（说清楚，不含糊）

1. 真机联调只覆盖了「下发 → 接收 → 应用」这条主链（见上一节）；终端的包下载、
   摘要校验、断网重传回执尚未在真机上验过。Pi 不在线时命令会停在 `queued`
   （这是设计行为，不是故障）。
2. **「引用实时读数」没做**（PRD §7.2 列为可选）：环境读数目前只有手工录入，不提供从设备
   传感器快照复制进本单的入口。
2.1 **不再要求选择仪表**（产品负责人 2026-09-14 口径）：录入界面只填四项读数、单位、位置与时间；
   服务端在没挂仪表时按**缺省量程**判边界（越界值照样拦），整包的 `instruments` 会是空数组。
   仪表台账与「按仪表判定量程」的服务端能力保留，接口也仍接受 `instruments`。
3. **整包下载的验签在设备侧**：平台只负责固化字节 + 给摘要；设备要按摘要校验后再原子应用。
4. **PRD §9.4 的手持端页面**（工单页、环境记录页、1024×600 布局）在终端仓库，不在本仓库。
5. **老工单没有迁移**：`seed/scenario.ts` 里的当前工单、草稿与历史工单仍走浏览器
   种子数据与共享会话的配置流程（总览页、地图点位、小木回答都在引用它们）。PRD §10 也要求
   「历史演示工单保留原值及来源标记」。
6. **指派后旧人员的历史归属**只保证记录里保留原岗位；跨端的细粒度审计导出不在本期。
7. **删除不可恢复**：没有软删与回收站；设备侧已经应用过的工单副本平台收不回
   （确认框里会写明这一条）。
8. 上传字节落在 `server/assets/uploads/`，`GET /api/batches` 只做台账；产物回收（清理未完成的
   上传单与字节）还没做，需要时从这里接。

# 权限变更 · 史（shi）全量开放

版本：v1.0　日期：2026-09-28　影响面：账号权限（前端置灰 + 服务端闸门）

**一句话**：人工智能架构师（史）的权限从"除指派权与模型上传外全给"改为**全量**——
工单指派、场景模型上传与成果提交全部可用；沈保留项目经理口径不动，饶 / 马的权限一条没加。

---

## 1 用户口径（原文）

> 「把我，shi的权限完全开放，所有功能都能直接用」

变更前史**刻意不给**的三条，本次全部授予（用户已确认 PRD 冲突由业务方承担）：

| 权限码 | 对应功能 | 变更前 | 变更后 |
|---|---|---|---|
| `workorder:assign` | 工单「指派/更换负责人、参与人员与职责」（含换人） | 只有沈 | 沈 + **史** |
| `scene:submit` | 场景成果提交（`POST /api/files?dir=scenes` 的字节闸门 + `scene.submit`） | 只有饶 | 饶 + **史** |
| `scene:upload` | 孪生页「上传/替换模型文件」按钮（前端判据） | 只有饶 | 饶 + **史** |

## 2 覆盖的 PRD 条款（明示，不是漏改）

- `docs/PRD-工单指派与扫描仪下发-v1.0.md` §6.2 L191：
  「人工智能架构师、管理员或小木智能体不能因为现有『全权限』集合而获得指派权」。
  —— 本次是**用户当面拍板的口径变更**，覆盖该条；`workorder:assign` 仍然是
  "显式授予的独立权限码"，没有塞进 `ACTION_PERMISSION`（不让它被 `ALL` 自动继承）。
- `docs/审剧本-第二章4.1逐句对照表.md` 第 13 行（史「已收到指派授权」）与
  `docs/审剧本-平台官方口径基准-v1.0.md`（"指派仅项目经理"）保持原样：
  剧本台词没改，只是平台侧现在也允许史操作指派。

## 4 没动的部分（防止误读为"全都放开"）

- **沈**：仍是"除场景模型上传外全量"（上传高斯模型是全栈开发工程师的活）。
- **饶**：`env:ack` / `scan:capture` / `data:upload` / `scene:submit` / `scene:upload` /
  `deployment:receive` / `sample:review` / `training:submit` / `knowledge:read|search|manage`；
  没有 `workorder:assign`、没有 `workorder:operate`，环境草稿与校验仍 403。
- **马**：只读知识中心 + 建图巡检本职；没有指派权、没有场景上传权。
- **`scene.keyframe.*` / `projection.*`**：本来就是 `"*"`（任意已登录账号），未改。
- **依赖按单职责的动作**（如"下发扫描仪" `canDispatch`）：仍要求被指派且具备该职责 ——
  史没有被指派时按钮不亮、接口也会拒，这是**设计如此**，与本次权限无关。

## 6 回退（一条命令级别）

1. `server/services/permissions.mjs`：把 `shi` 里的 `...WORK_ORDER_PERMISSIONS` 换成
   `"workorder:operate"`，并把 `...ALL` 换成 `...ALL_BUT_UPLOAD`。
2. `src/pages/MumaiDashboard/auth.ts`：把 `shi: ALL_PERMISSIONS` 换回
   `ALL_PERMISSIONS.filter((item) => item !== "scene:submit" && item !== "scene:upload")`。
3. 重启 8000（`node 服务管理.mjs restart`）+ `npm run build`。

## 追加更新：手持终端（树莓派 Pi 5）接入平台

**背景**：终端侧（`woodpulse`）早已实现上行接口，平台的 34 条路由里却一条设备路由都没有 ——
终端日志里是 `设备注册失败：没有这个接口：POST /api/devices/register`，硬件页四块只能用种子。
本次把收侧补齐，并顺手把页面与顶栏上"看着像状态、其实是固定值"的地方换掉。

### 设备网关（平台侧新能力）

- 新增 `server/services/device-gateway.mjs`：设备台账、令牌校验、设备数据存取与保留窗口、
  事件按 `messageId` 去重、命令下发与三态回执、现场调参回写、低帧率预览帧、
  `/ws/devices/{id}` 设备通道；表在本模块内建，不动 `db.mjs` 的全局 SCHEMA。
- 新增 11 条路由：注册握手（回 `platformTime`，终端拿它算时钟偏差）、设备数据收发与历史、
  事件批量（`accepted` / `duplicated` 是 **messageId 数组**）、命令下发、配置 ack、预览帧、设备台账。
- 心跳（5 秒）与遥测（1 秒）不入事件表，只留最新一份 —— 否则会把采集、批次、回执这些
  真正要留痕的事件冲掉（保留窗口只有几百条）。
- 浏览器 `/ws` 与设备 `/ws/devices/{id}` 共用 8000 端口：upgrade 改由 `index.mjs` 统一分发
  （原来 `ws` 对不匹配路径会直接回 400 并销毁连接，设备通道排不上队）。浏览器通道行为不变。
- 修一处隐患：`http.mjs` 的路由表原是模块级，同进程起第二个服务时新请求会命中上一个
  已关闭实例的处理器（表现为 `database is not open`）。

### 硬件监看接真机（`#/hardware?tab=monitor`）

- 设备状态 / 设备读数 / 通道状态 / 采集接收四块改接终端上报，**种子保留为兜底**：
  一份都没推过时整块退回种子并在顶部写明原因；设备掉线时保留最后一份真机数据并标「离线」。
- 逐条读数标来源（实测 / 推算 / 估算）；没有电量计就没有「电池电量」这一行且写明原因；
  `map` / `pose` 保留四行「断开 + 原因」；毫米波响应序列恒标回放，不因机型含「毫米波」变实采。
- 新增四块终端能给、平台原来没有的内容：**能力声明**、**终端遥测**、**设备事件与命令回执**
  （accepted 与 executed 分开显示，不把「已下发」当「已执行」）、**低帧率设备预览**
  （明确标注不是归档图像）。
- 采集接收：真实批次带构件 / 测区 / 配置 / 模型 / 帧数 / 数据集摘要；预期为 0 的通道按终端的
  `state` 判定，不再一律显示「0/0 100%」；真机在线时「补传」会下发 `request_upload`。

### 顶栏状态区

- 原来是四路通道（地图 / 位姿 / 视频 / 车辆）加种子里的固定时间戳，右边还接一串机型文字；
  整条宽到 1500px 左右就压住左侧导航。现在换成四格真实状态：
  **平台**（共享服务通道）、**智能车**（当前任务状态）、**扫描仪**（终端链路：真机在线 /
  延迟 Ns / 离线 Ns / 未接入）、**模型**（当前演示模型版本）。
- 时间与来源挪进悬停说明；右上角写死的「设备在线 4/4」改为按同四格现算的「状态正常 N/4」；
  状态区加宽度上限，1280 / 1500 / 1556 / 1920 四个宽度实测不再与导航叠字。

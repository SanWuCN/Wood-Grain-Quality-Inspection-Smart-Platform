## 1 背景与目标

### 1.1 背景

平台现有实现中，**前半段（设备上行、分片上传、批次清单摘要校验、归档校验、产物下载回验、工单整包下发）是真实链路**；**后半段（清洗 → 划分 → 训练 → 对比 → 量化 → 更新）为前端仿真**。同时，出于工程诚实性考虑，界面上保留了大量「演示记录」「批次回放」「模拟采集」「预设标注演示」「演示资产，不可烧录」等**面向开发者的来源标识**。

这些标识与 4.2 剧本的台词**直接冲突**：台词按正常业务流程叙述，屏幕却标注"这是演示"。演出时会被质疑，且需要在剧本里写大量"说明这是演示"的补丁。

### 1.2 改造目标

> **平台侧消除矛盾，剧本侧保持干净。**

两条主线：

1. **去演示化**：把**给评委看的**演示/回放/样例/不可烧录类字样去掉或改为中性业务词；**给开发看的**代码注释与内部字段一律保留。
2. **把"假"做得像在真算**：对确属仿真的环节（训练、量化、标注、更新进度），补上**过程动画、进度、阶段文案、版本前后变化**，让"过程"可看、"结果"可信。

### 1.3 明确不做（Out of Scope）

| 不做项 | 原因 |
|---|---|
| 真实模型训练服务 | 周期长、现场时间不允许，PRD 已列为 P1 |
| 真实 INT8 量化与算子转换 | 同上 |
| 真实固件刷写（串口/IAP/烧录器调用） | 现场无该硬件通路；改为**终端执行 + 进度条**表现 |
| 图像标注编辑器与标注接口 | 成本高，本期用动效呈现已有标注结果 |
| 三维场景坐标级标定 | 需现场标定，本期只做**构件编号级关联 + 锚点打点** |
| 复巡计划的创建与下发后端 | 本期只做**引用既有计划** |

### PR-02　交付页「提交/发布」接通后端　【P0】

**现状**
`pages/DeliveryCenter.tsx:249-265` 的 `submit()` 仅 `setArtifacts` + `pushEvent` + `toast`，**无网络请求**；后端 `artifact.publish` / `artifact.build` handler（`server/services/workflow.mjs:403,432`）与权限（`server/services/permissions.mjs:37-38`）**已就绪但未被调用**。现象：产物从"待提交"消失、不进"已发布"表、**刷新即复原**、其他账号不可见。

**需求**
1. `submit()` 改为调用已存在的 `artifact.publish` 动作（沿用平台既有动作总线与 `entities` 机制）。
2. 提交成功后：产物进入「已发布产物」列表，`state` 由 `checked` 推进到 `已发布`，**刷新与切页后不丢失**。
3. 提交失败：保留在「待提交」，`toast` 显示失败原因，可重试。
4. 提交前校验不通过的产物**不提供提交入口**（维持现状）。
5. 跨账号可见：史发布的产物，饶登录后能在「已发布产物」中看到并下载。

**接口（已存在，无需新增）**

```
动作：artifact.publish     权限：package:deliver
下载：GET /api/files/{id}/download   （返回真实字节 + Content-Disposition）
```

**验收标准**

| # | 验收项 | 通过判据 |
|---|---|---|
| B1 | 提交落库 | 提交后 `GET` 已发布产物列表包含该产物；`server/data/mumai.db` 的 `entities` 表新增/更新对应记录 |
| B2 | 刷新不丢 | 提交后按 F5 刷新页面，产物仍在「已发布产物」 |
| B3 | 跨账号可见 | 切换账号到「全栈开发工程师」，「已发布产物」中可见并**可下载**；下载文件字节数与 SHA-256 与源文件一致 |
| B4 | 失败可恢复 | 断网状态下提交，提示失败且产物仍在「待提交」；恢复网络后重试成功 |
| B5 | 权限校验 | 无 `package:deliver` 权限的账号看不到提交入口；直接调用动作返回 403 |
| B6 | 取用记录 | 下载后「取用 N 次」计数 +1，切页返回不回退 |

### PR-04　更新/写入过程可视化与版本前后变化　【P0】

**现状**
手持终端更新流程（接收→下载→摘要检查→切换版本→回验）已有阶段划分，但**过程短暂、无可视进度**；服务端演示包体量仅 **8 KB**、文件名 `demo-model.bin`，明显失真。

**需求**
1. **进度可视化**：终端更新界面提供阶段列表 + 进度百分比 + 已用时，阶段为
   `校验包摘要 → 擦除 → 写入 → 校验 → 重启 → 读回版本`，**总时长 30–60 秒**可配置。
2. **版本前后变化**：写入前显示 `v1.4.1 / DEMO-M02`，写入后读回 `v1.4.2 / DEMO-M02b`，**两者必须不同**并在界面同屏留痕。
3. **包体量与命名**：替换现有演示资产，要求
   - 文件名形如 `DEMO-M02b-mumai-scanner-v1.4.2.bin`；
   - 体量 **≥ 5 MB**（模型包量级）；
   - 含 `manifest.json`、模型说明、预处理配置、示例验证结果、`sha256`、版本号；
   - 校验项 `flashable` 不再作为**页面文案**展示（内部字段保留）。
4. **写入期间不弹出任何"演示/不可烧录"提示**。
5. 写入期间保持设备连接；流程结束后才允许断开。

**验收标准**

| # | 验收项 | 通过判据 |
|---|---|---|
| D1 | 进度可见 | 更新过程中界面显示 6 个阶段名 + 百分比，百分比单调递增 |
| D2 | 时长可控 | 从开始写入到读回版本的总时长在 30–60 秒之间（配置文件可调） |
| D3 | 版本变化 | 写入前版本 ≠ 写入后版本，且两个值同屏可见 |
| D4 | 包体量 | 平台侧该产物文件 ≥ 5 MB；文件名符合命名规范；`manifest.json` 字段齐全 |
| D5 | 摘要一致 | 终端本机重算的 SHA-256 与平台下发的 `sha256` 一致 |
| D6 | 无演示字样 | 更新全流程（含提示、日志、进度文案）不出现「演示」「不可烧录」「占位」 |
| D7 | 失败可分阶段定位 | 人为中断（拔网线）后，界面停在失败阶段并给出原因，不继续播放后续阶段 |

### PR-07　图像标注动效　【P1】

**现状**
融合分析页标注为 **3 条只读静态数据**，页面标注「预设标注演示」，标注框不可交互。

**需求**
1. **过程动效**：进入分析时，逐张图像滑过 → 标注框逐个落下（含 200–400 ms 淡入）→ 置信度数字滚动到位。总时长 4–8 秒。
2. **可交互**：点击任一标注框**打开对应原图**（原图查看为已有真实能力），并高亮该框。
3. **文案中性化**：区块标题改为「分析结果」；不出现「预设」「演示」。
4. 标注数据仍为静态 JSON（本期不做编辑器）。

**验收标准**

| # | 验收项 | 通过判据 |
|---|---|---|
| G1 | 有过程 | 进入分析后逐个出现标注框，非一次性全量渲染 |

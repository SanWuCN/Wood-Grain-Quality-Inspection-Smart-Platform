# 手持终端（树莓派 Pi 5）接入与验收

**一句话**：硬件详情 →「硬件监看」那一屏原来全是种子数据；现在终端每 2 秒把
设备数据推上来，页面直接显示**这一台机器**的读数、通道与批次，终端连不上时
退回种子并在页面顶部写明原因。

契约以终端侧两份文档为准（`手持扫描仪/docs/`）：

| 文档 | 管什么 |
|---|---|
| `平台接入实施说明.md` | 握手、心跳、事件、命令、上传 |
| `设备数据接口说明.md` | 硬件页四块：设备状态 / 设备读数 / 通道状态 / 采集接收 |

平台侧实现的是这两份文档的**收侧**：终端不用改一行代码。

## 2 把树莓派接上来

Pi 侧只改一个文件（`/var/lib/woodpulse/config.json`）：

```jsonc
{
  "platform": {
    "platform_url": "http://<平台主机局域网 IP>:8000",
    "device_id": "handheld-02",
    "device_token": "demo-token",     // 与平台侧 MUMAI_DEVICE_TOKENS 一致
    "demo_session_id": "demo-01"
  }
}
```

```bash
sudo systemctl restart woodpulse        # 注册握手只在开机时做一次，必须重启
curl -s http://<平台主机 IP>:8000/api/health   # 看 devices.online 是不是 1
```

平台侧默认令牌就是 `demo-token`（与终端出厂配置一致）。要改：

```bash
MUMAI_DEVICE_TOKENS="handheld-02:换成这个,another-dev:另一个" node server/index.mjs --static dist
```

只有令牌（没有 `deviceId:` 前缀）表示任意设备可用；`MUMAI_CONFIG_VERSION` 可改
注册响应里回的配置版本（默认 `CFG-02`）。

> ⚠️ **必须重启终端**：注册握手（`POST /api/devices/register`）只在终端进程启动时
> 调一次，之后它只重连 WebSocket。不重启的话设备数据、遥测、事件、命令都通，
> 但 `versions.config`、`readings.clock`（时钟偏差，需要注册响应里的 `platformTime`）
> 与台账里的 `appVersion` 会缺 —— 这是终端的设计，平台不替它编。

## 3 平台侧提供的接口

设备上行带 `X-Device-Token`；页面读取走登录令牌（同一条路由两种身份都认）。

| 方法 | 路径 | 谁用 | 说明 |
|---|---|---|---|
| POST | `/api/devices/register` | 终端 | 握手；回 `platformTime` / `heartbeatIntervalMs` / `offlineAfterMs` / `configVersion` / `pendingCommandCount` |
| POST | `/api/devices/{id}/hardware` | 终端 | 设备数据（每 2 秒一份），保留最近 300 份 |
| GET | `/api/devices/{id}/hardware` | 页面 | 最后一次上报 + 平台算的链路状态（`link` / `stale` / `ageSec` / `telemetry` / `lastEvent` / `configAck` / `recentCommands`） |
| GET | `/api/devices/{id}/history` | 页面 | 读数历史（趋势、CSV 用） |
| GET | `/api/devices/{id}/events` | 页面 | 最近关键事件（心跳与遥测不入库，避免冲掉留痕） |
| POST | `/api/device-events/batch` | 终端 | `accepted` / `duplicated` 是 **messageId 数组**，`rejected` 带 `retryable` |
| POST | `/api/devices/{id}/commands` | 页面 | 命令下发（白名单：`assign_task` / `apply_config` / `pause_capture` / `request_upload` / `prepare_update` / `query_status`） |
| POST | `/api/configs/{version}/ack` | 终端 | 现场调参回写（`state = local-tuned`） |
| POST | `/api/devices/{id}/preview` | 终端 | 低帧率预览帧（JPEG 直传，内存环形保留 12 帧） |
| GET | `/api/devices/{id}/preview/latest` | 页面 | 最新一帧（`image/jpeg`，无帧时 404） |
| GET | `/api/devices` | 页面 | 设备台账（在线/离线、能力、待执行命令数） |
| WS | `/ws/devices/{id}?deviceToken=…` | 终端 | 平台→设备命令、设备→平台心跳/遥测/事件；令牌不对直接拒绝升级 |

**平台自己的在线判定**（与终端各算一份，不冲突）：最近一次上报 ≤ 6 秒 = 在线、
6—15 秒 = 延迟、> 15 秒 = 离线；设备掉线时最后一份数据**保留**，页面标「离线」
而不是清空或回退成种子。

## 4 页面显示口径

- **来源要能一眼看出来**：每一条读数带「实测 / 推算 / 估算」标记（终端的
  `readings[].source`），种子兜底时整块挂「模拟采集」；
- **没有的就是没有**：终端没有电量计，不下发「电池电量」，页面也不补默认值 ——
  这一行直接不出现，并写明原因；
- **`radar` 恒为回放**：能力声明里写清「响应序列来自预制样例包」，不因为板上写着
  「毫米波」就显示成实采；
- **`map` / `pose` 保留四行**：手持端只拥有视频一路，另外三路按终端原话显示
  「断开 + 原因」，不隐藏；
- **连接两个口径都写**：平台按上报断流判定，终端按它自己的 WS/心跳判定；两者不一致
  时都显示出来，不互相盖掉；
- **判定仍在页面现算**：阈值随数据一起来（种子与真机同一套 `readingState`），
  改读数结论跟着变。

## 5 验收

```bash
node --test tools/test-device-gateway.mjs     # 契约回归（无需真机）
node tools/preflight.mjs                      # 启动预检
```

对照终端文档 §4 的验收要点，逐条在页面上核：

- [x] 设备断电/停终端 6 秒内读数与 `video` 通道标 `stale`，15 秒标 `offline`，
      其它通道与页面不受影响；
- [x] `readings[].source == "estimated"` 的项在页面上有「估算」标记；
- [x] 页面不出现「电池电量」那一行（并写明本机没有电量计）；
- [x] `radar` 仍标为回放/样例，不因 `hardware.model` 含「毫米波」而变成实采；
- [x] `map` / `pose` 两行显示 `offline` + 原因；
- [x] 终端还没上报过时页面显示「等待设备上报」并退回种子（URL 加 `?device=xxx`
      可以立刻复现这个分支）；
- [x] 平台下发 `query_status` → 终端回 `accepted` → `executed`，页面的
      「设备事件与回执」按三态显示，`accepted` 不当作已完成。

实机实测（2026-09-13，Pi 5 `SANWU` @ 192.168.31.60）：设备数据每 2 秒到达、
遥测每 1 秒到达、`query_status` 往返约 190 ms（accepted 与 executed 相差 2 ms）。

## 6 还没接的部分（说清楚，不含糊）

1. **文件交付**：终端的 `POST /api/files/uploads` 三步上传、`POST /api/batches`
   批次清单平台侧还没实现，所以「采集接收」的计数会是 0（批次本身已在终端封存）。
   要接的话按终端文档 §3.7 / §3.8 落；
2. **命令白名单里的 `prepare_update` / `apply_config`** 平台侧只负责下发与记录回执，
   更新包与配置下发的业务流程走平台既有的固件与配置页；
3. **采集作业 / 异常排查两个页签**仍是演示工作台（批次与波形来自种子）；
   真机的批次已经出现在「硬件监看 → 采集接收」里；
4. **预览图**只在「硬件监看」显示，不写盘、不入归档（终端也明确它不是归档图像）。

## 7 实测发现的两条终端侧现象（供终端同学参考）

1. **终端自述连接状态卡在「离线」**：平台侧 `WS 已建立 / 心跳正常 / 命令往返正常`，
   但设备数据里的 `state.connection` 仍是 `offline`（`platformDetail` 写着「心跳正常」）。
   终端的连接状态机 `ConnectionMachine` 不允许 `OFFLINE → ONLINE` 直接迁移，
   而开机时平台还没实现设备网关（注册 404），状态停在 OFFLINE 之后，
   后续 WS 连上时的 ONLINE 迁移被 `to()` 静默拒绝（返回 False）。重启终端即恢复；
   建议终端侧在 `_connect()` 成功后按 `CONNECTING → ONLINE` 显式走一步。
2. **机身温度阈值 55℃ 对 Pi 5 偏紧**：实机 `temp = 70.8℃` 在页面上被判成「超出上限」。
   Pi 5 的 SoC 在正常负载下 60—80℃ 属常见，降频线在 80—85℃；
   这个阈值来自终端的读数定义，平台照原样判定，是否放宽由终端侧决定。

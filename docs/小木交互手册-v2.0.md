## 0. 一分钟上手

1. 打开平台任意已登录页面，看**右下角**：小木的矢量形象常驻在那里（默认待机，形象下方徽标写「待机」）。
   - 形象尺寸 120px；短屏（视口高 ≤820px）收一档到 72px（`src/pages/MumaiDashboard/agent/xiaomuDock.css:88`、`:880`）。
2. 第一次用，先开**常驻唤醒**（三处入口任选其一，见 §1.1、§2.5）：气泡底部「**开启常驻唤醒**」、右侧小木助手面板头部的「**常驻唤醒**」、或快捷键 **Alt+W**。浏览器弹麦克风授权时选「允许」。
3. 对着麦克风说 **「小木小木」**（必须**连说两遍**），**停 0.3–1.5 秒**，再说命令，例如「**查近三个月天气**」。
4. 右下角气泡弹出：先出现你说的字（状态「正在听」），回答出来后会播报一次；气泡里有主回答、可折叠的「业务状态」「资料引用」、本轮时间与「重播（Alt+R）」。
5. 不想听了：按 **Esc**（停播报并收起气泡）。不想让它继续听：点气泡里的「**常驻唤醒：已开**」把它关掉（**关气泡不等于关麦克风**，见 §2.5）。

> 记不住能说什么：29 条能听懂的话全在 §3 的核心表里，文本直接取自生成文件，不是手抄。

## 1. 四个入口

小木有四个用户可见的入口。**四条路最终都调同一个 `ask()`**（`src/pages/MumaiDashboard/agent/executor.ts:551`），
所以业务结果一致（页面跳转、二次确认、工具日志都不会被绕过）；差别只在**怎么触发**和**界面落在哪里**。

| # | 入口（用户看到的名字） | 代码实体 | 怎么打开 / 怎么触发 | 界面落在哪 | 会用语音回答吗 |
| - | --- | --- | --- | --- | --- |
| 1 | **常驻语音唤醒** | `XiaomuDock`（右下角气泡）+ `WakeChannel`（`wakeChannel.ts`） | 开常驻唤醒后说「小木小木」两遍、停 0.3–1.5s、说命令；或 `?wake=1` | 右下角**气泡**（主页面不被遮挡） | 会（`VoiceOutput`，`XiaomuDock.tsx:95-115`） |
| 2 | **语音控制台** | `VoiceConsole.tsx`（`aria-label="小木语音智能体"`，`:601`） | 小木助手面板头部的「**语音**」按钮（`SmallWoodPanel.tsx:478`）；高风险意图自动转交（`:386`）；或程序化 `openAgent()`（`api.tsx:26-28`） | **全屏模态**（`.vc-root`，`z-index:90`） | 会 |
| 3 | **文字助手** | `SmallWoodPanel.tsx`（`aria-label="小木助手"`，`:443`） | 点右下角「**小木**」浮标（`Shell.tsx:492-512`，`aria-label="小木助手"`） | 右侧抽屉面板（`.xm`） | **不会**——面板里 `speak: () => {}`（`SmallWoodPanel.tsx:245`） |
| 4 | **键盘** | `XiaomuDock` 的全局 keydown | **Esc / Alt+W / Alt+E / Alt+R / Alt+M**（`XiaomuDock.tsx:248-329`） | 作用于入口 1 的气泡 | Esc 会停播报 |

四个入口的名字与代码的对应关系：

- 「**常驻语音唤醒**」= 代码里的**常驻唤醒开关**：气泡底部按钮文案是「开启常驻唤醒」/「常驻唤醒：已开」（`XiaomuDock.tsx:551`），
  助手面板头部同一个开关的文案是「常驻唤醒」/「唤醒中」/「启动中」（`SmallWoodPanel.tsx:473`）。
- 「**语音控制台**」在界面上的按钮只写「**语音**」（`SmallWoodPanel.tsx:485`），它的标题是「小木 · 语音智能体」（`VoiceConsole.tsx:608`）。
  它是**一层全屏模态**，`z-index` 高于右下角气泡（气泡 80、控制台根 `.vc-root` 90，`xiaomuDock.css:57`、`:46-56`），
  且代码注释里写明它现在是「**开发诊断入口**」（`wakeChannel.ts:648-652`、`VoiceConsole.tsx:413-427`）。
- 「**文字助手**」= `SmallWoodPanel`，界面上叫「**小木助手**」（`SmallWoodPanel.tsx:455`、`Shell.tsx:496`）。**本手册沿用「文字助手」这个叫法**，代码里没有名为 `文字助手` 的符号。

### 1.1 入口 1：常驻语音唤醒（默认交互面）

- **它是什么**：`wakeChannel.ts` 用 AudioWorklet 采 16 kHz 单声道 PCM，100 ms 一片推给**同源** `/voice-wake` 常驻 WebSocket
  （`wakeChannel.ts:26`、`:59-60`、`:553-557`）；唤醒与命令识别在语音边车侧完成，前端只负责送达与呈现（`wakeChannel.ts:1-22`）。
- **唤醒后落到哪里**：派发的是 `mumai:xiaomu-ask` 事件 —— **右下角气泡直接跑，主页面不被遮挡**；
  全屏的 `mumai:agent-open` 只保留给诊断控制台与高风险转交（`wakeChannel.ts:645-656`、`XiaomuDock.tsx:119-126`）。
- **代价与前提**：需要本机另起语音边车（Python 服务 127.0.0.1:8770 + Node 桥 127.0.0.1:8780）。不跑边车时唤醒通道会一直重连，
  右下角状态进入「出错了」，**不影响页面其它功能**（`docs/语音唤醒接入-v1.0.md:42-48`；`degrade.ts:289-304`）。

### 1.2 入口 2：语音控制台（全屏诊断台）

它有普通气泡没有的东西，所以验收时常用它（`VoiceConsole.tsx`）：

- 状态机徽标 + **真实麦克风电平条**与声波动画（`:606-627`）；
- 实时字幕分区：partial 灰、final 高亮，并显示 ASR 通道、置信阈值、`RETRIEVAL_NOTE`、语音输出通道（`:651-672`）；
- **按住说话**按钮（`:736-752`，双击 = 脚本化演示一次）、文本输入框（`:758-764`）、示例问句按钮（`:721-733`）；
- **工具调用明细**与多步任务的 ✓/●/○ 步骤清单（`:139-210`）；
- 「语音开/关」「清空对话」「✕ 关闭」（`:629-647`）；Esc 关闭（`:520-529`）。

⚠ 一个必须说清的区别：**控制台的「按住说话」走浏览器 `SpeechRecognition`（Chromium 是 `webkitSpeechRecognition`，`asr.ts:7-8`、`:138-141`、`:440`），
这条路的音频可能被浏览器送到云端；而唤醒那条链路是全本地的**（`docs/语音唤醒接入-v1.0.md:146-150`）。两者不是同一条识别通道。

### 1.3 入口 3：文字助手（不播报）

- 打开方式：点右下角「小木」浮标（`Shell.tsx:492-513`），浮标带 `aria-expanded`（`:497`）。
- 输入方式：面板底部的快捷问法按钮（取意图目录前四条，`SmallWoodPanel.tsx:440`、`:609-615`）＋输入框表单（`:617-624`）。
- **它不播报**：`speak` 是空函数，「屏幕上已经把答案写出来了，再念一遍是噪音」（`SmallWoodPanel.tsx:244-245`）。
- **需要二次确认的工具不在面板里执行**，而是转交语音控制台并如实说明「已在语音控制台打开待确认」（`SmallWoodPanel.tsx:371-398`）。
- 面板里也有常驻唤醒开关与「语音」按钮（`SmallWoodPanel.tsx:461-486`）。

### 1.4 入口 4：键盘

见 §7。要点：**只有 Esc 是单键**，其余都是 `Alt+字母`，且**与焦点无关**（在输入框里也生效，`XiaomuDock.tsx:287-301`）。

## 2. 唤醒规则

### 2.1 怎么说（用户侧动作）

1. **连说两遍「小木小木」** —— 单说一遍不会唤醒；
2. **停 0.3–1.5 秒**；
3. 再说命令，例如「查近三个月天气」。

这个节奏是 PRD FR-03 的要求，也是为什么服务端把「命令最长收集时间」从 8 秒提到 10 秒 ——
它**从唤醒那一刻起算**，要覆盖「1.5（最长停顿）+ 8（说话）+ 0.5（余量）」（`D:\平台\voice-module\service\server.py:437-445`）。
0.3 s 与 1.5 s 两个端点各有端到端实测证据（`docs/验收矩阵-v2.0.md:60` 的 A1-1d：停顿 0.3 s 通过、1.5 s 通过）。气泡底部的提示也写着同一句：
「两遍「小木小木」 → 停一下 → 说命令」（`XiaomuDock.tsx:553`）。

### 2.2 判定规则（服务端）

关键词用的是**两音节「小木」而不是四音节「小木小木」**：四音节召回只有 78.3%，扫遍
`num_trailing_blanks` / `max_active_paths` / `keywords_score` / `threshold` 都推不动 ——
两遍之间有停顿就匹配不成一个连续 token 序列；两音节召回 91.3%，代价是**单次呼名也必然报一次命中**（`server.py:1138-1141`）。

所以「必须两遍」由**两条分支**各自强制（`server.py:1143-1148`）：

| 分支 | 规则 | 实测 |
| --- | --- | --- |
| 1 | **1.5 秒窗口内 KWS 报 ≥2 次命中** → 直接唤醒 | 18/23 |
| 2 | 只报 1 次 → 取预滚段交 whisper 复核，转写**去标点后必须出现两次「小木」**才唤醒 | 3/5 通过 |
| 合计 | 两条分支都强制"两遍"（单次呼名在分支 2 会被拒掉） | **21/23 = 91.3%** |

相关常量（`server.py`）：`TWO_HIT_WINDOW_S = 1.5`（`:394`）、`REVIEW_DELAY_S = 0.5`（`:397`）、
复核取 `REVIEW_BEFORE_S = 1.2` / `REVIEW_AFTER_S = 0.6`（`:401-402`）、唤醒后冷却 `WAKE_COOLDOWN_MS = 1200`（`:447`，避免播报尾音又触发一次）。

**「1.5 秒内 ≥2 次命中」这个口径也是服务端 `ready` 帧自己声明的**：
`"rule": "必须两遍：窗口内 ≥2 次 KWS 命中，或单次命中经 whisper 复核确认两次"`（`server.py:1165`）。

唤醒之后前端还有两个配套动作（`wakeChannel.ts`）：

- 唤醒的那一刻就把 `collecting` 置真，界面**同一帧**切到「正在听」（`:593-609`），不必等流式字幕攒够音频；
- 命令交出去之后**暂停推流**（小木要说话，喇叭声会漏回麦克风），**2.5 秒后自动恢复聆听**（`RESUME_AFTER_COMMAND_MS = 2500`，`:73-86`、`:729-730`）；关闭气泡时**立即**恢复（`:838-841`）。

### 2.3 全本地，不外网

- 唤醒链路是：浏览器（本仓库）→ 同源 `/voice-wake` → Node 桥 `127.0.0.1:8780` → Python 服务 `127.0.0.1:8770`
  （`docs/语音唤醒接入-v1.0.md:29-40`）。
- WebSocket 地址用**同源相对路径**拼（https 页面自动走 wss），前端不判断环境（`wakeChannel.ts:555-557`）。
- 为什么不用浏览器自带识别做唤醒：`webkitSpeechRecognition` 在 Chromium 上会把音频送到云端，
  **断网就认不出任何东西**；唤醒要求"一直在听"，既不能依赖网络，也不该把常驻麦克风音频持续送出去
  （`docs/语音唤醒接入-v1.0.md:146-150`）。

### 2.5 「开启常驻唤醒」按钮在哪（三处 + 一个 URL 参数）

| 位置 | 文案 | 来源 |

**关气泡 ≠ 关麦克风**：只有显式点「关闭常驻唤醒」（或 Alt+W）才释放麦克风、断开 `/voice-wake`；

### 2.6 唤醒词不会被当成命令

服务端的命令段有时会把唤醒词一起带进来，前端在派发前会**剥掉开头连续两遍「小木」**（允许中间有 `，,、` 与空格），
**句中出现的小木不动**（`wakeChannel.ts:687-698`）：

```ts
const spoken = text.replace(/^\s*(?:小木[\s，,、]*){2}\s*/, "");
```

这一行是**唯一真源**：验收工装 `D:\平台\voice-module\tools\意图匹配桥.mjs` 在运行时会**读这一行**、从行内提取正则字面量后现场构造，
读不到就报错退出，不复制正则（`docs/验收报告-v2.0.md:186`、`:191-195`）。

### 4.2 播报优先级：预录音频 > 浏览器合成音 > 静默降级

`tts.ts` 的 `VoiceOutput.speak()` 就是这么走的（`tts.ts:1-23`、`:188-205`）：

1. **预录语音包**：调用方没显式给 URL 时，按**文本精确匹配**去语音包找（`audioUrlForText()`），命中且能加载（`probeAudio()`，1.2 s 兜底超时）就播音频文件（`tts.ts:199-203`、`:58-81`；`voicePack.ts:64-69`）；
2. **浏览器合成音**：没命中就回退 `speechSynthesis`（`lang=zh-CN`、`rate=1.05`，优先选 `localService` 的中文语音，`tts.ts:83-90`、`:265-311`）；
3. **静默降级**：`speechSynthesis` 不可用时**只显示字幕，不报错、不白屏**（`tts.ts:265-272`）。

两条播报路径（右下角气泡、全屏控制台）**共用同一个 `VoiceOutput` 实现**，
语音包 → 合成音 → 静默降级全部由它负责（`XiaomuDock.tsx:84-101`、`VoiceConsole.tsx:338-362`）。
匹配是**逐字**的：`voicePack.ts` 的 `normalize()` 只去掉首尾空白与所有空白字符（`voicePack.ts:29-32`），
**全角标点、`·`、`℃`、`（）`、`「」`都必须一致**，否则不命中（`public/voice/README.md:60-62`）。

两条路径都有**看门狗**：`speaking` 状态在 `onend`/`onerror` 都不来时按 `max(2500, 文本长度×260)` 毫秒兜底翻回 `false`
（`tts.ts:238-255`、`:292-309`），避免卡在"正在说话"导致麦克风再也不恢复。

### 4.3 明确边界（这四条请务必先读）

**边界 1：带参数的意图只覆盖「默认参数」那一版，换参数就回退合成音。**

生成文件是在**固定的一次渲染**里采样出来的（`stageKey=fusion`、账号 `沈 · 文物保护工程师`，见 `docs/语音播报文本清单-v1.0.md:6`），
所以录音里的槽位值就是那一轮的值。举三个具体例子：

- `open_page`：三种说法录的都是「任务总览」那版（`好的，正在打开任务总览。` / `任务总览已经打开。` / `正在跳转到任务总览。`）。
  说「打开地图」时主回答里的页面名变了（模板 `{pageLabel}`，`intents.ts:512`），**这一句不在 manifest 里 → 合成音**。
- `robot_move`：录的那版说的是 `Z04 金柱 Z04（P5 · Z04 观察点（避开手持作业区），1.6 m）`。
  说「让小车去一号木柱」时目标构件与观察点都变了（模板 `{targetLabel}`/`{waypointLabel}`，`intents.ts:624`）→ **合成音**。
- `robot_return_home` / `load_map` / `start_mapping` 一类：只有 `MAP-SH-06`、`起点 / 殿门`、`电池 91%` 这些**本轮演示值**被录过；
  装载别的地图版本、电量变化后 → **合成音**。

**边界 2：60 条里有 53 条本身就"随状态变化"。**

生成文件第二部分的 64 段带标记：**✅ 固定文案 7 段 / ⚠ 随状态变化 53 段 / ⛔ 空槽位 4 段**（逐条统计自 `docs/语音播报文本清单-v1.0.md` 第二部分）。
标记含义是官方给的：⚠ 表示"句子里含演示状态或数据取值，演示推进 / 数据变化后要重新取文本再录"（`docs/语音播报文本清单-v1.0.md:73-75`）。
按意图看，**只有 `open_page` 一个意图整组都是 ✅ 固定文案**，其余 26 个意图都含有 ⚠ 句子。
所以"演示状态一推进，录音就大面积失配、回退合成音"是**已知且已被生成文件预先标注**的行为，不是 bug。
`public/voice/候选键.json` 也用 `⚠ ` 前缀标出这些键，并说明前缀本身不是运行时键（`_标记` 条目）。

**边界 3：两个意图完全没有录音。**

`open_evidence`（打开 Z04 下部记录）与 `robot_patrol_route`（多步巡检任务编排）：说这两类话时**一定**是合成音。
原因不是漏录，而是生成时的句子里槽位是空的（`金柱 Z04（）的记录已打开…`、`已按你的说法生成执行计划：。路线为 ，…`），
属于 ⛔ 空槽位。要录这两条，必须**先在页面上实问一次**、用气泡里出现的整句替换后再合成（`docs/语音播报文本清单-v1.0.md:74-75`；`public/voice/README.md:44-46`）。

**边界 4：界面不会告诉你这一句走的是录音还是合成音。**

气泡页脚显示的是 `turn.voice`，它的值是 `voicePackOf(intent.id)` 产出的**意图目录标签**（形如 `AI语音7`），
是"这个意图声明了语音包"的意思，**不是实际播放通道**（`intents.ts:842-852`；`replyView.ts:135`；`executor.ts:222`、`:373`）。
要确认实际走哪条，用脚本或浏览器媒体事件（见 §9.3）：`验收语音包.mjs` 的判据是结尾必须 `audio=1 synth=0`，
`诊断-播报媒体时间线.mjs` 可以打印每个 `<audio>` 的完整媒体事件时间线（`public/voice/README.md:48-58`）。

## 5. 小木的状态与表情

### 5.1 七个状态与状态文字

界面状态**刻意不复用执行器的十个状态**（`PLANNING`/`WAITING_TOOL` 那些是执行器语义），而是"用户看得见的七种"
（`XiaomuDock.tsx:36-51`）。状态文字的唯一来源是 `DOCK_STATE_LABEL`（`XiaomuDock.tsx:53-61`）：

| 状态 | 状态文字 | 什么时候出现（`XiaomuDock.tsx:349-366` 的优先级顺序） |
| --- | --- | --- |
| `confirming` | **等待确认** | 有未决的高风险确认（`agent.pendingConfirm`）——**优先级最高** |
| `error` | **出错了** | 唤醒通道 `error`/`reconnecting`，或执行器 `ERROR` |
| `speaking` | **播报中** | 执行器 `RESPONDING` |
| `thinking` | **思考中** | `UNDERSTANDING`/`PLANNING`/`EXECUTING`/`WAITING_TOOL` |
| `recognizing` | **识别中** | 执行器 `RECOGNIZING` |
| `listening` | **正在听** | 通道 `live` 且正在收集命令（`collecting` 或已有 `partial`） |
| `idle` | **待机** | 以上都不成立 |

顺序本身就是设计：`collecting` 优先于 `partial`（收到唤醒事件那一刻就为真，否则唤醒后会有近一秒显示「待机」）；
四个"思考类"状态排在"正在听"之前（初版把"有 partial 就算正在听"放在思考之前，结果小木已经在执行、徽标还写着「正在听」，`XiaomuDock.tsx:332-348`）。

### 5.3 关掉动效后仍能靠"表情形状"分辨

这是硬要求（FR-06 / AC-05），实现方式是**七套完整的静止五官 + 动画只做叠加**：

（`xiaomuDock.css:247`）。`prefers-reduced-motion: reduce` 下只关动画，**不隐藏任何状态信息**（`xiaomuDock.css:887-916`）。

验收侧有对应断言：CDP 模拟 `prefers-reduced-motion` 生效后，7 个部件的动画/过渡全部 ≤0.01 s 或 `none`，
且**7 个状态徽标文字各不相同、状态配色组合 7/7 种不同**（等确认=橙、出错=红，两者已分开）——`docs/验收矩阵-v2.0.md:411`（AC-05）。

## 7. 键盘与无障碍

### 7.1 实际键位（与代码逐条核对，不是照抄文档）

| 按键 | 作用 | 生效条件 | 来源 |
| --- | --- | --- | --- |
| **Esc** | 收起气泡并**取消本轮**（走统一 `closeAgent()`） | 仅当 `agent.open \|\| expanded` 为真；且要**让路**（见 §7.2） | `XiaomuDock.tsx:250-285` |
| **Alt+W** | 常驻唤醒 开/关（`live` → `stop()`，否则 `start()`） | 任意页面，**与焦点无关** | `XiaomuDock.tsx:287`、`:303-308` |
| **Alt+E** | 展开 / 收起气泡面板（与"点小木形象"同一个动作） | 同上 | `XiaomuDock.tsx:308-310` |
| **Alt+R** | 重播最近一轮主回答（**只读**：只调播报，不重新 `ask()`） | 同上；没有最近一轮时静默忽略 | `XiaomuDock.tsx:311-314` |
| **Alt+M** | 重新开始常驻聆听（`start()` + `resume()`） | 同上 | `XiaomuDock.tsx:315-323` |

三条容易被误传的规则，按代码如实写：

- **Alt 组合键与焦点无关**：在输入框里打字时按 Alt+W/Alt+E 也生效。原来有一条"焦点在输入框里就不响应"的守卫，已删除 ——
  AltGr（Windows 上是 `Ctrl+Alt`）已被 `event.ctrlKey` 排除，纯 Alt+字母在 Chrome/Windows 下不产生文本输入（`XiaomuDock.tsx:288-300`）。
- **`event.repeat` 一律挡掉**，长按 Alt+R 不会变成狂暴重播（`XiaomuDock.tsx:301`）。
- **`event.shiftKey` 不参与判断**，所以 `Alt+Shift+W` 等同 `Alt+W`（`docs/键控编排-v1.1.md:30`；`XiaomuDock.tsx:287`）。
- **只有 Esc 是单键**（其余都用修饰键），避免和页面输入框、地图快捷键打架（`XiaomuDock.tsx:246`）。

### 7.2 Esc 的三条让路规则

一次 Esc 只能关掉**用户眼前那一个东西**（`XiaomuDock.tsx:250-285`；判据 `hasForeignModal()` 与全屏控制台共用，`api.tsx:58-75`）：

1. 页面上有**别人的**模态框（`[role="dialog"][aria-modal="true"]` / `[role="alertdialog"][aria-modal="true"]`，且不在 `.xd`、`.vc-root` 里）→ 气泡只 `return`、**不 `stopPropagation`**，让事件继续走到那个 Modal；
2. **全屏控制台正开着**（`.vc-root` 存在）→ 气泡让路（它是更上面的一层）；
3. 都不成立时，气泡才 `preventDefault()` → `close()`。

实现细节：监听器挂在**捕获阶段**（`window.addEventListener("keydown", onKey, true)`）——
让路判据必须早于页面 Modal 的冒泡监听器，否则"谁先注册"会决定结果（`XiaomuDock.tsx:326-328`，根因见 `:252-271`）。

### 7.3 焦点、`aria-expanded` 与文字兜底

| 项目 | 行为 | 来源 |
| --- | --- | --- |
| **焦点返回** | 记住"面板出现之前焦点在谁身上"，关闭时还给它；记不到就还给形象按钮（它是常驻入口，永远是合理落点）。修的是"关掉后焦点掉到 `BODY`、再按 Tab 要从头走一遍整页" | `XiaomuDock.tsx:204-219`、`:388-400` |
| **`aria-expanded`（形象）** | 值取 `visible`（面板可见性的唯一来源），**不是**本地 `expanded`：面板可能因本轮交互（`agent.open`）而可见 | `XiaomuDock.tsx:559-583` |

# 小木语音唤醒 · 接入说明 v1.0

## 一句话

说两遍「小木小木」，停一下，再说要做什么 —— 小木自动弹出并执行。
**全程本地、不联网。**

---

## 一、这条链路分两半，一半在仓库里，一半不在

这一点必须先说清楚，否则只拉仓库是跑不起来的。

```
浏览器（本仓库）                     语音边车（voice-module，不在本仓库）
┌──────────────────────────┐        ┌────────────────────────────────┐
│ agent/wakeChannel.ts     │  同源  │ Node 桥接 127.0.0.1:8780         │
│  · 采集 16k PCM          │ ─────► │  /voice-wake 转发                │
│  · 常驻 WebSocket        │        │        ↓                        │
│  · 唤醒事件 → 打开控制台  │        │ Python 服务 127.0.0.1:8770       │
│ agent/WakeOverlay.tsx    │ ◄───── │  · /wake  KWS 判定 + 二级复核    │
│  · 右下角状态 + 流式字幕  │  事件  │  · /asr   定稿识别（whisper）    │
│  · 中央回执对话框         │        └────────────────────────────────┘
└──────────────────────────┘
```

**为什么边车不放进仓库**：它带 3.5 GB 的 Python 运行时、464 MB 的模型、
CUDA 运行库，还有 KWS 模型 —— 这些都不该进 git。
仓库里只有前端那一半。

**这对合并意味着什么**：把本分支合进 RAO 之后，页面上的唤醒功能需要
本机另起 voice-module 才能工作。不跑边车时，唤醒通道会一直重连
（右下角状态条会显示"连接中断，正在重连…"），**不影响页面其它功能**。

---

## 二、怎么跑起来

1. 启动语音边车（两个进程）：

   ```
   voice-module\启动语音服务.cmd        # Python 服务，127.0.0.1:8770
   node voice-module\bridge\server.mjs  # Node 桥接，127.0.0.1:8780
   ```

2. 启动页面（`pnpm dev`，5173）。

3. 打开带唤醒参数的地址，在页面上点一下授权麦克风：

   ```
   http://127.0.0.1:5173/?wake=1
   ```

   不带 `?wake=1` 时默认不开麦（免得一进页面就弹权限）。
   另一个入口：右侧小木助手面板标题栏的「常驻唤醒」按钮。

---

## 三、接口契约（前端与边车之间的全部约定）

WebSocket `/voice-wake`，前端发二进制帧、边车回 JSON 文本帧。

**前端 → 边车**

| 帧 | 内容 |
| --- | --- |
| 二进制 | 16 kHz 单声道 16 位小端 PCM，100 ms 一片 |
| `{"type":"skip"}` | 我在跳过静音，没推流不是链路卡了 |
| `{"type":"preroll"}` | 验收用：要一次预滚缓冲回执 |

**边车 → 前端**

| 帧 | 内容 |
| --- | --- |
| `{"type":"ready"}` | 就绪，带 `stage`（`p1-kws` / `p0-passthrough`） |
| `{"type":"stats"}` | 每 500 ms 一次：帧数、字节、电平、跳过次数 |
| `{"type":"wake"}` | 判定唤醒，带 `route` / `detail` / `decision_ms` |
| `{"type":"partial","text":…}` | 唤醒后正在说的那句话（**当前整句**，前端整句替换） |
| `{"type":"command","text":…,"raw":…}` | 命令识别完成（`text` 已去掉开头唤醒词） |

**当前实现里的两个关键数字必须成对修改**：

| 位置 | 常量 | 值 | 说明 |
| --- | --- | --- | --- |
| 前端 `wakeChannel.ts` | `SILENCE_SKIP_MS` | 1000 | 静音超过它就不推流 |
| 边车 `service/server.py` | `COMMAND_END_SILENCE_MS` | 1000 | 边车收不到静音帧，用前端的 `skip` 当命令结束信号 |

## 四、判定规则：**必须说两遍**

这是产品硬要求。单说一遍「小木」**不会**唤醒。

规则分两条分支，两条都强制"两遍"（依据见 `voice-module/tools/实验-*.py` 的实测）：

1. **两遍直接命中**：关键词用两音节的「小木」，1.5 秒窗口内 KWS 报 ≥2 次 → 立即唤醒
   （实测 18/23，判定滞后 5–11 ms）
2. **单次命中 → 二级复核**：只报 1 次时，取预滚段交给 whisper 复核，
   转写去标点后必须出现**两次**「小木」才唤醒（实测 3/5 通过）

合起来 21/23 = 91.3%。这就是 Siri 那套"一级高召回 + 二级精判"的简化版。

> 为什么不用四音节关键词「小木小木」：实测召回只有 78.3%，而且扫遍
> `num_trailing_blanks` / `max_active_paths` / `keywords_score` / `threshold`
> 都推不动 —— 两遍之间有停顿就匹配不成一个连续 token 序列。

### 一个要注意的坑

`vite.config.ts` 里给代理挂了 `attachProxyErrorHandler`：后端不在时只让
**那一个请求**返回 502，而不是把错误冒到进程级。但 **WebSocket 代理的错误
仍可能把 vite 打挂**（实测崩过一次，日志是 `[vite] ws proxy error: read ECONNRESET`）——
所以**不要在页面开着唤醒通道时重启语音边车**。崩了就重新 `pnpm dev`。

## 六、为什么不用浏览器自带的语音识别

仓库里原有的 `agent/asr.ts` 走 `webkitSpeechRecognition`，Chromium 内核会把
音频送到云端识别 —— **断网就认不出任何东西**。唤醒要求"一直在听"，
既不能依赖网络，也不该把常驻麦克风音频持续送出去。所以唤醒这条路完全本地。

---

## 七、接入点

唤醒命中和命令识别都走**既有的** `mumai:agent-open` 事件（带 `question`），
不新增入口。也就是说：语音唤醒、串口语音、点击/文本三个入口最终落到
同一条执行链路上，页面跳转、二次确认、工具日志都不会被绕过。

---

## 八、现场排查

F12 控制台：

```js
__mumaiWake.state()        // "live" 才对；idle=没开、error=麦克风问题
__mumaiWake.stats()        // serverPeakRms 接近 0 = 音频没上来
__mumaiWake.wakes()        // 本轮唤醒次数
__mumaiWake.lastWake()     // 走了哪条判定分支、判定滞后多少毫秒
__mumaiWake.lastCommand()  // 唤醒后那句话识别成了什么
__mumaiWake.partial()      // 当前流式字幕
__mumaiWake.suspended()    // 是否在"命令已交出去、暂停听"的那 2.5 秒
```

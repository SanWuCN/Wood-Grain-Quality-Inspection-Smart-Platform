## 1. 验收范围与门槛

范围为总览四窗口、平台资源弹窗、支撑这些数据的只读采集与映射、最后播放的图表动画，以及用户要求的全站设备显示名统一。

不对中央地图进行重设计验收；只检查四窗口改动未遮挡既有地图操作，以及图表动画与原开场的衔接。其他页面只验收命名统一和真实设备接口未回归，不扩展为全站功能重构。

最终通过条件：所有 P0 项通过；无意外裁切 / 强制手动滚动、真实接口被静态数据替代、错误资源公式、未知误判为空闲、动画提前播放等阻断问题。工单超量时允许并要求固定高度逐条自动循环，须通过专门轮播用例。缺少截图、日志或数值样本时标“未测”，不得填“通过”。

结果枚举统一：未测 / 通过 / 失败 / 阻塞。每个用例记录测试人、时间、构建版本、输入样本、实际结果与证据。

### F3：阈值与极值

| GPU 输入 | 期望负载 |
|---:|---|
| 0 | 空闲 |
| 24.9 | 空闲 |
| 24.999 | 空闲；不按格式化后的 25.0 判档 |
| 25 | 低负载 |
| 49.999 | 低负载 |
| 50 | 中负载 |
| 74.999 | 中负载 |
| 75 | 高负载 |
| 100 | 高负载 |
| null / N/A / 过期 | 负载未知 / 数据过期，不能为空闲 |

利用率为 0 时任何 ±12% 扰动都应得到 0；利用率 100%、正扰动时封顶 100。显存同理不超过 24 GiB。有效输入应先校验范围，非法负数或超过 100 的原始值标无效，不默认为正常样本。

### F4：网络差分与缺口

1. 第一条累计样本只建立基线，显示“采样中”。
2. 2.5 秒后发送累计增加 2,500,000 B：真实 1,000,000 B/s，平台 300 MB/s。
3. 再次采样累计无变化：真实与映射均为 0 B/s。
4. 计数器小于上一条：当前速率无效，重新建基线；不得显示负数或超大溢出值。
5. 存在物理网卡及其 VPN / 虚拟网桥：只计算配置选中的、不重复的接口。

## 10. 证据与缺陷记录

### 10.1 必交证据

1. 四个目标视口的总览完整截图，各一张正常态；另附小尺寸异常态截图。
2. 存储、GPU、网络弹窗截图，至少一组显示4台服务器。
3. 正常开场与地图延迟场景录像，能够判断图表是在最后播放。
4. F1–F4 原始输入、映射输出与计算断言结果。
5. 一组真实后端主机采样记录和对应资源快照，注明hostId及各指标时间。
6. 扫描设备/巡检车真实接口状态变化证据，包含改名前后设备ID保持不变的核对结果。
7. 两个浏览器同snapshotId下的逐台资源数值对照。

### 10.3 阻断性缺陷

- 任一四窗口必须由用户手动滚动才能看到核心信息，或出现意外裁切；工单超量却不按要求循环、无法暂停或始终遗漏某些条目也属阻断问题。
- 扫描仪/车辆的真实接口被静态值替换；更名导致设备主键或控制目标改变。
- 服务器数错误、存储不等分、网络多乘N、GPU扰动误写成±12个百分点。
- 采集无数据时显示0占用/空闲；断线后仍继续随机变化伪装实时。
- 图表在地图或任一面板入场完成前播放，或每次数据更新都重播初始动画。
- 主卡、节点明细和功耗合计无法在同一快照复算。

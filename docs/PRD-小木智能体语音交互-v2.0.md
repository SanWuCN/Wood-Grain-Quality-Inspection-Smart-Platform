# 小木智能体语音交互 PRD v2.0

文档状态：待开发、待真机验收  
编写日期：2026-09-13  
适用项目：木脉智检平台 SHI 开发分支  
基线说明：需求分析基于 RAO 已合入的小木常驻唤醒实现；不得修改或推送 RAO/main，开发成果只进入 SHI。

## 1. 背景

平台已有两种小木入口：右侧文字助手，以及覆盖大半屏幕的语音控制台。RAO 已接入常驻麦克风、`/voice-wake`、本地 KWS/Whisper、意图匹配、工具执行、结构化事实和 TTS，但实际使用仍有以下问题：

1. 用户说“`小木小木`，停顿一下，再说命令”后，应直接触发原本需要点按钮或输入文字才能完成的交互。
2. 真人录音样本已存在，但唤醒准确率和误唤醒率还没有达到可交付标准；新命令也缺少“一个标准句对应多个真人样本”的规范化接入能力。
3. 语音唤起的全屏控制台会遮挡主业务页面；在独立挂载路径中还存在关闭后界面不退出的问题。
4. 语音入口和文字助手的输出能力不一致：天气回答已有结构化事实，但语音控制台没有展示文字助手已有的资料引用。
5. 当前按命令文本去重；用户连续两次说相同命令时，第二次可能不执行。

## 2. 产品目标

### 2.1 核心目标

- 用户无需点击按钮，只需说“`小木小木` + 短暂停顿 + 命令”，即可完成与按钮/文字入口相同的查询或脚本操作。
- 支持为一个标准命令录入多条真人语音样本，以样本集完成识别标定、回归和验收。
- 默认交互改为右下角动态小木形象与气泡，不再弹出覆盖大半屏幕的语音窗口。
- 小木必须能可靠关闭；关闭显示界面不等于关闭常驻唤醒。
- 查询结果必须保留主回答、结构化业务状态、可追溯资料引用和时间戳。

### 2.2 非目标

- 不接入联网大模型，不把归档天气描述成实时天气。
- 不用 DOM 点击模拟按钮；语音必须调用按钮背后的既有意图、工具或公开处理函数。
- 不绕过现有工具白名单、权限判断及风险等级 ≥3 的二次确认。
- 本需求不替代 COM4 外接语义设备通道；两条输入通道最终都应复用同一个 `openAgent/ask/Tool Registry` 执行入口。

## 3. 当前基线与已知证据

### 3.1 已有链路

```text
浏览器麦克风
  → wakeChannel（16kHz 单声道 PCM，常驻 WebSocket）
  → /voice-wake
  → sherpa-onnx KWS 判定“小木”两次 + Whisper 复核
  → 收集停顿后的命令并转写
  → mumai:agent-open(question)
  → ask → understand → Intent → Tool/Facts → TTS
```

该链路应继续复用，不再创建第二套语音执行器。

### 3.2 真人样本现状

- 原始样本：`D:\平台\voice-module\recordings\raw02\clip01.m4a` 至 `clip23.m4a`。
- 转码样本：`D:\平台\voice-module\recordings\wav16k02\clip01.wav` 至 `clip23.wav`。
- 标签清单：`D:\平台\voice-module\recordings\labels.json`。
- 23 条均为用户本人说“`小木小木`”的正样本。
- Whisper 已记录命中 20/23，召回率 87%；漏检为 clip02、clip03、clip10。
- 现行 KWS 参数注释记录的最佳正样本召回为 21/23，即 91.3%。
- 当前真人负样本为 0，无法测量真实 FAR（每小时误唤醒次数）。

结论：现有录音可以作为第一批标定和回归材料，但不能把“已放进 recordings”视为“模型已经学习完成”，也不能仅在这 23 条训练样本上调到全过就宣称可用。

### 3.3 已确认的代码问题

- `AgentHost` 仅随 `SmallWoodPanel` 挂载；面板关闭时，语音唤起会走 standalone root。
- standalone 的销毁依赖 `mumai:agent-close`，但 `VoiceConsole` 的关闭按钮只执行 `setAgent({open:false})`，没有走统一关闭入口，导致全屏界面可能残留。
- `lastAutoQuestionRef` 以命令文本去重；合法的连续同句指令也会被拦截。去重必须改为事件 ID，而不是文本。
- `SmallWoodPanel` 已显示 `sources`，但 `BotTurn/VoiceConsole` 当前没有资料引用字段和视图。

## 4. 目标用户旅程

1. 用户在小木设置中开启一次“常驻唤醒”，授予麦克风权限。
2. 右下角显示小木动态形象，待机态不遮挡主页面。
3. 用户说：“小木小木”。
4. 小木在识别到唤醒词后立即进入“正在听”状态，并给出可见但不刺耳的动画反馈。
5. 用户停顿约 0.3–1.5 秒后说：“查近三个月天气”。
6. 气泡实时显示正在识别的文字，定稿后调用 `site_weather`，效果必须等价于点击/文字输入该命令。
7. 小木在右下角输出完整结果，并只播报主回答一次。
8. 用户可以关闭气泡或小木交互层；主页面始终可操作。常驻唤醒继续工作，除非用户明确关闭“常驻唤醒”。
9. 用户再次说同一句命令时，必须产生新的一轮请求和新结果，不得因文本相同而被去重。

## 5. 功能需求

### FR-01 真人录音样本接入（P0）

系统必须支持“一条标准语句对应多条真人录音”。样本至少分为：

- 唤醒正样本：不同语速、音量、距离、朝向和环境下的“`小木小木`”。
- 唤醒负样本：单次“`小木`”、小木桥、小木屋、小木马、木木木、小幕、节目、幕布、正常对话、平台播报回环和环境噪声。
- 命令正样本：例如“`查近三个月天气`”的多次真人录音及允许的自然说法。
- 命令混淆样本：含“天气”但不应命中归档天气的句子，例如“今天天气怎么样”。

每个样本必须有清单字段：`sampleId`、`intentId`、`canonicalText`、`audioPath`、`speakerId`、`deviceId`、`environment`、`distance`、`speed`、`label`、`datasetSplit`、`createdAt`。

要求：

- 原始文件保留；派生文件统一为 16kHz、单声道、PCM 16-bit WAV。
- 训练/标定集与验收集在调参前固定；同一次连续录音不能拆散后分别进入训练和测试。
- 新增样本后必须通过单一命令完成体检、转码、评估并输出报告。
- 默认不把含真人声音的原始录音推送到 Git；只提交用户明确允许的素材、标签和统计。大文件需要另行确认存储策略。

### FR-02 唤醒词识别（P0）

- 唤醒短语为连续两次“`小木`”，即“`小木小木`”。
- 只说一次“`小木`”不得唤醒。
- 匹配前必须去除空格和标点，兼容“小木，小木。”等转写。
- 不得因为小木自己的 TTS 播报、页面视频声音或音箱回环再次唤醒。
- 唤醒成功后只切换到命令收集状态，不应立刻弹出全屏窗口。
- 服务不可用、麦克风被拒绝或 KWS 退化时必须显示真实状态，禁止显示“正在听”但实际没有音频链路。

### FR-03 唤醒后停顿与命令识别（P0）

- 支持“唤醒词 → 0.3–1.5 秒自然停顿 → 命令”的说法。
- 唤醒前后的预滚缓冲不得吃掉命令开头。
- 命令结束以可靠的静音或协议边界判定，不能在正常词间停顿处提前截断。
- 去除唤醒词时不能破坏“木柱”等业务词。
- 流式字幕可自我修正，不能重复拼接同一段文字。
- 每次命令必须携带唯一 `interactionId`；重复同一句话仍是两次独立交互。

### FR-04 与按钮交互等价（P0）

- 语音命令命中后，调用现有 Intent、Tool Registry 或按钮背后的业务函数。
- 同一命令通过语音、文字、示例按钮或 COM4 进入时，业务结果必须一致。
- 禁止通过坐标或 DOM selector 模拟点击。
- 查询类命令不得产生写操作；高风险动作继续弹出明确的确认/取消气泡，未确认不得执行。

### FR-05 天气命令固定结果（P0）

标准句：“`查近三个月天气`”。允许至少包括现有意图中的同义说法，但“`今天天气怎么样`”不得错误命中归档天气。

主回答必须由现有结构化数据生成，文字为：

> 归档天气档案（2026-06-11 至 2026-09-10（近三个月））：梅雨期累计降水 412mm，8 月 3 次连续降雨过程，平均相对湿度 78%，日温差最大 11.4℃。数据来源：归档天气档案 · 非实时联网查询；这是归档数据，不是实时联网查询。

同时展示以下业务状态：

| 字段 | 值 |
| --- | --- |
| `weatherRange` | `2026-06-11 至 2026-09-10（近三个月）` |
| `weatherSummary` | `梅雨期累计降水 412mm，8 月 3 次连续降雨过程，平均相对湿度 78%，日温差最大 11.4℃` |
| `weatherSource` | `归档天气档案 · 非实时联网查询` |

资料引用必须显示并可点击：

- 标题：`示例寺近三个月归档天气档案`
- 原文位置：`降水与湿度 · w-01`
- 点击后打开现有知识库原文位置或至少打开对应知识文档。
- 气泡底部显示本轮实际生成时间，格式 `HH:mm:ss`；`19:03:48` 只是示例，不得写死。
- TTS 只播报主回答，不逐项朗读字段名、来源定位和时间戳。

### FR-06 右下角动态小木形象（P0）

- 默认入口固定在右下角，不显示全屏遮罩，不阻塞主业务页面。
- 复用现有 `I04-xiaomu-assistant` 视觉资产；如果后续采用分层动画、序列帧或 Lottie，必须保持同一形象，不再引入第二套小木造型。
- 建议形象主体 72–96px；距右、下边缘 20–28px；气泡最大宽度 420px，在 1366×768 下不得遮挡超过约四分之一页面。
- 状态至少包括：待机、已唤醒/聆听、识别中、思考中、播报中、等待确认、错误。
- 动效使用轻微呼吸、上下浮动、声波或光圈表达状态；不使用大幅跳动和持续高亮闪烁。
- 尊重 `prefers-reduced-motion`，关闭动效后仍能通过文字和颜色辨认状态。

### FR-07 气泡式交互（P0）

- 用户流式字幕显示为靠近小木的用户气泡；识别定稿后原气泡就地更新，不重复新增相同文本。
- 小木回复显示为助手气泡，包含主回答、结构化业务状态、资料引用和时间戳。
- 默认只保留最近交互所需的有限高度；历史记录可在气泡内滚动或通过“展开记录”查看，不恢复全屏遮罩。
- 回答较长时允许折叠“业务状态”和“资料引用”，但主回答、归档/非实时声明必须直接可见。
- TTS 状态、静音/重播、识别失败和重试必须在紧凑区域内可操作。

### FR-08 关闭与生命周期（P0）

- 小木区域必须提供始终可见、可点击的关闭按钮，并支持 `Esc`。
- 所有关闭入口必须调用同一个 `closeAgent()` 或等价的统一生命周期函数，不能分别只改局部 state。
- standalone root、Portal、事件监听、计时器、ASR、TTS 和未完成确认必须正确清理。
- 关闭时立即停止当前 TTS，结束本轮命令采集；若有未确认高风险操作，应按“取消”处理。
- 关闭气泡后常驻唤醒默认继续；只有用户点击“关闭常驻唤醒”才释放麦克风并断开 `/voice-wake`。
- 关闭后主页面焦点恢复到唤起前元素；页面上不得留下透明遮罩或拦截点击的容器。

### FR-09 重复命令与并发（P0）

- 连续两次说“查近三个月天气”必须执行两次并分别显示时间戳。
- 去重仅能依据同一 `interactionId/eventId`，不得依据命令文本。
- 同一时刻只处理一个语音命令；新命令到来时应排队、明确打断或提示忙碌，不得并发写入同一个 Agent store。
- TTS 播报期间继续执行自听回环抑制；播报结束或被用户打断后恢复监听。

### FR-10 失败与降级（P1）

- 未听清：显示“没有听清，请再说一次”，不执行任何工具。
- 低置信命中：显示识别文本和建议标准说法；查询可回复但必须标注不确定，高风险操作禁止执行。
- 未命中意图：使用现有 Fallback，不猜答案。
- 本地语音服务断开：动态小木进入错误态并提供重连；文字入口和 COM4 入口仍可用。

## 6. 样本包与命令配置建议

每个新命令应形成一个可追踪样本包，而不是在代码里散落文件名。建议逻辑结构：

```text
recordings/
  wake/xiaomu-xiaomu/{positive,negative}/
  intents/site_weather/{positive,confuser}/
  manifests/voice-intents-v2.json
  reports/evaluation-v2.json
```

示例清单：

```json
{
  "intentId": "site_weather",
  "canonicalText": "查近三个月天气",
  "samples": [
    {
      "sampleId": "site-weather-shi-001",
      "audioPath": "intents/site_weather/positive/shi-001.wav",
      "speakerId": "shi",
      "deviceId": "demo-laptop-mic",
      "environment": "demo-room",
      "label": "positive",
      "datasetSplit": "test"
    }
  ],
  "expected": {
    "intentId": "site_weather",
    "risk": 0
  }
}
```

该结构是产品数据约束，不要求照抄为新的运行时抽象；开发前应先复用现有 `recordings/labels.json`、评估脚本和 Intent 目录。

## 7. 交互状态机

```text
待机
  └─ 两遍唤醒命中 → 已唤醒/聆听
       ├─ 流式转写 → 识别中
       ├─ 静音定稿 → 理解/执行
       │    ├─ 普通查询 → 回复气泡 → 播报 → 待机
       │    ├─ 高风险操作 → 确认气泡 → 确认/取消 → 待机
       │    └─ 未命中/错误 → 提示气泡 → 待机
       └─ 超时/关闭 → 取消本轮 → 待机
```

任何状态下关闭显示层都不得关闭主业务页面。只有显式关闭常驻唤醒，才进入“麦克风关闭”。

## 8. 验收标准

### AC-01 指定天气链路

使用用户真人声音说“`小木小木`”，停顿 0.3–1.5 秒，再说“`查近三个月天气`”：

1. 唤醒成功，流式字幕正确；
2. 最终命中 `site_weather`；
3. 主回答与 FR-05 完全一致；
4. 三个业务字段值正确；
5. 资料标题和 `降水与湿度 · w-01` 可见、可打开；
6. 时间戳为本轮实际时间；
7. 全程不出现全屏遮罩。

用户提供的该句验收样本必须 100% 通过；另行冻结的未参与调参测试集命令识别正确率目标不低于 95%。

### AC-02 唤醒准确率

- 冻结真人正样本集上的漏唤醒率 FRR 目标 <3%。
- 真人负样本连续回放和现场底噪测试的误唤醒率 FAR 目标 <1 次/小时。
- 现有 23 条正样本必须全部进入报告，但不能全部同时作为调参集和验收集。
- “小木”单次、小木桥、小木屋、小木马、木木木、平台 TTS 回环不得唤醒。

### AC-03 重复同句

连续完成两轮相同天气命令，两轮均返回；`interactionId` 和时间戳不同，不能只执行第一轮。

### AC-04 关闭

- standalone 和应用内挂载两条路径分别测试关闭按钮与 `Esc`。
- 关闭后 200ms 内界面消失，DOM 中无残留遮罩，不再拦截页面点击。
- 正在播报、正在识别和等待高风险确认时关闭，也必须正确停止/取消。
- 关闭气泡后再次喊“`小木小木`”仍可正常唤起。

### AC-05 UI

- 1366×768、1920×1080 两种尺寸验收；小木与气泡只占右下角局部区域。
- 背景地图、表格和主要按钮仍可见、可点。
- `prefers-reduced-motion` 下无持续动态，但状态信息完整。

### AC-06 回归与安全

- 点击、文字、语音、COM4 对同一意图返回同一事实值。
- 风险等级 ≥3 的操作仍必须二次确认。
- 未命中、低置信、服务断开、麦克风拒绝均不误执行工具。

## 9. 非功能要求

- 全链路优先本地运行；原始音频默认不上传外网。
- 不在日志中永久保存连续原始麦克风音频；调试录音必须由用户显式开启。
- 唤醒结束到可见“正在听”反馈目标 ≤800ms。
- 命令结束到首个完整回复气泡目标 ≤2s（首次模型预热单独记录）。
- 动画应使用 transform/opacity，避免影响地图和三维页面帧率。
- 新功能必须可通过配置关闭，关闭后不影响文字助手、COM4、SensorTag 和其它 RAO 功能。

## 10. 建议实施顺序

1. 修复统一关闭生命周期和重复同句去重问题，并添加组件/状态测试。
2. 抽取语音与文字入口共享的回复视图模型，使结构化事实和资料引用只有一个来源。
3. 在现有 Agent store 上实现右下角动态小木与气泡渲染，默认停用全屏 VoiceConsole；保留开发诊断入口。

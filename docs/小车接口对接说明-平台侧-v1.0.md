# 木脉智检 · 小车接口对接说明（平台侧 v1.0）

本文是**平台已经实现、正在使用**的小车接口清单，用来对接与排查。
契约源头是小车端的《木脉智检 · 小车端接口 v1.0》，平台这一侧没有改小车任何代码，
只在平台服务端做了一层转发与鉴权。

- 平台服务地址：`http://<平台主机>:8000`
- 小车服务地址：`http://192.168.31.221:8765`（小车屏幕上是 `http://127.0.0.1:8765`）
- 涉及页面：建图巡航（`/#/mapping`），源码 `src/pages/MumaiDashboard/pages/cart/`

---

## 0. 一句话总览

| 方向 | 谁发起 | 用途 | 接口 |
|---|---|---|---|
| 平台 → 小车 **读** | 平台服务端 | 状态、地图、截图、视频 | 代理到小车 `/api/state`、`/api/map.png`、MJPEG 等 |
| 平台 → 小车 **写** | 平台服务端 | 建图 / 巡航控制 | 代理到小车 `/api/mapping/*`、`/api/navigation/*` 等 |
| 小车 → 平台 **上行** | 小车 | 注册与遥测 | `POST /api/devices/register`、`POST /api/device-events/batch` |

**浏览器不直连小车**。两个原因（小车端文档 §1 也写了）：控制令牌不能进前端包；
小车对浏览器 POST/WS 校验 `Origin === Host`，跨源会被 403。

## 1. 平台侧配置（一次性）

### 1.1 平台 → 小车的控制令牌

平台服务端读 `server/data/cart.json`（权限 0600，已在 `.gitignore` 内）：

```json
{
  "url": "http://192.168.31.221:8765",
  "token": "<小车 config.local.json 里的 control_token>"
}
```

也可以用环境变量覆盖：`MUMAI_CART_URL`、`MUMAI_CART_TOKEN`。

> 只读接口在小车上不需要令牌，所以**没配令牌时页面仍可看**（地图、位姿、视频、全部参数都是真实的），
> 只是所有按钮置灰并提示「只读监视」。配了令牌才有控制权。

### 1.2 小车上行到平台的设备令牌

平台服务端读 `server/data/device-tokens.json`（0600，已忽略）：

```json
{ "mumai-car-01": "<平台给小车的设备令牌>" }
```

也可以用环境变量：`MUMAI_DEVICE_TOKENS="mumai-car-01:<令牌>,其他设备:<令牌>"`。
两个来源会合并。

## 2. 平台 → 小车：只读接口

全部是 `GET`，需要平台登录态（`Authorization: Bearer <平台令牌>`）。

### 2.1 小车链路状态（页面主数据源）

```
GET /api/cart/status
```

返回平台服务端**已经判过新鲜度**的快照，页面不自己算：

```json
{
  "configured": true,
  "canControl": true,
  "link": "online",
  "live": true,
  "ageMs": 52,
  "lastError": null,
  "state": { "...": "小车 /api/state 的完整对象" },
  "info": { "deviceId": "mumai-car-01", "version": "1.0.0", "simulated": false, "maxSpeedMps": 0.35 },
  "serverTime": "2026-09-15T00:40:00.000Z"
}
```

| 字段 | 含义 |
|---|---|
| `link` | 平台服务端 → 小车的连接：`unconfigured` / `connecting` / `online` / `offline` |
| `live` | 链路在线 **且** 状态年龄 ≤ 3 秒（小车端文档 §2：超过 3 秒按断线处理） |
| `ageMs` | 最近一份状态的年龄（毫秒） |
| `state` | 小车 `/api/state` 的完整对象，原样转发，不加工 |

同一份快照也会通过平台的 WebSocket 推送（约 2 Hz）：

```
WS /ws?sessionId=demo-01
→ { "kind": "cart", "type": "state", "payload": { ...同上的快照... } }
→ { "kind": "cart", "type": "link",  "payload": { ...链路变化时的快照... } }
```

### 2.2 只读通道转发

```
GET /api/cart/read/{channel}
```

`channel` 取值与小车路径一一对应：

| channel | 小车路径 | 说明 |
|---|---|---|
| `health` | `/api/health` | `{ok,version,simulated}`，只代表服务存活 |
| `session` | `/api/session` | `{token,can_control,device_id,max_speed_mps}` |
| `state` | `/api/state` | 完整状态（也见 2.1） |
| `config` | `/api/config` | 平台上报地址与 RTMP 设置；**需要控制令牌**，不回传令牌值 |
| `map` | `/api/map` | 当前地图元信息；未就绪时小车回 404 |
| `maps` | `/api/maps` | `{maps:[...]}` 已保存地图，按创建时间倒序 |
| `routes` | `/api/routes` | `{routes:[...]}` 已保存路线 |
| `battery` | `/api/battery` | 电池对象 |
| `chassis` | `/api/chassis` | 底盘对象 |

### 2.3 设备信息（页面头部用）

```
GET /api/cart/info
```

`{ ok, info: { deviceId, version, simulated, maxSpeedMps, platformUrl, platformTokenSet, rvizRtmpUrl, cameraRtmpUrl, telemetryIntervalS }, status }`

### 2.4 当前栅格地图 PNG

```
GET /api/cart/map.png
```

直接回 `image/png`。页面按 `state.map.revision` 判断是否需要重取（文档 §3）：

```
/api/cart/map.png?v=<revision>
```

未就绪时回 `409 MAP_UNAVAILABLE`，页面显示「无地图」。

### 2.5 已保存地图的预览图与 Nav2 文件

```
GET /api/cart/maps/{mapId}/preview.png     → image/png
GET /api/cart/maps/{mapId}/map.yaml        → text/yaml
GET /api/cart/maps/{mapId}/map.pgm         → application/octet-stream
GET /api/cart/maps/{mapId}/metadata.json   → application/json
```

> 注意小车侧的两条路径**不一样**：预览图是 `/api/maps/{id}/preview.png`，
> Nav2 文件是 `/api/maps/{id}/files/...`。平台已经按这个分开了，对接时别混。

### 2.6 两路视频（MJPEG）

```
GET /api/cart/stream/rviz      → multipart/x-mixed-replace   （小车 Xvfb :99 上的 RViz 画面）
GET /api/cart/stream/camera    → multipart/x-mixed-replace   （摄像头 /camera/color/image_raw）
```

可直接 `<img src="...">`。通道未就绪时回 `502`，页面显示离线，**不伪造图像**。
两路的输出分辨率不同（实测 RViz 694×434、摄像头 640×480），页面各探一帧读出真实尺寸后
按原始比例显示，不做任何拉伸。

## 3. 平台 → 小车：控制接口

```
POST /api/cart/action
Content-Type: application/json
X-Request-Id: <本次逻辑操作的唯一编号，建议 UUID>
```

请求体第一段是动作名，其余字段原样转发给小车：

```json
{ "action": "navigation/start", "map_id": "map_...", "points": [{"x":0.4,"y":0.2,"yaw":0.0}], "mode": "multi", "speed_mps": 0.2 }
```

**为什么动作名放请求体**：动作名是 `mapping/start` 这种带斜杠的两段名，
放进 URL 路径段会被 `:param` 在斜杠处截断。服务端有白名单（下表 14 个），
页面怎么拼都只能打到这些动作上。

### 3.1 动作白名单与所需权限

| action | 小车路径 | 平台权限 |
|---|---|---|
| `mapping/start` | `/api/mapping/start` | `map:save` |
| `mapping/restart` | `/api/mapping/restart` | `map:save` |
| `mapping/save` | `/api/mapping/save` | `map:save` |
| `mapping/stop` | `/api/mapping/stop` | `map:save` |
| `navigation/load` | `/api/navigation/load` | `mission:dispatch` |
| `navigation/auto-localize` | `/api/navigation/auto-localize` | `mission:dispatch` |
| `navigation/localize` | `/api/navigation/localize` | `mission:dispatch` |
| `navigation/preview` | `/api/navigation/preview` | `mission:dispatch` |
| `navigation/start` | `/api/navigation/start` | `mission:dispatch` |
| `navigation/speed` | `/api/navigation/speed` | `mission:dispatch` |
| `routes/save` | `/api/routes/save` | `map:save` |
| `navigation/pause` | `/api/navigation/pause` | `mission:monitor` |
| `navigation/resume` | `/api/navigation/resume` | `mission:monitor` |
| `control/stop` | `/api/control/stop` | `mission:monitor` |

### 3.2 各动作的请求体

| action | 请求体字段 | 备注 |
|---|---|---|
| `mapping/start` | `{}` | 已在建图时小车回 `ALREADY_MAPPING` |
| `mapping/restart` | `{}` | 先把当前地图持久化，再重启建图；返回 `backup` |
| `mapping/save` | `{ "name": "一层大厅" }` | 名称去空格后 1–40 字 |
| `mapping/stop` | `{}` | 结束建图，**不自动保存** |
| `navigation/load` | `{ "map_id": "map_..." }` | 保存当前建图后切 Nav2，自动尝试全局定位 |
| `navigation/auto-localize` | `{}` | 重新调用 AMCL 全局定位 |
| `navigation/localize` | `{ "pose": { "x": 1.0, "y": 0.0, "yaw": 1.57 } }` | 发布 `/initialpose` |
| `navigation/preview` | `{ "points": [...], "mode": "single" }` | 只规划不运动；可能返回 `NO_PATH` |
| `navigation/start` | `{ "map_id", "points", "mode", "speed_mps" }` | **车辆会运动** |
| `navigation/pause` | `{}` | 取消当前目标，保留航点下标 |
| `navigation/resume` | `{}` | 重新前往被暂停的航点 |
| `navigation/speed` | `{ "speed_mps": 0.2 }` | 绝对速度，允许 `[0.05, 0.35]`；**0 不是停止** |
| `control/stop` | `{}` | 取消任务并发布零速度；急停走这条 |
| `routes/save` | `{ "name", "map_id", "points", "mode", "speed_mps" }` | 路线与地图 ID 绑定 |

`mode`：`single` 恰好 1 个航点 · `multi` 1–100 个依次运动 · `loop` 2–100 个循环。
`points` 元素为 `{x, y, yaw}`，单位 m 与 rad，必须在**已知自由栅格**内。

### 3.3 幂等

`X-Request-Id` 转发给小车，小车按它做幂等（小车端文档 §1）：同一编号 + 同一路径 + 同一请求体
重复提交返回第一次的结果；编号被用于其它内容返回 `409 IDEMPOTENCY_CONFLICT`。
**同一逻辑操作重试时必须复用同一个编号**，所以编号由发起动作的页面生成、不在平台这层生成。

### 3.4 `ok:true` 的含义

只表示「这次操作已被接收」，**不代表已完成**。最终结果看状态里的 `mode` 与 `mission.state`
（`idle/accepting/running/pausing/paused/stopping/stopped/completed/failed`）。

## 4. 小车 → 平台：上行接口

小车端已经是现成的（`backend/uplink.py`），需要填两样：

```http
POST /api/settings/save          # 小车右上角设置页
```
```json
{
  "platform_url": "http://<平台主机>:8000",
  "platform_token": "<平台分配的设备令牌>",
  "rviz_rtmp_url": "rtmp://推流服务器/live/car01_rviz",
  "camera_rtmp_url": "rtmp://推流服务器/live/car01_camera"
}
```

### 4.1 注册

```http
POST {platform_url}/api/devices/register
X-Device-Id: mumai-car-01
X-Device-Token: <设备令牌>
Content-Type: application/json
```
```json
{
  "schemaVersion": "1.0", "deviceId": "mumai-car-01", "bootId": "<本次服务会话 UUID>",
  "appVersion": "1.0.0", "adapterVersion": "ros2-humble-1",
  "host": { "kind": "robot", "os": "linux" },
  "capabilities": { "mapping": true, "navigation": true, "telemetry": true, "video": ["mjpeg", "rtmp"] }
}
```

### 4.2 遥测（随后约每秒一次）

```http
POST {platform_url}/api/device-events/batch
X-Device-Id: mumai-car-01
X-Device-Token: <设备令牌>
Content-Type: application/json
```
```json
{
  "events": [{
    "schemaVersion": "1.0", "type": "device.telemetry", "deviceId": "mumai-car-01",
    "bootId": "<当前会话 UUID>", "messageId": "<本条消息 UUID>", "seq": 1,
    "sentAt": "2026-09-15T00:40:00+08:00",
    "payload": { "...": "小车 /api/state 的完整状态（省略 scan_points / path / imu_history）" }
  }]
}
```

平台确认（支持外层 `data` 包裹）：

```json
{ "accepted": ["<messageId>"], "duplicated": [], "rejected": [] }
```

只有 messageId 出现在 `accepted`/`duplicated` 且没有 `rejected`，小车才显示「平台已连接」。

### 4.3 平台侧的设备读取（排查用）

| 接口 | 用途 |
|---|---|
| `GET /api/devices` | 已登记设备清单与在线状态（需登录态或设备令牌） |
| `GET /api/devices/{deviceId}/hardware` | 最近一份上报与链路状态 |
| `GET /api/devices/{deviceId}/events?limit=40` | 最近事件 |
| `GET /api/devices/{deviceId}/history?limit=` | 上报历史采样 |

## 5. 错误码与状态码

平台把小车的错误码**原样保留**，只把状态码翻成 HTTP 语义，便于判断：

| 小车错误码 | 平台 HTTP | 典型场景 |
|---|---|---|
| `MAP_UNAVAILABLE` | 409 | 还没建图 / 地图未就绪 |
| `MAP_NOT_FOUND` | 404 | 地图 ID 不存在 |
| `MAP_MISMATCH` | 409 | 路线绑定的地图与当前加载的不一致 |
| `INVALID_NAME` / `INVALID_WAYPOINTS` / `INVALID_POSE` | 422 | 参数不合法 |
| `OUTSIDE_MAP` / `POINT_BLOCKED` | 422 | 航点在地图外 / 障碍或未知区域 |
| `NOT_LOCALIZED` | 409 | 未定位，不能规划或巡航 |
| `NAV_NOT_READY` | 409 | Nav2 动作服务未就绪 |
| `NO_PATH` / `PLAN_REJECTED` | 422 | 规划不出路径（**不要用直线替代真实路径**） |
| `MISSION_ACTIVE` / `NOT_RUNNING` / `NOT_PAUSED` | 409 | 任务状态冲突 |
| `CONTROL_LOCKED` / `UNAUTHORIZED` | 403 | 平台侧没配控制令牌 |
| `ROS_TIMEOUT` | 504 | 小车 ROS 超时 |
| `CART_UNREACHABLE` / `CART_UNCONFIGURED` | 502 / 503 | 平台连不上小车 / 没配地址 |
| `BAD_ACTION` | 404 | 动作名不在白名单里 |
| `IDEMPOTENCY_CONFLICT` | 409 | 同一 `X-Request-Id` 用于了不同内容 |

平台统一的错误体：

```json
{ "code": "NOT_LOCALIZED", "message": "未定位", "fieldErrors": [], "retryable": false }
```

## 6. 排查命令

```bash
# 平台到小车的链路状态（把 <平台令牌> 换成登录拿到的 token）
curl -s -H "authorization: Bearer <平台令牌>" http://<平台主机>:8000/api/cart/status | jq '{link,live,ageMs,mode:.state.mode}'

# 只读通道
curl -s -H "authorization: Bearer <平台令牌>" http://<平台主机>:8000/api/cart/read/maps | jq '.maps[].name'

# 路线预览（只规划，不让车动）
curl -s -X POST http://<平台主机>:8000/api/cart/action \
  -H "authorization: Bearer <平台令牌>" -H 'content-type: application/json' \
  -H "x-request-id: $(uuidgen)" \
  -d '{"action":"navigation/preview","points":[{"x":0.4,"y":0.2,"yaw":0}],"mode":"single"}' | jq

# 视频通道是否活着（能出帧就说明代理与小车都正常）
curl -s -m 4 -o /dev/null -w '%{http_code} %{content_type}\n' http://<平台主机>:8000/api/cart/stream/rviz

# 小车上行是否配好（platform_url / platform_token_set）
curl -s -H "authorization: Bearer <平台令牌>" http://<平台主机>:8000/api/cart/read/config | jq

# 设备是否登记成功
curl -s -H "X-Device-Token: <设备令牌>" http://<平台主机>:8000/api/devices | jq '.devices[] | {deviceId, "link": .link.state}'
```

**登录拿平台令牌**（演示口令 `123456`）：

```bash
curl -s -X POST http://<平台主机>:8000/api/auth/login \
  -H 'content-type: application/json' \
  -d '{"account":"mayutian","password":"123456"}' | jq -r .token
```

## 8. 已知边界（避免误判）

1. **`null` 不是 0**。IMU / 里程计超过 2 秒未更新、电压字段 5 秒未更新，小车返回 `null`，
   页面显示「—」。不要把它当成零值参与计算。
2. **视频在播放 ≠ 车辆在线**。地图、位姿、RViz、摄像头四路各自判断新鲜度。
3. **`/PowerVoltage` 是电压，不是电量**。页面上的「剩余电量」是按 3S 锂电池
   （满电 12.6 V、标称 10.8 V、截止 9.0 V）的放电曲线**本地推算**的；小车若上报合法 BMS
   百分比则优先用实测值。充电时电压被充电器抬高，页面显示「充电中」而不给数字。
4. **`commanded_velocity` 是控制指令**（`/cmd_vel`），不代表实测速度；实测看 `velocity`。
5. **`velocity.pose` 不是 map 坐标**，它是 `odom_combined` 里的里程计位姿；
   map 坐标看 `pose`。
6. **`ok:true` 只是接收成功**，巡航最终结果看 `mission.state`。
7. **RTMP 的 running 只代表小车本地编码进程在跑**，不代表平台已收到流。
   浏览器不能直接播 `rtmp://`，平台侧需要自行转 WebRTC/HLS/HTTP-FLV。

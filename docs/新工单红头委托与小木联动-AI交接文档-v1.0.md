# 新工单红头委托与小木联动 AI 交接文档 v1.0

## 文档目的

本文档供后续 AI 或开发人员直接接手“快捷键来单、红头委托预览、小木读取、平台工单生成效果与模块动态展开”需求喵

实现必须复用现有快捷键建单、工单服务、语音模糊匹配、导航和揭示机制，并把服务端返回的数据作为唯一业务事实喵

任何图片生成结果、语音识别文本或模型临场推理都不得成为工单字段的数据源喵

## 目标效果

用户在平台任意已登录页面按下 `Ctrl + Q + L` 后，平台继续通过现有服务端事务创建一张新工单，并显示“收到新工单”的通知喵

用户点击通知中的“查看”后不得立即跳转工单档案，而应打开一张具有真实纸张、红色抬头、正文排版、落款和印章质感的委托文件照片喵

用户面对该委托文件喊出唤醒词和读取命令后，小木开始简短播报，同时关闭委托预览并跳转到这张工单的档案详情喵

详情页的大模块必须跟随小木播报的语义节点依次展开，不得在第一句话出现前一次性显示全部内容喵

## 锁定交互时序

1. 用户按住 `Ctrl`，先按 `Q`，再在 1.5 秒内按 `L` 喵
2. `useWorkOrderShortcut.ts` 生成单次事件 ID，并调用现有工单触发接口喵
3. 服务端在同一事务中创建工单、四条检测主体、空环境草稿和转换日志喵
4. 平台显示带“查看”动作的新工单通知喵
5. 用户点击“查看”后，平台记录该通知对应的 `orderId` 为待读取工单，并打开红头委托预览喵
6. 此时路由保持不变，用户原页面不得提前跳走喵
7. 用户说出唤醒词，停顿 0.3 至 1.5 秒，再说读取命令喵
8. 语音链路派发既有 `mumai:xiaomu-ask` 事件，并由第①轮剧本处理喵
9. 第①轮必须优先读取已绑定的待读取 `orderId`，不得默认取工单列表第一项喵
10. 小木开始回复后，平台关闭红头委托预览并导航到 `/orders?order=<已绑定 orderId>` 喵
11. 工单详情根据播报节点依次展开四组内容喵
12. 播报结束、播报失败或交互被中断后，揭示计划必须自动收尾，页面不得永久停留在半展开状态喵

## 触发短语

标准演示说法为“**小木小木**”，停顿 0.3 至 1.5 秒后说“**读取这份工单**”喵

允许命中的短语包括“读取工单”“整理任务”“整理任务范围和出发清单”等与第①轮高度一致的表达喵

现有同音字、近音字、漏字和语序变化的模糊匹配能力继续保留，但必须通过既有置信阈值和第二名余量判定喵

只有匹配结果为明确命中时才能执行导航和揭示，无关短句、低置信结果和仅说“工单”不得触发整套流程喵

## 小木回复 v1.0

小木显示和播报以下短文案，产品文本本身不追加语气词喵

> 读取中，工单摘要已生成。  
> 任务范围和出发清单已生成。  
> 已整理为四项任务：现场建档、风险初筛、重点精扫和复核交付。  
> 附件里未明确的信息，我已单独列出。本次任务涉及的木构主体为四根木柱，我已按照 Z01 至 Z04 编号。

回复不得额外播报风险结论、木材树种、设备检测结果、具体柱位方向或附件中不存在的信息喵

## 模块展开节拍

| 播报节点 | 页面动作 | 必须展示的确定性内容 |
| --- | --- | --- |
| 读取中，工单摘要已生成 | 关闭委托预览并进入已绑定工单，展开工单摘要喵 | 工单编号、标题、状态、计划时间、地点、创建时间、负责人和来源喵 |
| 任务范围和出发清单已生成 | 展开任务范围与出发清单喵 | 委托范围、交付要求、四项任务和预设装备检查项喵 |
| 已整理为四项任务 | 强调并完整展开任务模块喵 | 现场建档、风险初筛、重点精扫、复核交付喵 |
| 附件未明确信息与四柱编号 | 展开待确认信息、检测主体和后续执行模块喵 | 待确认项、Z01 至 Z04、人员指派、环境配置、扫描仪下发和作业成果空态喵 |

展开节拍应按标点切分后的语义段计算，不得再按整段总字数平均分配喵

当真实 TTS 返回播放完成事件时，以真实结束时间为最终收尾依据，字数估时只作为降级方案喵

## 唯一事实源

### 原始委托事实

快捷键场景的委托事实只允许来自 `server/services/work-orders.mjs` 中的 `sampleCommission(now)` 返回值喵

该对象当前锁定以下数据口径喵

- 标题为“关于开展示例寺四根木柱检测工作的委托”喵
- 委托单位为“示例古建筑保护管理单位”喵
- 项目名称为“示例寺古建筑检测”喵
- 地点为“上海市松江区示例寺院内”喵
- 检测主体类型为木柱，数量为四根，具体位置进场核对喵
- 作业日期相对触发日期动态生成，开始日为触发日后两天，结束日为触发日后四天喵
- 交付期限为触发日后九天喵
- 范围为现场四根木柱的非破坏性检测，并逐根记录检测位置、环境条件与原始数据喵
- 原始附件只有“示例寺建筑平面示意图.pdf”和“现场进场与开放时间安排.docx”喵

红头委托中的日期、地点、正文、附件名称和交付期限必须从当前工单详情读取，不得在前端另写一份静态副本喵

### 平台转换事实

工单编号、内部 `orderId`、状态、平台创建时间和 Z01 至 Z04 检测主体由服务端事务确定性生成喵

原始委托只写“四根木柱”，不得把 Z01 至 Z04、雷达结论、风险等级或平台内部字段伪装成委托单位原文喵

“已生成”表示小木已经将现有委托读取并组织为平台视图，不表示语音阶段再次执行建单接口喵

## 四项任务与出发清单

四项任务属于本演示的确定性整理结果，不允许由模型自由改写或增删喵

1. 现场建档用于逐根确认位置、拍摄影像并记录现场环境喵
2. 风险初筛用于依据现场可见信息形成待复核清单，不预先写入检测结论喵
3. 重点精扫用于对现场确认的重点区域执行非破坏性精细采集喵
4. 复核交付用于核对原始数据、影像、记录和成果报告的可追溯性喵

出发清单应作为代码内受控配置或服务端字段维护，不得根据图片内容临时生成喵

- 建档装备包括相机、备用电池、尺寸标尺、构件编号牌和现场记录终端喵
- 环境记录装备包括温湿度仪、风速仪及对应校准记录喵
- 精扫装备包括手持扫描仪、备用电池、数据线和存储介质喵
- 安全装备包括安全帽、防滑手套、警示隔离带和急救包喵

若现有 PRD 或产品负责人给出不同清单，应整体替换此预设并同步测试，不得同时保留两套口径喵

## 附件未明确信息

下列内容必须显示为“待现场确认”或“附件未明确”，不得补写成确定事实喵

- 四根木柱的准确位置、朝向和构件名称喵
- 现场联系人姓名和电话号码喵
- 现场供电、网络和设备摆放条件喵
- 实际使用仪器的设备编号与校准有效期喵
- 现场安全边界、临时封控范围及具体进场动线喵
- 任何木材树种、含水状态、病害类型、风险等级和诊断结果喵

## 红头委托视觉资产规则

图片生成工具只负责纸张纹理、拍摄透视、折痕、阴影、红色抬头和非可识别印章质感，不负责生成业务正文喵

所有可读文字必须由 React 和 CSS 根据当前工单详情动态叠加，以保证字符、日期和附件名称逐项准确喵

视觉上必须明确标注“演示样例”，不得使用真实机关名称、国徽、真实公章或足以被误认为真实行政公文的标识喵

图片不得包含模型自行生成的正文、编号、电话号码、签名、二维码或额外附件名喵

图片加载失败时仍要以纯 CSS 纸张版式显示完整、准确的委托内容喵

## 防幻觉硬规则

1. 不对红头图片做 OCR 后再生成工单，图片不是数据源喵
2. 不从语音转写文本中提取工单编号、日期、地点、主体数量或附件名称喵
3. 不使用 `orders[0]` 猜测用户正在查看的工单，必须优先使用显式绑定的待读取 `orderId` 喵
4. 绑定工单不存在、已删除或无权限时必须停止导航，并明确提示“当前委托无法读取，请重新打开新工单通知”喵
5. 服务端返回 `restricted` 时不得展示委托正文和附件，只能显示该账号获准查看的摘要喵
6. 未产生风险记录时不得生成风险等级、缺陷位置、置信度或处置结论喵
7. 未采集环境数据时不得沿用历史温湿度、风速或 EMC 数值喵
8. 未指派人员时负责人显示“未指派”，不得使用历史工单负责人填充喵
9. 未执行扫描仪下发时必须保留下发空态，不得播报“已下发”或“已接收”喵
10. 附件未明确的字段统一进入待确认列表，不得利用常识补全喵
11. 任何工具失败都不得继续播报成功结果，页面应解除半展开状态并显示可恢复提示喵
12. 连续触发多张工单时，每个通知、预览、语音读取和详情页必须保持同一个 `orderId` 喵

## 冲突处理优先级

发生口径冲突时按以下顺序处理喵

1. 用户在当前任务中明确锁定的新要求优先喵
2. 本文档已冻结的验收口径优先于历史演示稿中的旧行为喵
3. 服务端工单详情和权限字段优先于客户端缓存、图片文字和语音文本喵
4. 现有工单 PRD 的幂等、事务、权限和数据完整性要求不得因演示效果被削弱喵
5. 生成图片、旧截图、历史播报音频和过期文档只能作为视觉或排练参考，不能覆盖运行时事实喵

新需求中“喊话后生成完整平台工单”与现有“快捷键触发即事务建单”存在字面冲突时，采用“快捷键完成数据创建，喊话完成读取整理和页面呈现”的解释喵

该解释避免第二次调用建单接口，同时保留妈妈要求的演示叙事喵

## 测试先行要求

实现代码前必须先修改或新增测试，使旧行为失败、新规格可被观察喵

### 快捷键与预览验收

- 按一次快捷键只增加一张工单喵
- 点击“查看”后路由保持不变且委托预览出现喵
- 预览中的单位、地点、日期、主体数量、正文和附件与接口详情一致喵
- 关闭预览不会删除或重复创建工单喵
- 连续创建两单后，分别点击通知可打开各自绑定的预览喵

### 语音与模糊匹配验收

- 标准短语“读取这份工单”命中第①轮喵
- “读取工单”“整理任务”和合理近音结果仍可命中喵
- 只说“工单”或无关命令不得误触发喵
- 小木回复必须与本文档 `v1.0` 文案逐字一致喵

### 跳转与揭示验收

- 语音触发后打开预览绑定的工单，而不是列表第一张工单喵
- 四组模块依次出现，未到拍点的模块不可见喵
- 人员、环境、下发和成果模块不得提前出现喵
- 播报结束后全部模块可见喵
- 播报失败、中断、刷新或手动进入详情时页面最终完整可用喵

### 数据与安全验收

- Z01 至 Z04 仍由服务端一次事务生成喵
- 原始委托正文不出现 Z 编号、雷达结论、风险等级或树种猜测喵
- 无权限账号看不到委托正文和附件喵
- 图片加载失败不影响文本准确性和流程可用性喵

## 1. 产品决策

将当前“上传—更新—检索”的实验工具页，改为面向技术人员的**数据与知识中心**。

整个页面围绕三个问题组织：

1. 平台积累了哪些资料、来自哪里、关联哪个项目或设备？
2. 哪些资料已经进入 RAG 索引，哪些仍在更新或发生异常？
3. 一条检索证据如何追溯到原始资料、构件、工单和历史记录？

采用“两层数据、四个页签、一套状态”的结构：

| 层级 / 页面 | 定位 | 主要内容 |
|---|---|---|
| 源数据资产库 | 普通数据库在产品上的呈现 | 原始文件、结构化业务记录、来源、分类、版本、关联对象 |
| RAG 索引库 | 从资产库派生的检索层 | 可检索内容、分块、向量条目、来源映射、索引版本和更新任务 |
| 总览 | 默认首页 | 资产规模、索引覆盖、更新状态、资产关系图、近期变化 |
| 数据资产 | 管理资料 | 分类筛选、导入、资产详情、内容预览、版本和索引状态 |
| RAG 索引 | 运维检索层 | 覆盖分布、任务流水线、失败处理、配置和版本切换 |
| 检索验证 | 核验知识可用性 | 检索结果、证据出处、关联资料、版本及定位 |

一级导航暂时保留“知识库”，避免影响整个平台的导航认知；进入后页面标题使用“数据与知识中心”。“普通数据库”在界面统一称“数据资产库”，具体物理数据库类型放在技术文档中。

**本期采用的方案：** 复用现有共享服务，真实保存资产元数据、支持范围内的文件和任务记录；使用确定性的演示索引适配器表达 RAG 生命周期。不接入真实嵌入模型、向量数据库或大模型生成服务。

页面页眉保留一个低干扰的“演示环境”标识。详细能力边界收纳到“数据说明”抽屉，不再让免责声明占据业务工作区，也不把模拟状态包装为生产服务监控。

## 2. 现状诊断与改造目标

### 2.1 当前问题

| 当前表现 | 对专业使用者的影响 | 本次决策 |
|---|---|---|
| 上传区反复解释浏览器、不上传、不连接后端 | 主任务被开发说明挤占，像临时实验页 | 删除主界面的重复解释；导入入口改为标准操作 |
| “把小木叫来一起看” | 表述拟人、随意，功能目的不明确 | 删除此按钮，证据操作使用“查看来源”“关联资料” |
| 资料、向量、索引和检索挤在同一屏 | 无法判断平台的数据规模和层次 | 拆为资产库和派生索引库，按页签组织 |
| 只有 5 份资料、13 个分块，关系链仅 13 个节点 | 无法表达多源数据和工程积累 | 提供可展开、可筛选的多源演示数据集 |
| 相似度关系被当作业务关系链 | 不清楚连线代表共同构件、来源还是文本相似 | 明确区分“业务关联”和“索引血缘” |
| 主成分累计、平均密度、标量元素数占据主要位置 | 显示算法过程，却没有决策价值 | 从主界面删除；必要技术字段放配置详情 |
| 一个检索摘要在多个区域重复出现 | 文本密度高，视线来回跳转 | 结果列表加一个详情区域，图节点只放简短提示 |
| 大面积固定空白与多层滚动条并存 | 首屏信息不足，关键状态又被挤到下方 | 按工作区高度布局，列表区域独立滚动 |
| 上传完成与进入索引的区别不清楚 | 容易误以为所有文件都可检索 | 分开显示“资产状态”和“索引状态” |

### 2.2 可验收目标

- 在 1920×1080 和 1366×768 下，首屏能直接看到资产总数、索引覆盖率、当前服务版本、待更新数、异常数。
- 从总览进入任一异常资产详情不超过 2 次点击；从检索结果定位原始证据不超过 2 次点击。
- 主工作区不出现解释实现方式的长段落；空状态说明最多 2 行，算法参数默认折叠。
- 资料新增、替换、删除后，资产列表、指标、任务、图谱和检索结果有一致的状态变化。
- 图中的每条可点击业务关系都有来源字段或明确规则，不用随机连线增加密度。
- 浏览器刷新、多端打开、断线重连后，读到同一会话的同一已提交状态。

## 3. 用户与任务

| 使用角色 | 高频任务 | 页面应直接提供的能力 |
|---|---|---|
| 项目负责人 | 看数据是否齐全，巡检证据是否可追溯 | 项目筛选、来源分布、异常资产、原始记录定位 |
| 算法 / AI 架构人员 | 看索引是否更新、哪些资料未覆盖 | 当前版本、覆盖率、分块与向量条目、失败任务 |
| 平台开发人员 | 导入资料，排查数据和同步问题 | 资产版本、文件摘要、任务错误码、事件时间 |
| 设备 / 巡检工程人员 | 查看构件、设备、工单相关资料 | 按对象查询、时间线、日志范围、关联图 |

上述是产品任务分工，不自动扩大现有账号权限。具体按钮权限见第 13 节。

## 4. 数据资产库与 RAG 索引库

### 4.1 两层关系

源数据资产库负责保存原始事实。文件字节和结构化业务记录都可以成为资产，不要求把视频或日志内容塞进同一个数据库字段。

RAG 索引库保存可用于检索的派生内容及来源映射。一个资产可以产生多个分块，一个资产也可以暂时没有可索引内容。原始文件保留在资产库，索引不替代原始文件。

~~~mermaid
flowchart LR
  A[文档 / 图片 / 视频] --> D[数据资产库]
  B[工单 / 日志 / 设备记录] --> D
  D --> E[分类 · 版本 · 关联对象]
  E --> F[内容提取或已审核文本]
  F --> G[分块与来源定位]
  G --> H[演示索引构建]
  H --> I[RAG 索引版本]
  I --> J[检索验证]
  J --> K[证据与原始资产]
  D --> L[新增 / 修改 / 删除事件]
  L --> F
~~~

图中“内容提取”是产品阶段名称，其本期实际支持范围见第 11 节。OCR、语音识别和真实嵌入不能因出现该阶段而被视为已经实现。

### 4.2 资产分类：四个正交维度

| 维度 | 示例 | 使用方式 |
|---|---|---|
| 资产类型 | 文档、图片、视频、工单、日志、业务记录 | 六个互斥主类，用于数量统计 |
| 文件格式 | PDF、DOCX、XLSX、JPG、MP4、JSONL | 技术属性；不与业务分类混用 |
| 业务分类 | 巡检报告、构件档案、维修记录、设备运行、规范方法 | 可多标签，用于业务筛选 |
| 数据来源 | 人工导入、平台业务、巡检设备、历史归档 | 单一主来源，另存来源系统与原始编号 |

关联对象另外保存：项目、建筑、区域、构件、设备、任务、工单。通过 ID 连接，名称变更不会破坏关系。

**去重计数规则：** 一个工单是一个“工单资产”；工单附件是独立文件资产，并通过“附件属于”关系连接。附件不能再次被统计为工单。结构化日志按批次计资产，同时记录批次内的日志条数。

### 4.3 各类资产的可检索内容

| 资产 | 原始内容 | 索引内容 | 来源定位 |
|---|---|---|---|
| PDF | 文件、页数、版本 | 页面段落、表格文字 | 页码、段落 / 区域 |
| Word | 文件、章节 | 标题层级、正文、表格 | 章节路径、段落编号 |
| XLSX | 工作簿 | 表头与行记录组合 | 工作表、单元格范围 |
| 图片 | 原图、缩略图、采集元信息 | 人工描述、审核标注、预置识别文本 | 图片 ID、标注区域 |
| 视频 | 视频文件、时长、采集信息 | 预置转写片段、事件说明、关键帧描述 | 起止时间码、关键帧 |
| 历史工单 | 工单字段、状态流转、处理记录 | 问题—处置—复核记录 | 工单编号、记录节点 |
| 平台 / 设备日志 | 批次和事件序列 | 按设备、事件和时间窗聚合的记录 | 设备 ID、时间范围、行号 |
| 业务记录 | 采样、检测、校准、发布等结构化记录 | 字段模板生成的可读记录 | 原业务实体 ID、revision |

无文本的图片和视频可以先作为资产管理，状态显示“待补充内容”。本期不会仅根据文件大小估算分块并当作已成功建立索引。

### 5.3 数据资产页签

采用“分类侧栏 184 px + 资产表格自适应”的结构。

侧栏显示六大资产类型及数量；主区顶部提供关键词、业务分类、来源、关联对象、时间、索引状态筛选。高级筛选折叠；默认可见筛选不超过 4 项。

默认表格字段：复选框、名称、类型、关联对象、来源、更新时间、当前版本、索引状态、更多操作。文件大小和资产 ID 放可选列或详情，避免默认出现十几列。

资产详情四个页签：

1. **内容：** 预览或结构化字段、原文定位、可用附件。
2. **元数据：** 来源、分类、对象、摘要、大小、采集时间、负责人。
3. **索引：** 当前资产版本、已索引版本、分块列表、任务结果。
4. **历史：** 版本差异、关联变更、删除 / 恢复事件。

空状态使用“暂无匹配资产”与“清除筛选”；首次无资产使用“导入资料”按钮。异常必须给出具体状态，如“文件缺失”“待补充文本”，而不是统一写“失败”。

### 5.4 RAG 索引页签

顶部一张服务状态卡；中间是“覆盖分布 + 更新任务”；下方为“版本记录”。高级参数在配置抽屉中。

- 服务状态：是否可检索、当前服务版本、最近成功发布时间、待处理变化、异常资产数。
- 覆盖分布：六类资产的已覆盖 / 待更新 / 异常 / 未纳入堆叠条，点击即可跳转过滤后的资产列表。
- 更新任务：运行中置顶，显示任务类型、目标版本、处理数、成功数、失败数、触发来源；完成的任务进入历史。
- 版本记录：版本号、发布时间、构建范围、资产数、分块数、向量条目数、增加 / 修改 / 删除、操作者、当前服务标记。
- 配置抽屉：纳入规则、自动更新开关、聚合窗口、分块策略、演示索引模式、配置版本。参数调整必须产生配置版本，不能偷偷改变旧索引。

### 5.5 检索验证页签

采用“上方检索栏 + 左侧结果列表 40% + 右侧证据详情 60%”。无查询时展示 3 条工作场景示例，不展示算法教程。

查询示例：

- Z04 柱脚历次渗水记录与处置结果。
- 扫描设备在九月巡检期间的通信异常。
- 某工单对应的报告、现场照片和复核记录。

结果卡只展示标题、资产类型、关联对象、两行命中摘要、来源定位。详情区展示完整片段和原始资料入口；相似度和检索配置放“检索详情”折叠区。

默认输出证据列表。本期如提供“证据摘要”，只能基于实际命中片段用固定模板整理，并列出引用；不得补充检索不到的原因、诊断或处置结论。无合格命中显示“未检索到匹配证据”，允许展开“低相关候选”，不把低分结果写成回答。

## 6. 视觉与文案规范

### 6.1 专业化的具体处理

- 延续平台深色背景和青蓝强调色，使用现有设计变量，不重新引入一套装饰性主题。
- 卡片使用细边线、低对比底色；减少切角、发光边框和每个标题前重复的装饰符号。
- 页面标题 22–24 px；模块标题 16–18 px；正文 14 px；辅助信息 12–13 px；核心数字 28–32 px。1366 px 下正文仍不小于 13 px。
- 数字使用等宽数字特性，右对齐；数量使用千位分隔；资产、分块、日志条数的单位必须明确。
- 蓝色表示选中与运行中，绿色表示可用 / 已完成，橙色表示待更新 / 部分异常，红色表示阻断性失败。状态同时有文字，不能只靠颜色。
- 动画仅用于状态反馈：150–250 ms；发布后指标只变化一次，图节点局部高亮约 1 秒，不持续闪烁，不自动旋转。
- 信息优先级是“状态 → 数字 → 对象 → 操作”。定义解释放 tooltip，算法配置放抽屉。

### 7.2 指标定义

| 指标 | 精确定义 | 基线 / 点击行为 |
|---|---|---|
| 资产总量 | 当前筛选范围内未删除的逻辑资产数；多版本计一次 | 1,248；进入数据资产 |
| 纳入索引资产 | 当前纳入策略允许，且符合内容就绪条件的资产数 | 948；进入纳入资产列表 |
| 当前版覆盖资产 | 当前服务索引的来源 revision 与资产当前 revision 一致，且所需分块完整有效 | 900 |
| 索引覆盖率 | 当前版覆盖资产 / 纳入索引资产 ×100% | 900/948 = 94.9%；一位小数 |
| 待更新 | 纳入资产中，尚未覆盖当前版，且处于待处理 / 处理中 / 已取消待重试的资产数 | 36 |
| 更新异常 | 纳入资产中，当前目标 revision 最近一次构建终止于失败，尚未重试的资产数 | 12；进入异常列表 |
| 未纳入 | 未满足纳入策略或内容条件的资产数；保存排除原因 | 300 |
| 有效分块 | 当前服务版本中可访问、未被删除规则屏蔽的分块数 | 18,420 |
| 向量条目 | 当前服务版本中处于有效状态的演示向量记录数；本期一块一条 | 18,420；详情标注演示索引模式 |
| 最近成功发布 | 最新一次索引发布事务完成时间 | 展示完整日期或同日时间 |
| 最长等待 | 最早一个待处理变更到服务端当前时间的间隔 | 无待处理时显示“—” |
| 原始数据容量 | 存在真实文件的去重文件字节总和 | 自动计算；未随包携带的文件不计入 |

公式约束：

~~~text
资产总量 = 纳入索引 + 未纳入
纳入索引 = 当前版已覆盖 + 待更新 + 更新异常
有效分块 = 当前有效向量条目       （仅适用于本期一块一条策略）
向量条目 ≠ 向量维度 ≠ 标量元素数量
~~~

无纳入资产时覆盖率显示“—”，旁边显示“暂无纳入资产”；不能显示误导性的 100%。处理中的分块和向量计入任务暂存指标，不提前加入当前有效总量。

不展示虚构的 GPU 利用率、真实嵌入吞吐、ANN 延迟和生产数据库磁盘占用。检索耗时可测量当前接口的真实响应时间；样本不足时不显示 P95。逻辑向量记录不意味着物理存储了 768 维模型向量。

### 7.3 范围与时间口径

- 顶部项目筛选作用于六项指标、资产卡、图谱与任务列表；各模块回显同一范围。
- 页签内部的关键词和类型筛选只影响当前页内容。若图谱仅跟随选中对象，应显示“当前对象：Z04”，不能仍显示成全项目。
- 所有聚合响应携带 snapshotSeq、servingVersion 和 scope，前端按同一快照成组更新，避免卡片已经加一而列表仍旧。
- 资产采集时间、导入时间、版本更新时间分开存储。列表默认按版本更新时间降序，筛选器允许选择时间字段。
- 使用服务端 UTC 时间保存，界面以 Asia/Shanghai 展示；历史演示事件使用真实的场景时间标签，不通过每次刷新改写为当前时间。

## 8. 关系图：业务关联与索引血缘

### 8.1 图谱要回答的问题

业务关联视图回答“这些资料与哪些工程对象有关”；索引血缘视图回答“这些检索内容从哪里产生、进入哪个版本”。两种视图使用独立边集合，禁止把所有关系混成一张无法解释的网。

| 视图 | 节点 | 边与来源 | 默认观察方式 |
|---|---|---|---|
| 业务关联 | 建筑 / 构件、设备、工单、资产、巡检任务 | 属于、采集自、附件属于、记录对象、处置对象、引用 | 按对象形成业务簇 |
| 索引血缘 | 资产版本、提取内容、分块组、分块、服务索引版本 | 提取自、切分自、索引于、更新自 | 从左到右的有向分层布局 |

示例链路：**Z04 柱 → 五月巡检报告 → PDF 第 2 页 → 分块 C-004 → KB-021**；同时可展开 **Z04 柱 → 渗水工单 → 处置照片 → 复核记录**。这比“几个球按相似度连线”更能说明平台能力。

### 8.2 规模、聚合与性能

- 初始业务图目标 80–120 个实际显示节点，边上限 240；按建筑、构件或设备聚合形成 6–10 个业务簇。数字是视觉预算，不是硬凑的节点数。
- 点击聚合节点按需展开；普通视图最多 180 节点 / 400 边，全屏最多 250 节点 / 600 边。达到预算后显示“继续筛选或收起其他节点”。
- 完整关系集从夹具生成，不预先编造“共 6,000 条关系”。服务返回真实范围统计，如“范围 1,248 项资产；当前显示 96 节点 / 182 条关系”。
- 索引血缘默认按资产与分块组聚合，不能在首屏绘制 18,420 个分块。聚合节点显示“分块 ×20”，点击后展开真实明细。
- 节点坐标按稳定 ID 和业务簇生成初值，局部更新保留旧节点位置。不能每个事件都重排全图。
- 默认二维布局，停止自动旋转；业务图使用稳定力导向或预计算坐标，血缘图使用固定分层坐标。

### 8.3 编码和交互

节点形状区分实体与资产，颜色区分主类；状态使用边框或小标记，不把类别色改成状态色。节点大小只表达聚合数量，图例注明该含义。边的方向表示依赖方向，虚线只用于明确的引用关系；默认不显示所有边标签。

悬停显示名称、类型、关联数；单击高亮一跳邻居；双击或“展开关联”加载下一层；空白点击取消选择。右侧详情通过同一个抽屉显示，不在图下面复制整段检索摘要。

工具栏保留：视图切换、对象筛选、展开层级、适应视图、全屏。支持拖动和缩放；缩放时只显示高优先级标签；选择节点后提供键盘可访问的“关联列表”，Canvas 不是唯一操作入口。

### 8.4 关系可信度

每条业务边至少保存 relationType、fromId、toId、evidenceRef、origin。来源只能是业务字段、人工维护或演示夹具规则。

同一构件的两份资料优先通过构件节点相连，不生成全部两两相连的边。文本相似关系本期不做主视图；未来如保留，应单独命名“内容相似”，同时展示实际分值和算法来源，不把相似性当成因果或业务关联。

## 9. RAG 状态与动态更新规则

### 9.1 三套状态分开表达

不能用一个“正常”代表资产、索引和任务都正常。

| 对象 | 状态集合 | 解释 |
|---|---|---|
| 资产可用性 | 可用、待补充内容、文件缺失、已删除 | 原始资产或可检索文本是否存在 |
| 单资产索引 | 未纳入、待更新、处理中、已覆盖、更新失败 | 针对资产当前 revision 的处理结果 |
| 构建任务 | 排队、运行、成功、部分成功、失败、已取消 | 一次批量更新的执行结果 |

RAG 总状态由两条信息组成：

- **检索服务：** 可检索 / 未就绪 / 不可用。
- **更新状态：** 已同步 / 待更新 / 更新中 / 有更新异常 / 已暂停。

例如“可检索 · 更新中”表示继续提供旧版本检索；“可检索 · 有更新异常”表示部分资产未更新，并非整库不可用。若同时更新中和有失败项，主标签显示“更新中”，异常计数仍可见。通信中断使用“连接中断 · 状态截至 14:32”，不继续显示实时正常。

服务可检索要求：共享服务可访问、存在已发布且可读取的索引版本、版本通过一致性校验。空资产场景显示“未就绪”；接口故障显示“不可用”。不依据一盏固定绿灯判断。

### 9.2 自动更新触发与合并

| 触发事件 | 处理范围 | 规则 |
|---|---|---|
| 新资产纳入 | 新资产当前版 | 生成提取内容和新分块 |
| 内容替换 | 同一资产的新 revision | 旧版继续服务，新版完成后原子替换 |
| 仅名称 / 展示标签变化 | 元数据与关系图 | 不重建文本向量；更新来源展示 |
| 对象 / 权限 / 纳入策略变化 | 关系、过滤或索引成员 | 权限与删除过滤即时生效；必要时新建索引任务 |
| 原始资产删除 | 对应索引成员 | 即时屏蔽检索，随后发布清理版本 |
| 新工单记录 / 日志批次归档 | 新增或变化的记录 | 通过已有业务事件转为资产变化 |
| 分块或索引配置变化 | 受影响资产 | 创建配置 revision，按范围重建 |

自动调度使用“2 秒安静窗口或最早变更等待满 10 秒”启动一批；持续输入不会因不断重置防抖而永不执行。默认每批最多 50 项，同一个索引范围同时只运行一个发布任务，后续变化进入下一批。

同一资产短时间内多次修改只处理最新目标 revision；运行中的任务保留固定输入快照，新 revision 进入下一批。发布前发现构建对象已被删除、权限撤回或配置过期，应跳过 / 终止对应结果，不允许旧事件覆盖新状态。

设备日志先按“设备 + 会话 + 60 秒时间窗”聚合，归档后产生一个日志资产；不能每条心跳生成一份资料、触发一次索引构建。日志记录条数另计，不混入资产数。

### 9.3 流水线与进度

阶段统一为：**检测变更 → 提取内容 → 分块 → 构建索引 → 一致性校验 → 发布**。

阶段展示“已处理 12/36 项”及阶段状态。进度来自完成记录数；无法预先确定工作量的阶段显示“进行中”。演示适配器可设置固定阶段节奏便于讲解，但不得用独立计时器把进度走完后强行标记成功。

任务暂存结果不进入有效指标。完成校验后，一个事务切换服务版本指针、写版本统计和发布事件；所有客户端在同一 snapshotSeq 更新有效分块、向量条目、资产覆盖状态。

### 9.4 失败、重试、取消与版本恢复

- **部分失败：** 允许成功资产形成一个新版本，失败资产保留可用旧版或保持未覆盖。任务显示“部分成功 34/36”，失败数为 2。不得显示“全部完成”。
- **全部失败：** 不产生新的服务版本；保留原服务版本，记录失败任务。
- **重试：** 只处理失败且仍需要更新的当前 revision。唯一键防止重复分块和向量条目。
- **取消：** 已发布内容不受影响；未发布暂存结果不对检索可见，对应资产回到待更新。清理暂存记录采用逻辑标记或延迟回收。
- **发布竞争：** 任务携带 baseServingVersion，发布时比较当前指针；不一致则重新校验差异或重排任务，不能盲目覆盖更新的版本。
- **切换历史版本：** 显示目标版本和预计覆盖变化，点击“切换服务版本”后执行。只切换检索层，原始资产库不回滚。历史分块仍要经过当前删除规则和权限过滤。
- **服务重启：** 检查未结束任务；本期从最后已完成资产检查点重新运行尚未提交部分。不能仅凭前端进度恢复，也不能自动将运行中改成成功。

## 10. 核心交互流程

### 10.1 导入资料

点击“导入资料”打开抽屉，提供“文件 / 目录”和“结构化记录”两种入口；粘贴文本归入文件入口的二级操作。

流程：选择文件 → 校验与预览清单 → 设置业务分类 / 关联对象 → 确认导入 → 资产登记 → 根据规则进入更新队列。

导入清单显示文件名、类型、大小、处理方式、重复状态、预期索引条件。支持多选设置分类；自动分类使用 MIME、扩展名及预置字段规则，允许人工修正，不写“AI 自动理解所有内容”。

完成提示使用“已登记 8 项，6 项进入更新队列，2 项待补充内容”。用户可直接查看资产或任务。文件传输进度与索引处理进度分开，不共用一个 100%。

文件相同但名称不同：通过服务端 SHA-256 识别字节重复。默认复用物理文件；逻辑资产是否相同依据来源系统原始 ID 或用户选择。禁止仅凭文件名合并资产。导入未完成的临时文件不得成为可用资产。

### 10.2 内容更新与版本对照

在资产详情点击“上传新版本”，显示旧版、待导入新版和内容变化标记。提交后：资产 revision 增加；详情显示“当前 v2 / 索引 v1”；覆盖率暂时下降；旧索引继续服务且结果带“来源版本 v1，存在更新”。新版发布后切换并清除该提示。

仅改变文件名或标签不增加内容 revision；增加元数据 revision。分离这两种 revision，避免所有界面编辑都触发向量重建。

### 10.3 业务记录持续进入资产库

工单关闭、巡检报告归档、设备日志批次完成时，复用原业务实体 ID 和 revision 登记资产。若平台暂时没有相应真实事件，排练控制台提供“注入一批示例记录”，产生明确的演示事件；页面不假装监听了尚未接入的设备数据源。

由同一个 sourceSystem + sourceEntityId 确认是否为现有资产的新版本。事件重放不增加资产数。资产详情提供“打开原业务记录”，跨页跳转保留 projectId 和对象 ID。

### 10.4 检索与图谱联动

检索选择明确的服务版本快照执行。点击结果时高亮来源资产和相关构件；“查看血缘”切换至该分块的来源链。翻页、切换图视图不重新生成结果排名。

查询执行后服务版本发生变化时，显示简短的“索引已更新”按钮供重新检索；当前结果保留其版本标识，避免阅读中的证据被替换。已删除或失去权限的结果须即时移除并提示，不继续展示旧片段。

### 10.5 演示脚本与预期数值

| 脚本 | 操作 | 必须出现的变化 |

### 11.2 大规模夹具如何生成

使用固定 seed 和场景模板生成 1,248 条资产记录，以及表中对应的提取内容、分块、索引条目。模板维度包括建筑、构件、设备、时间、工单状态、故障类型、处置记录；ID 和关联规则稳定，重置后结果一致。

夹具分两层：

- **可深入展示样本：** 至少 24 组，覆盖六大资产主类；包含真实可打开的示例文件或完整结构化记录、文本和定位，保证主要演示链路可追溯。
- **规模样本：** 其余条目提供可阅读的场景文本和元数据。若未附原始二进制文件，详情显示“原始附件未随演示包提供”，仅提供记录 / 文本预览，不能出现可点击却无文件的下载按钮。

规模样本是明确的合成资料；不得复制相同片段来制造“独立证据数量”。相同物理文件可以复用，检索去重按来源资产和证据身份处理。夹具生成报告列出资产数、各类数量、分块数、关系数、缺失附件数和错误项。

基线分块数是夹具生成后的验收约束，不是生产规则要求“每篇文档恰好 20 块”。真实导入的分块数始终从实际内容计算。

### 11.3 演示向量与检索技术的选择

本期明确采用 **DemoIndexAdapter**：保存一块一条的向量描述记录，包括 vectorId、chunkId、assetRevision、indexVersion、dimensionConfig=768、mode=demo。无需为 18,420 条记录实际申请稠密向量数组，也不计算全量 PCA。

“向量条目”表示演示索引中真实存在的逻辑记录；768 是配置值，不能拿“条目 × 768 × 4”当作实际磁盘占用。现有 768 维哈希投影如需保留，只用于开发诊断的少量样本，不能与模型嵌入混称。

检索适配器复用现有中文 2–4 元 TF-IDF / 余弦思路，先按项目、权限、对象、日期与版本过滤候选，再排名。评分应使用与服务版本绑定的词项统计；构建后缓存语料统计，避免每次输入都同步遍历全部内容。文本计算放 Node 工作线程或分批执行，不阻塞共享服务的设备通信。

阈值、Top K 和同义词规则使用版本化配置。Z04 等对象 ID 支持精确字段匹配；“五月”按场景年份解释为时间范围并回显筛选条件。没有明确年份的自然语言不隐式指向错误年份。验收检索集单独标注相关证据，阈值根据该集调校；不得沿用 0.15 后人为提高结果分数来制造命中。

### 12.5 事务、事件与客户端恢复

~~~json
{
  "kind": "event",
  "sessionId": "demo-01",
  "seq": 218,
  "type": "knowledge.index.published",
  "entityKind": "knowledgeIndex",
  "entityId": "KB-022",
  "revision": 1,
  "payload": {
    "scopeId": "project-example-temple",
    "previousVersion": "KB-021",
    "servingVersion": "KB-022",
    "jobId": "job-example-01"
  }
}
~~~

事件只作为变化通知或完整领域补丁，不能在前端遇到事件就盲目“总数 +1”。发布事件后拉取同一 seq 或更新 seq 的总览快照；分页资产按需失效刷新。完整事件序号仍属于平台共享会话流，不另建会与原 seq 冲突的计数器。

客户端按序处理：seq 小于等于已处理序号则忽略；出现缺口则缓冲并补事件；无法补齐时拉快照。快照加载期间缓冲新事件，安装 snapshotSeq 后只重放更高序号，防止竞态漏更新。

索引成员写入、版本指针切换、命令幂等结果和发布事件在同一事务完成，提交后广播。广播失败不撤销已提交状态，客户端通过重连补齐。相同 commandId 重复请求返回原结果。

### 12.6 文件与内容处理限制

本期建议默认：单次最多 50 个文件、单文件 100 MiB、单批 500 MiB；纯文本实际解析上限 5 MiB。超过解析限额的文件可以登记为资产，但显示“待补充提取文本”。限制作为配置，不在主界面铺长说明。

确认真实 MIME 与扩展名；原始文件保存名使用服务端生成的 ID，不把用户路径拼进存储目录。预览文本转义，JSON / CSV 不执行任何内容，Word / Excel 宏不运行。下载和预览沿用当前会话与资产访问校验。

新上传文件先保存，再执行资产登记；登记失败的孤立文件记录进入清理队列，避免界面失败而磁盘不断堆积。不能在接入本页时修改平台其他模块现有文件的删除策略。

拆分顺序：

1. 先定义 DTO、夹具和指标不变量，让任何 UI 都读同一快照。
2. 接入服务端资产、任务与发布事务，完成新增 / 修改 / 删除脚本。
3. 做总览和资产页，再替换关系图，最后迁移检索与版本操作。
4. 删除旧版队列状态、重复说明和不再使用的图谱计算，避免两套来源同时运行。

分块和检索纯函数迁移时保留必要回归验证；共享逻辑不可由 Node 直接导入含 React、DOM 或前端种子的模块。可提取为运行时无关的模块，或在服务端实现并对照固定样本验证结果。

迁移不读取浏览器临时状态作为权威数据。如果需要保留既有浏览器导入资料，提供显式“导出旧资料清单 / 重新导入”路径；初始化新的 knowledge-demo-v1 不覆盖平台原有工单、设备、归档文件或其他会话。

## 16. 验收标准

### 16.1 产品与视觉

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| A01 | 1920×1080、1366×768 首屏 | 六项指标、当前服务版本、更新状态同时可见；无横向溢出 |
| A02 | 文案检查 | 主界面没有“不上传任何服务器”“本页不连接后端”“把小木叫来一起看”等旧文案 |
| A03 | 信息密度 | 总览无重复正文摘要；空状态不超过 2 行；算法说明默认不可见 |
| A04 | 状态可辨 | 运行、待更新、异常、未就绪都有文字标识；绿色不覆盖更新异常 |
| A05 | 页面操作 | 导入、过滤、查看异常、证据定位均可通过键盘和鼠标完成 |
| A06 | 图谱 | 初始有多个业务簇；显示数量与实际渲染节点 / 边一致；每条边可追溯 |
| A07 | 图谱稳定性 | 新增一项资料后原有节点不整体洗牌；选中节点不会被刷新清除 |

### 16.2 数据与状态

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| D01 | 基线数量 | 六类合计 1,248；纳入 948；覆盖 900；待更新 36；异常 12；未纳入 300 |
| D02 | 基线索引 | 有效分块和逻辑向量记录均为 18,420；可从记录查询复算 |
| D03 | 新增 / 修改 / 删除 | S01、S02、S03 的前后数值及可检索性逐项一致 |
| D04 | 相同命令重放 | 同一 commandId 提交 3 次，只产生一次登记 / 任务结果 |
| D05 | 事件重放与乱序 | 重复事件不加计数；缺口补齐后与服务端一致 |
| D06 | 更新过程中再次修改 | 旧任务不得覆盖新 revision；新版本保留待更新状态 |
| D07 | 取消与全失败 | 旧服务版本持续有效，暂存块不进入总览和结果 |
| D08 | 部分成功 | 成功和失败分别计数，允许发布成功部分，失败项可重试 |
| D09 | 切换历史版本 | 仅切换索引；当前资产不回滚；已删除内容不重新暴露 |
| D10 | 服务重启 | 已提交版本可恢复，运行中任务从检查点重试而非伪装成功 |
| D11 | 空数据与全排除 | 分母为 0 时显示“—”，无除零和错误的 100% |
| D12 | 页面范围 | 指标、列表、图谱和任务对相同项目范围返回一致结果 |
| D13 | 文件缺失 / 不支持 | 无假正文、假页数、假下载；状态和可执行动作准确 |

### 16.3 检索与共享服务

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| R01 | 预定义查询集 | 至少 20 条查询，包含对象编号、时间范围、多来源、无命中及歧义 |
| R02 | 相关证据命中 | 标注的可命中查询中，至少 90% 在 Top 5 中含一条相关来源；该目标为计划值，实施后报告实测 |
| R03 | 来源定位 | 24 组深入样本均可打开对应内容；PDF 页码、表格范围、视频时间码等与实际文件相符 |
| R04 | 无命中 | 低相关候选不生成确定性回答，不输出无出处诊断 |
| R05 | 权限过滤 | 无权限账号直接请求查询、文件或写接口均得到拒绝，不能只靠隐藏按钮 |
| R06 | 跨端状态 | 两个终端操作同会话，提交后状态最终一致，S07 通过 |
| R07 | 索引发布中的查询 | 每个查询绑定单一已发布版本，不混读新旧成员 |

### 16.4 性能目标与测试方法

以下为开发验收目标，尚未实测。基准环境建议使用交付机的 Chrome、1920×1080、16 GB 内存、同一局域网 Node 服务；测试报告记录 CPU、浏览器版本和数据包版本。

- 1,248 资产、18,420 分块下，总览数据响应 P95 ≤500 ms；热缓存检索 P95 ≤800 ms；至少记录 30 次有效样本，首查单独报告。
- 96 左右图节点的拖动保持可交互，目标 ≥30 FPS；全屏上限场景不得造成连续 500 ms 主线程阻塞。
- 资产分页默认 50 项；检索结果默认 Top 10；分块和任务明细分页读取，不把全部正文加入总览快照。
- 索引构建期间，原有设备通信、页面导航和任务状态查询应持续可用。同步 SQLite 事务短小批量执行，文本计算不在长事务内。
- 无运行中任务时不启动高频计数刷新；事件合并刷新上限约 4 次 / 秒，图谱按需更新。

验证命令优先使用仓库现有 npm run build、npm run lint；针对新增领域逻辑运行 test-knowledge.mjs。UI 使用浏览器实测两种视口，保存总览、图谱展开、失败任务、证据定位四类截图。此 PRD 文档阶段无需重新运行与文档无关的应用测试。

## 18. 主要风险与控制措施

| 风险 | 控制措施 |
|---|---|
| 只把数字改大，资产和关系无法展开 | 先生成实体记录与完整性报告，再实现指标和图谱 |
| 演示流程与真实文件能力混淆 | 导入前显示处理方式，详情标注内容来源，未支持项停留在明确状态 |
| 页面为减字而隐藏必要状态 | 删除解释性长文，保留状态、数量、版本、失败原因和可执行操作 |
| 图变大但更难读 | 业务簇聚合、限制层级、明确边类型、默认二维、来源列表兜底 |
| 旧本地状态与新服务端状态混用 | 一次性迁移数据读取入口，旧状态只用于显式导出 |
| 发布新索引影响巡检设备通信 | 计算分离、短事务、限批调度，联调时并行运行设备业务 |
| 版本恢复重新暴露已删除内容 | 当前删除和权限过滤始终生效，不随索引版本切换失效 |

## 19. 本次评审结论与后续扩展边界

本 PRD 推荐按以下决定进入开发：**数据资产库与 RAG 索引库分层；总览优先；二维关系图表达业务关联与索引血缘；共享服务维护演示状态；确定性索引适配器承接动态更新；检索以来源证据为核心。**

未来需要真实 RAG 时，保持 Asset、Chunk、IndexVersion 和来源定位协议，替换内容提取、Embedding 和检索适配器即可。真实实现还需补充模型评测、召回与重排、存储容量、访问隔离和运行监控；这些不是本期演示需要部署的基础设施。

当前文档未修改页面实现，未部署上述接口，未把规划指标描述成实测结果。

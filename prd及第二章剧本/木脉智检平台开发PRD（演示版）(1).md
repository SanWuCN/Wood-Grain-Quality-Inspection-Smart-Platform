# 木脉智检平台开发PRD与技术实现方案

版本 1.0　编制日期 2026年9月11日　适用对象 前端 后端 联调与演示开发人员

本平台服务于木脉智检国赛展示，连接工单、机器人巡检、手持检测、场景重建、模型适配和修缮跟踪。开发以完整、流畅、可重复的展示为目标：页面和业务数据真正联动，训练与部署使用可控演示任务，小木通过意图识别调用固定工具并组织模板回复，RAG实际检索资料。主流程不部署本地大模型，不依赖外网服务。

本文按最新《3.1木脉智检 第二章》和第一章历史巡检问答设计。第二章S01至S23用于开发定位，不要求在正式界面展示页码、演讲者或比赛计时。本文规定功能和技术契约，页面构图由设计与开发人员发挥。

## 1 产品目标与开发范围

### 1.1 必须完成的展示闭环

历史资料查询并打开旧场景；接收新工单；记录环境并同步参数；显示建图和巡检；导入高斯成果；小木定位Z04疑点；手持初扫触发异常；采集参考样本；自动清洗与人工审核；数据划分校验；展示训练及新旧版本比较；生成和下发更新包；展示设备更新回执；复扫回传；多模态关联；数字孪生查看；创建复核工单；归档校验。

所有页面使用同一组项目、构件、批次和版本数据。点击场景中的Z04，应打开该构件的图像、回波与处理记录；从工单点击附件，应回到同一份结果。避免各页面只有孤立的动画和固定数字。

### 1.2 实现边界

| 能力 | 首版实现 | 页面身份 |
| --- | --- | --- |
| 工单、环境、样本、审核、文件、版本、日志 | 数据库真实读写 | 当前会话业务记录 |
| RAG | 本地资料解析、向量索引、检索、来源跳转；模板生成答案 | 资料检索 |
| 小木与语音 | 规则意图识别、工具编排、固定话术；预录音频优先 | 自动化助手 |
| 高斯场景 | 真实加载预采重建成果，支持自由浏览与标注 | 预采场景 |
| SLAM与巡检 | 优先接已有ROS演示；接口未接通则回放地图、轨迹、视频 | 实时或回放 |
| 手持数据 | 优先文件导入或本地代理上传；未接通使用预置数据包 | 实采或样例 |
| 清洗与评估 | 可解析样例真实运行规则、分组检查、指标统计 | 标注数据来源 |
| 训练、量化与视觉识别 | 后台演示任务读取预置产物、曲线和标注 | 演示任务 |

每条数据记录source_mode，取live、replay、simulation。来源提示放在任务标题或结果角标，不做满屏提示。历史资料、当前实采、预置结果保留各自批次；一个页面可以并列展示，但不相互覆盖。

首版P0包括本文全部主流程、四角色协作、离线素材、失败重试和恢复。P1为在线语音识别、托管语义向量服务、真实训练服务、正式固件流水线、完整维修单位门户。不能把P1作为完成比赛主流程的前提。

### 1.3 验收目标

开发验收以完整走通一轮、重开会话再走通一轮为准。四个浏览器客户端操作一致；指定断网、刷新、重复点击、数据缺失等故障能恢复。关键页面无占位空按钮，所有成功状态有对应记录或产物。50至53分钟是全场排练目标，不作为后台必须等待的计时规则。

## 2 角色与信息架构

### 2.1 四个账号

| 账号 | 默认工作区 | 可执行操作 |
| --- | --- | --- |
| 沈 项目经理 | 工单与审核 | 环境校验、分组检查、新旧评估对比、工单审核、交付摘要校验 |
| 史 人工智能架构师 | 平台总览 | 小木调用、资料检索、场景发布、训练演示、封装下发、多模态分析 |
| 饶 全栈开发工程师 | 采集与交付 | 手持参数确认、原始数据上传、场景成果提交、更新包接收与回验 |
| 马 具身智能工程师 | 建图巡检 | 地图检查、点位配置、巡检监视、样本位置复核、复巡计划 |

角色限制在后端执行。比赛环境提供固定账号快捷登录，密码由部署配置设置，不把管理员权限写进浏览器。演示控制台使用独立管理权限。经理可以审核业务结果，真实车辆运行仍须具身工程师确认接管条件。

### 2.2 导航与页面

左侧一级导航控制在八项：任务总览、工单档案、建图巡检、数字孪生、检测适配、知识库、报告归档、演示控制。设备状态与个人账号放在顶部；小木作为右侧可展开面板，另提供大屏对话模式。

检测适配下分采集、异常排查、数据集、训练验证、更新交付、融合分析六个页签。切换页签保留筛选条件、当前批次和滚动位置。页面用URL记录job_id、component_id、batch_id，复制链接即可让另一台电脑打开同一对象。

四人浏览器各自导航，不因别人切页而被强制跳转。大屏窗口单独具有presentation角色，通过“投到展示窗口”切换。展示控制权有一个当前持有人；换人时显式交接。小木普通打开操作只影响发起客户端，投屏动作才改变大屏。

## 3 页面功能与展示内容

### 3.1 任务总览与工单档案

总览展示当前寺院、工单、四柱状态、当前阶段，以及地图、场景、手持采集三个通道。主区域用场地概览和本轮任务串联；侧边放待办与最近事件。统计来自数据库查询，未检测显示“未采集”，不显示为零风险。

工单详情包括地点、范围、Z01至Z04清单、任务附件、环境记录、人员分工和操作记录。支持创建、编辑、开始、暂停、归档。开始前验证构件清单和地点；暂停保留所有已生成记录。历史工单与当前工单分列表显示。

环境表单录入温度、湿度、风速、仪表、位置和测量时间。温度必须注明摄氏度，湿度为0至100，风速非负；仪表量程由配置给定。经理运行校验通过后生成不可变配置版本，饶点击接收并返回ack，界面分别显示“已提交”“设备已确认”。演示ack由模拟适配器产生，实机ack必须来自设备代理。

环境补偿页展示补偿前后参考曲线及配置差异。HH平衡含水率只作环境先验。首版直接加载已准备的计算示例或经核对的现有函数，不凭空生成木柱实测含水率；风速不代入HH公式。后端给每条曲线保存来源文件和处理配置。

### 3.2 建图巡检

主视图是可缩放平移的占据栅格地图，叠加小车、轨迹、巡检点、四柱和禁入区。旁侧以视频和通信状态辅助判断，不做一屏全是仪表盘。工具栏提供地图保存、版本选择、路线预览、任务下发、暂停与取消。

建图展示当前地图更新、定位和轨迹，不虚构算法的完成百分比。平台可以显示覆盖情况、更新时间和“采集中／待检查／已保存”。需要原生RViz时可嵌入经配置的远程桌面画面，但首版地图渲染不依赖RViz投屏。

巡检先选择地图版本和点位序列，展示路径预览，再提交任务。收到机器人确认才进入执行中；执行阶段显示当前目标、已到达点、异常和接管记录。路径预览是平台计划，机器人实际路径单独着色。地图版本变更后旧计划需重新确认。

通信状态分别显示地图、位姿、视频和车辆状态更新时间。任一路断流只影响该通道，不把“视频在播放”视为车辆在线。演示车与实机使用明显不同的设备名称，切换来源只能在任务停止后进行。

### 3.3 场景管理与数字孪生

场景库显示历史与本轮场景、来源视频、关键帧、处理记录、版本和发布时间。全栈上传后处于“待检查”，架构师检查并发布，其他客户端收到通知。场景构建页按影像检查、关键帧整理、位姿展示、成果导入依次展开；训练过程使用预置任务记录。

孪生主视图优先占页面约三分之二以上，可自由移动、旋转、复位，按Z01至Z04快速跳转。支持构件标签、表面疑点、雷达响应、巡检路线、历史记录图层分别开关。点击Z04下部热点，展开原图、回波、初筛、融合结果和历史任务；三维位置与业务构件使用ID关联。

提供同构件历史与当前对比，可用视角书签切换或并排查看。场景与导航地图没有完成坐标标定时，以柱号和人工热点对应，不让车辆直接追踪三维点击位置。内部异常以示意响应区域表达，不把手绘虫道、深度或承载能力当成扫描测量。

### 3.4 手持采集与异常排查

采集页选择工单、柱号、测区、扫描方向、配置与模型版本；启动后显示实时预览、接收帧数、文件落盘状态和波形。原始数据、表面图像、结果文件分别呈现接收情况，整批校验通过才报“数据全部回传”。

初扫在指定节点触发“适用域待核验”事件，界面冻结该批次的诊断输出并提示保存、暂停。异常排查分设备状态、信号质量、测区条件、模型适用范围四项，每项可查看记录、填结论并签名。完成检查后创建参考样本采集任务。

首版异常由演示控制事件触发，关联预置证据；真实模式只有实际检查结果或检测程序输出才能触发。不要用固定置信度低于某值就自动判定材种未知。暂停页面状态不等于实际传感器停止，实机须返回确认，未接入则显示“等待操作员确认停止”。

### 3.5 数据集与人工审核

样本列表记录物理样本ID、路径、材种来源、已知状态、标签依据、采集文件与质量标志。未知标签单独管理。小木启动清洗后展示每步输入量、保留量、待审核量及原因，可查看一条记录清洗前后内容。

空文件、格式损坏等确定问题标记不可用；疑似重复、饱和或离群先待审核。每条记录保留原文件，清洗只生成新版本。相似记录按物理样本分组，避免把真实缺陷当作噪声删除。

审核页按职责分配：饶查信号；马查来源和位置；沈查标签和集合分组；史确认版本。全部必要项通过后冻结dataset_version，训练只引用冻结版本。经理的分组检查实际读取训练、验证、测试的物理样本ID，输出交集与冲突清单。

### 3.6 训练验证与更新交付

训练页展示基线版本、数据集、更新范围、学习率、停止条件及输入规格。点击提交生成后台job，依次呈现排队、数据准备、适配、验证、完成。损失曲线、样本预测、日志来自同一份预置实验包，保留“演示记录”身份。

验证页包含新旧曲线、同一测试集的逐样本预测、混淆矩阵、漏检与误报、原有材种回归结果。经理执行的比较程序从归档预测表真正计算统计值；不把动画结束当验证通过。验收规则由配置给出，可预置通过与失败两套案例。

交付页按量化记录、兼容性检查、封装、下发、接收、更新、重启自检、版本确认呈现。包清单展示模型版本、预处理、输入输出规格、目标运行环境、摘要和恢复版本。下载产生真实文件；默认是不可烧录的演示包。饶在自己的账户接收并执行模拟更新，史同步看到回执。

### 3.7 复扫与多模态融合

复扫创建新批次，继承Z04测区位置但重新选择当前配置，不能覆盖初扫。首版准备三条样例响应：疑似受潮0.71、疑似空洞0.84和0.87，对应原始文件、图像和标记。数值仅为剧本演示种子；接实机后读取实际结果，不硬覆盖。

融合页依次显示数据完整性、图像标注、雷达特征、测区匹配和结果汇总。视觉标注从JSON载入，雷达曲线从数据文件绘制。点击任一异常即可联动原图局部、曲线片段和三维热点。

首版融合是明确规则：两路在同一测区提示异常且质量合格，列为优先复核；仅一路异常，列为补充检测；位置不一致或任一路质量不合格，列为待核对。不对两个模型分数做相加平均，不制造一个更高的综合置信度。返回优先级、依据和下一步动作，保存规则版本。

### 3.8 工单跟踪与归档

小木依据所选风险生成复核工单草稿，自动带入位置、图像、回波、结果和建议。经理可编辑优先级、责任部门、处理建议和复巡日期，确认后进入待复核。状态为草稿、待复核、待处理、处理中、待验收、已关闭；验收不通过回到处理中。

施工反馈与验收使用两个独立操作。上传完工资料只进入待验收，人工验收通过才关闭。首版不建立外部施工登录端，由授权演示账号录入反馈与验收案例。复巡计划引用地图版本、观察点和视角书签，生成计划后仍需单独下发。

归档页列出工单、环境、原始数据、图像、地图、场景、数据集、模型记录、更新日志和报告。经理运行实际SHA-256校验，报告缺失和不一致文件。大文件流式读取，结果缓存绑定文件大小、更新时间及摘要；完整性校验不替代内容审核。报告输出HTML打印版及PDF，归档包按清单下载。

## 4 小木语音与自动化方案

### 4.1 不部署大模型的主链路

输入文字或语音识别文本 → 规范化词语 → 匹配意图 → 提取地点、日期、构件等参数 → 补齐当前会话上下文 → 校验权限与业务状态 → 调用白名单工具 → 读取实际返回结果 → 填充回复模板 → 播放语音并执行视图跳转。

小木自研部分是意图规则、业务工具、编排逻辑、状态检查和回复模板。前端显示“查询资料”“读取工单状态”“打开场景”等工具卡片，内容是实际调用状态。模型推理等模拟工具也返回任务ID和模拟标志；不伪造第三方模型日志。

### 4.2 意图目录

| 意图ID | 典型表达 | 工具与成功结果 |
| --- | --- | --- |
| history_summary | 查今年五月示例寺巡检 | 检索报告、查询风险状态、返回摘要与来源 |
| open_history_scene | 打开当时的高斯场景 | 找到历史scene_id并打开书签 |
| unresolved_followup | 还有几个没处理完 | 查未关闭项及下一步；不重新猜地点 |
| site_weather | 查近三个月天气 | 读取工单绑定的天气档案，显示采集日期 |
| compare_columns | 比较四根木柱 | 加载已标注关键帧，按规则返回Z04优先 |
| anomaly_summary | 汇总异常并生成任务 | 读取异常记录，建立补采检查清单 |
| clean_dataset | 启动清洗并列出待审核 | 执行清洗job，返回审核清单 |
| prepare_split | 生成数据集划分 | 按物理样本分组，返回待确认版本 |
| compare_models | 对比新旧模型 | 读取同一测试集预测，计算指标 |
| deployment_check | 检查是否可以部署 | 查审核与兼容条件，列出通过或阻断项 |
| run_fusion | 分析本批次并融合结果 | 启动预置分析任务，生成fusion_record |
| open_evidence | 打开Z04下部的记录 | 定位热点，展开图像与回波 |
| draft_workorder | 生成复核工单 | 按模板建草稿，等待经理确认 |
| create_revisit | 安排下次复巡 | 保存点位与计划，不直接驱动车辆 |

规则采用同义词集合加必需槽位。将“五月／5月”“第四根／4号柱／Z04”统一；优先匹配包含日期和项目的复杂查询，再匹配简单导航。一次请求支持“查询并打开”这一明确组合，其他不支持的组合返回可选动作，不能任意串联。未知输入回复“可查询巡检资料、查看构件或启动当前业务流程”，不猜测执行。

“今年”按平台业务日期解析，演示种子年份在启动时一次生成并冻结。语境中的“当时”“剩下的”从会话最近一次成功查询读取，包含项目、日期范围和结果ID；跨项目后清空。工具修改数据失败时，回复说明失败，不播放成功音频。

### 4.3 语音实现与离线保障

默认提供按住说话、文本输入和常用指令三个入口。P0不做语音模型部署：使用语句按钮触发规范化文本，或操作员输入实际识别文本，后端统一执行意图链路。麦克风按钮不能只录音却宣称识别成功；未接ASR时按钮明确进入“演示语句选择”。

需要真实说话触发时，增加浏览器SpeechRecognition适配器。它兼容性和联网条件不稳定，不能作为唯一入口。[MDN SpeechRecognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)说明其支持限制。ASR失败、无声或超时，自动保留文本输入并显示常用指令，不推进业务。

回复优先使用本地预录音频，静态说明整句录制，动态统计使用分段录音或浏览器speechSynthesis。动态数值一律来自工具结果；整句预录文件绑定数据快照，快照不匹配则只显示文字或改用语音合成。提供停止播放、重播、静音，避免多人同时开麦串音。

浏览器录音需要安全上下文，默认在服务器本机localhost操作语音；其他电脑使用文字入口。如四台都要录音，部署受信任HTTPS证书，不依赖普通局域网HTTP。[MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)规定了相关限制。开场用一次点击启用音频，语音播放结束不作为任务完成的唯一条件。

## 5 RAG知识库的真实轻量实现

### 5.1 资料与状态分开读取

知识库保存巡检报告、构件档案、维修反馈说明、方法文档、场景索引和天气档案。每份资料关联项目、工单、时间、版本、文件摘要和来源位置。结构化工单状态保存在业务数据库。

查询“五月巡检发现几个风险，截止今天解决几个”时，报告内容由RAG检索；风险总数、施工反馈数、验收关闭数按同一项目工单从数据库统计。回复模板把两种结果合并，并分别给出来源。这样施工状态变化后不必重写报告，也不会让语言模板猜数字。

### 5.2 首版检索技术

首版用scikit-learn的TfidfVectorizer建立中文字符2至4字的稀疏向量，余弦相似度排序。无需下载嵌入模型或部署大模型；这是向量检索加资料辅助回答，但不宣传为深层语义理解。向量索引文件与SQLite元数据构成轻量检索存储，不必额外部署Milvus等服务。[TfidfVectorizer官方文档](https://scikit-learn.org/stable/modules/generated/sklearn.feature_extraction.text.TfidfVectorizer.html)提供实现接口。

导入DOCX直接读取段落；PDF优先文本层，纯扫描PDF先人工转成可检索文字，首版不强制加入OCR。每段约300至500汉字、重叠约60字，尽量不切断完整句子。保存原段落序号或PDF页码。资料表格可以转成带字段名的文字，同时保留原表链接。

处理流程为文件校验、文字提取、元数据确认、分块、向量化、索引发布。索引版本采用新建后原子切换，查询绑定一次快照；不要在查询期间修改正在使用的矩阵。保存稀疏矩阵NPZ、词表JSON、IDF数组和版本清单，不从用户文件加载pickle。

检索先按权限、项目和日期过滤候选chunk，再取Top 5。根据排练问题确定无命中阈值；初始可用0.15作调试值，不能当通用指标。查询向量为空或无命中时回答“当前资料未检索到”，允许用户放宽日期，不能返回其他寺院凑答案。

### 5.3 页面体现RAG

知识库页面提供文档上传、分类、索引状态、版本和检索测试。小木答案下方有来源卡片；展开可看到查询词、筛选条件、命中片段与相似度，点击打开资料所在段落。相似度标为“检索相似度”，不能标为病害置信度。

历史问答种子固定为MAY-DEMO-01：6个风险R01至R06；R01至R04已有施工完成反馈；其中R01至R03验收关闭，R04待验收；R05和R06待处理。答案应为“6处风险，施工反馈完成4处，验收关闭3处，尚未关闭3处”。继续问未关闭项，返回R04、R05、R06的不同下一步。

命中报告同时关联历史scene_id和柱底camera_bookmark。小木先返回检索证据，再执行打开场景工具；场景不存在时仅说明预览不可用，保留已查到的文字结果。天气问答优先读取预先准备的归档天气，显示日期和来源；未接外网时不称为正在联网查询。

### 5.4 后续语义检索扩展

P1可将TF-IDF检索器替换为托管Embedding API加本地向量存储，服务端缓存向量。保持Retriever.search接口不变，密钥只放后端。首版已有知识库和来源组件可复用。网络不可用时明确回退到本地索引，不改变资料权限和状态统计口径。

| mapping | S04至S05 | 地图记录、位姿和建图版本 |
| reconstruction | S06至S07 | 预采视频、已发布场景 |

阶段用于组织展示，实际任务分别保存状态。机器人巡检可以与手持采集并行；异常阶段不能只改总进度而遗漏巡检暂停。业务依赖由状态机检查，例如未冻结数据集不能提交训练、未审核不能生成交付版本。

### 7.2 任务运行规则

普通job状态为queued、running、waiting_review、succeeded、failed、cancelled。配置保存阶段顺序、最短动画时长、产物ID和人工确认点。进度由服务端累计运行时间或真实适配器回报产生；曲线播放不等于训练发生。等待审核的任务不得因倒计时结束自行通过。

后台持久化started_at、elapsed_active_ms、current_step、artifact_id和version。浏览器刷新后读取快照并重新订阅事件；服务器重启后运行任务进入可恢复状态，由操作员继续，真实运动任务不自动重发。取消后保留日志和产物，重试创建attempt编号。

### 7.3 WebSocket事件契约

API负责命令，WebSocket负责通知。事件由服务器统一编号；客户端按entity_version丢弃旧事件。使用FastAPI WebSocket实现通知通道，参考[官方文档](https://fastapi.tiangolo.com/advanced/websockets/)。

```json
{
  "event_id": "evt-1042", "seq": 1042,
  "session_id": "session-A", "type": "job.updated",
  "entity_id": "train-01", "entity_version": 8,
  "source_mode": "simulation",
  "occurred_at": "2026-09-11T02:00:00Z",
  "correlation_id": "req-95",
  "payload": {"status": "waiting_review", "progress": 80}
}
```

断线后携带last_seq重连，服务器补发保留范围内事件；超出范围返回resync_required，客户端重新取快照。补发事件只更新界面，不能再次发送烧录、导航或生成工单命令。保存事件和业务更新在同一事务完成，再广播，避免“成功通知发了但记录未存”。

所有改变状态的请求带Idempotency-Key；同一请求重发返回原结果。修改对象同时传expected_version，冲突返回409并提示刷新。客户端按钮请求期间禁用只是辅助，去重必须由后端完成。

### 7.4 演示控制台

管理员可新建排练会话、选择正常或故障案例、暂停动画、继续、触发异常、装载阶段快照、检查缺失素材。跳阶段先生成该阶段需要的完整业务快照，不能只把顶部进度改成完成。每个会话拥有独立数据库记录，历史种子只读复用。

重置新建session并使旧客户端重新绑定，不删除素材原件。存在真实设备运行任务时拒绝重置；具身工程师确认停止后再操作。大屏隐藏控制台入口，日志仍记录谁触发了演示事件。每次加载快照提示受影响对象，避免误覆盖本轮实采。

## 8 小车联动技术实现

### 8.1 接入现状与协议

当前小车是Ubuntu 20.04、ROS Noetic，即ROS1体系，已有SLAM和自主巡航demo。平台对接现有节点，不迁移ROS2或Nav2。Firebat主机、雷达和相机型号用于配置档案，不在第二章平台首页重复做硬件宣传。

RobotAdapter提供get_health、subscribe_map、subscribe_pose、get_video、submit_mission、pause_mission、cancel_mission接口。ROS1通过rosbridge JSON WebSocket或车载Python代理接入，参照[ROS1 rosbridge协议](https://github.com/RobotWebTools/rosbridge_suite/blob/ros1/ROSBRIDGE_PROTOCOL.md)。浏览器只接业务后台；rosbridge不开放给所有客户端任意发布。

联调先只读rostopic list、rostopic info、rostopic hz以及现有launch参数，确认地图、位姿、TF、扫描、视频和任务反馈。/map、/tf、/odom、/scan仅为常见候选；导航可能使用action或厂商接口，不预写/move_base已可用。维护一张名称、消息类型、frame_id、频率、用途、是否允许写入的映射表。

### 8.2 地图与视频

OccupancyGrid按width、height、resolution、origin解析，未知格与可通行格分别着色。网格转世界坐标时应用origin的旋转与平移，Canvas显示处理行方向翻转；用一个已知参考点校验方向，不能只乘分辨率。

后端将地图转PNG或增量栅格，位姿单独推送。建议地图更新1至2Hz、位姿2至5Hz、状态1Hz，作为联调起始值；不把高频原始雷达直接灌进所有浏览器。目标是定位变化可感知，具体频率按实测带宽调整。

视频首版使用已有MJPEG或代理转码流，同源转发；有成熟WebRTC再升级。原始视频不塞进普通JSON事件，不把大量base64图片存数据库。保存视频通道名称、capture_time、received_at、是否回放；深度图与彩色图分别检查可用性。

### 8.3 导航命令与回放

巡检任务绑定robot_id、map_version、点位列表、速度配置版本和当前工单。服务端检查设备在线、定位可用、地图匹配、无冲突任务、具身确认后下发。适配器把标准任务转换为现有机器人接口，按accepted、running、paused、completed、failed回报；不能用HTTP请求成功代替车端接收成功。

运动权限默认关闭，真实接入时只允许白名单任务和取消操作，保留车端急停、人工接管及失联停车机制。界面暂停是业务命令，不等同硬件急停。尚未验证停车回路时，只读监视或使用回放，不让演示逻辑直接发cmd_vel。

回放包包含按时间排列的地图、位姿、视频和状态事件，以统一时钟同步。机器人等待、避障、恢复和到点来自同一条轨迹记录。暂停冻结回放时间；拖动回放位置重新计算状态，不触发实机指令。回放不修改真实设备心跳和电量。

## 9 手持设备与平台的数据通道

### 9.1 首版文件导入与代理

手持设备由树莓派汇总数据、ESP32-S3承担采集控制和端侧任务；原始雷达协议尚待确认。首版先接文件目录：本地Python代理监听采集完成的目录或由饶选择数据包，上传文件和manifest。已有实时协议后替换ScannerAdapter，页面和业务不变。

ScannerAdapter提供health、apply_config、start_capture、stop_capture、upload_batch、get_update_receipt。代理使用设备令牌认证、发送心跳并拉取已授权配置。浏览器无需直接访问串口。配置下发后代理校验字段、保存版本、回报结果；未接硬件时由模拟适配器执行相同契约。

### 9.2 原始数据包契约

```json
{
  "batch_id": "scan-Z04-002", "component_id": "Z04",
  "zone_id": "Z04-lower", "source_mode": "simulation",
  "physical_sample_id": null,
  "config_version": "CFG-02", "model_version": "DEMO-M02",
  "raw_level": "spectrum", "schema_version": "1.0",
  "files": [
    {"role": "radar", "path": "radar.csv", "sha256": "由工具计算"},
    {"role": "image", "path": "surface.jpg", "sha256": "由工具计算"}
  ]
}
```

raw_level允许ADC、IQ、spectrum、features、result_only、opaque，按设备实际输出填写；result_only不能画成已取得原始ADC。CSV样例字段为frame_id、timestamp_ms、channel、bin_index、value、unit；IQ另存i和q。图像关联frame_id或独立时间戳。代理保留设备时间和接收时间，不假设两者天然同步。

多文件先上传临时区，服务端逐项核对大小、摘要和必需字段，再提交batch完成。分块上传记录upload_id及偏移，支持断点续传；重复摘要可复用文件但仍创建本次业务关联。缺图或少帧显示部分接收，未完成不得进入整批分析。

### 9.3 预览与处理

图像与回波按同批次、测区和时间容差匹配，超限显示未匹配。FFT仅对有正确采样定义的时域信号执行；输入本已是频谱时直接绘图，不再FFT。饱和、空帧、非有限值、重复文件等按schema中的量程规则检查，阈值绑定设备配置。

实时预览可以下采样，原始文件不丢弃。波形坐标轴必须注明单位；没有标定距离轴时标频点索引，不把频谱横坐标假写为木柱深度。所有特征输出保留处理版本，便于训练和复扫一致使用。

## 10 高斯场景与空间关联实现

使用MipMap软件离线处理全景影像，平台承担输入登记、流程展示、成果发布和浏览。MipMap是外部软件名称，不等同Mip-Splatting算法。先用实际导出文件做兼容性样例验证，再锁定浏览器格式；保留原始导出文件与转换后的发布文件。[MipMap官网](https://www.mipmap3d.com/)为软件核对入口。

浏览器采用Three.js与Spark加载经验证的高斯成果，可按其官方示例使用SplatMesh；依赖版本成对锁定，不能混用不同版本接口。[Spark官方文档](https://sparkjs.dev/docs/)提供浏览器渲染方案。开发交付必须包含一份能在目标电脑打开的四柱场景，不只交一个空加载器。

场景manifest记录format、asset_url、scene_id、version、单位、轴方向、初始相机、包围盒与书签。热点位置用scene坐标保存，另绑定component_id、zone_id和evidence_ids。高斯点不一定支持普通网格的拾取方式，首版用透明代理网格或屏幕投影标签处理点击。

导航map与场景坐标分离。完成标定后保存T_scene_from_map、标定参考点、误差及有效版本；涉及单目重建尺度时还需尺度参数。初版热点人工放置并按柱号核对即可，不因高斯场景看起来逼真就声称毫米级定位。

大文件先做加载测试，再准备压缩或降采样版本；进入第二章前预加载当前与历史两份场景。切换时释放GPU资源，保留一份低精度备用。加载失败使用全景图浏览作为明确的降级视图，能继续看热点和证据，但不标作高斯渲染。接口支持Range请求和缓存摘要，避免每次切页重新下载整文件。

## 11 清洗训练与部署的演示实现

### 11.1 可真正执行的数据处理

对可解析数据真实执行空值检查、重复摘要检测、数值范围检查。以提取的归一化特征做相似度筛查与可选聚类，结果只作为审核建议。首版聚类可用固定随机种子的KMeans整理示例特征；样本不足或特征不可解析时跳过并说明原因。

划分以physical_sample_id为最小组，固定随机种子并保存组清单。先分组再对训练集做增强；同一原始样本的所有衍生记录保留group_id。未审核标签、未知状态不进入监督训练，单列待核验集合。

### 11.2 训练模拟包

预先制作一个实验包：config.json、epochs.csv、predictions_old.csv、predictions_new.csv、model_card.json、quantization_report.json和日志。任务逐步读取这些文件，形成可点击的真实记录。不同页面必须来自同一实验ID，禁止训练曲线、准确率和混淆矩阵各用随机数。

首版可以设置“新材适配示例”和“原材回归示例”两个测试分组。预测表含sample_id、group_id、label、score、material_group，比较页根据同一threshold计算TP、FP、TN、FN、精确率、召回率和F1；分母为零返回不适用，不显示NaN。样例统计不是项目实测性能。

训练状态结束只代表演示产物已装载。验证规则至少检查测试集一致、标签完整、无分组交叉、预处理版本一致、必要指标条件通过。失败案例可选择漏检增加或旧材表现退化，界面阻止进入发布，供排练和答辩展示。

### 11.3 包类型与固件概念

固件是设备程序；模型是参数与运行定义。平台可以管理三类交付：独立模型包、集成模型的固件包、演示包。当前实机是否支持独立模型IAP待确认，首版默认第三类，不需要临时开发真实烧录链路。

演示包扩展名使用.demo.zip，包含manifest、模型说明、预处理配置、示例验证结果和模拟回执定义，artifact_kind=demo_nonflashable。禁止给占位数据命名成可烧录固件并调用刷写工具。页面可以完整演示量化、封装、下发和重启过程，操作只更新模拟设备记录。

真实固件接入作为独立分支：由现有构建工具提供已验证文件，记录目标芯片、固件类型、模型版本、分区方案或加载位置、运行依赖、摘要与恢复包。平台不凭空假定所有模型都能放进ESP32-S3，也不假定当前实现有双分区或热加载。

### 11.4 模拟更新与实际更新

模拟流程：封装完成 → 架构师下发 → 饶接收 → 校验摘要 → 点击模拟更新 → 写入动画 → 重启动画 → 固定参考输入回验 → 更新模拟版本 → 回传日志。服务端保存每步时间和来源，任一失败停在相应阶段，支持恢复至原模拟版本。

Device对象分开保存live_reported_version与demo_reported_version，界面按当前设备模式选择展示，不能让模拟回执覆盖真机状态。演示期间实机继续使用已准备且验证过的程序；复扫样例与演示版本作为业务关联存在，不意味着硬件确已更新。

后续接实机时只替换DeploymentAdapter：校验artifact_kind、目标设备、签名策略和摘要，调用白名单现有烧录工具，解析退出码、读取设备真实版本和参考输出。升级失败不能靠后台按钮改成成功。SHA-256验证完整性，不等于验证发布者身份；真实包来源鉴别另用签名或受控发布名单。

## 12 项目经理的实际技术操作

经理工作区提供三个校验单元和一个评估入口，均作用于当前工单数据。需要现场敲代码时使用预备模板，只允许指定变量和表达式；不是浏览器任意Python执行器。

环境单元允许补写assert 0 <= relative_humidity_pct <= 100；分组单元补写overlap = (train_ids & val_ids) | (train_ids & test_ids) | (val_ids & test_ids)。后端用AST白名单解释比较、集合交并、赋值和assert，变量只能来自当前数据；拒绝import、函数调用、属性访问与循环，不使用eval或exec。界面明确“受限Python校验单元”。

后端真正执行相同语义的检查，返回passed、details、data_version、executed_at。冲突时列出物理样本ID并允许整组调整，调整后重新运行。输入错误显示语法提示，不播放“核验通过”。

新旧模型比较使用第11节预测表计算，不需要加载神经网络。归档校验由后台流式hashlib.sha256处理服务端允许的文件，经理从已登记资产中选择清单；浏览器不能任意遍历其他电脑的目录。需要检查饶电脑本地文件时，由本地代理执行并返回签名或认证回执。

## 14 API与适配器契约

### 14.1 通用规则

路径统一/api/v1，角色会话认证后按session_id隔离。列表支持limit、cursor与筛选；单次最多100条。成功响应包含data、request_id、server_time；错误包含code、message、details、request_id。文件下载使用鉴权资源ID，不回传服务器真实目录。

## 15 界面视觉与交互要求

整体采用浅色工作区、深色导航、青绿主色和木色小面积强调，突出古建场景与技术工作。场景页让三维占主导，巡检页以地图带视频，适配页以曲线、样本和任务阶段组织，知识库以对话和证据展开；不要所有页面都是相同的四张卡片。

总览突出当前任务与待办，不堆无实际作用的大数字。技术细节如索引、工具调用、数据版本、曲线参数放在可展开面板；表单和日志允许切到完整技术视图。设计稿需要包含总览、巡检、孪生、训练验证、小木检索五张重点页面及公共组件。

主要目标分辨率1920×1080，兼容1366×768。大屏模式收起导航和次要工具，建议正文不小于18px、关键结论24px以上；普通操作模式可按密度调整。状态同时用文字和颜色，不能只靠红绿。弹窗不遮住现场最重要的场景或停止控件。

所有页有加载、空数据、错误、断线、部分完成和成功状态。按钮点击立即有响应；长任务显示当前步骤和可查看日志，不无限转圈。首次进入引导先选择工单；切换工单时提示未保存表单。快捷操作支持键盘，提交与删除不能共用同一热键。

小木工具过程采用短步骤卡片：动作、对象、状态、结果入口。思考动画可用于等待真实工具，但不显示虚构长篇推理。图表使用真实或预置文件数据，无数据即提示待导入，不生成随机曲线填空。

## 17 部署运行与故障恢复

### 17.1 局域网部署

一台稳定电脑作为平台服务端，接比赛路由器有线网络；四个客户端访问固定局域网地址，小车与手持代理接同一路由。若N100承担机器人任务，优先另用队员电脑运行平台，避免争抢导航资源。三维渲染在浏览器本机，需提前测试投屏电脑性能。

交付启动脚本负责检查端口、存储空间、数据库迁移、素材摘要、索引、服务与设备通道。配置密钥不进前端产物，服务日志脱敏。平台对外仅提供一个业务入口，ROS桥限制为平台服务器访问；CORS只允许已配置来源。

首次部署创建账号和种子，之后启动不能自动覆盖已有排练数据。启动后可查看健康检查页；先预载两份场景和音频，再开启本轮会话。停机时先停止设备任务，再等待上传和数据库事务完成；备份使用SQLite备份接口或一致性快照，不直接复制忙碌数据库而漏掉WAL。

### 17.2 失败恢复表

| 情况 | 界面与后台处理 |
| --- | --- |
| 浏览器刷新或断网 | 恢复快照和事件，不重复执行任务 |
| ASR不可用 | 保留输入文本和常用指令；不推进成功状态 |
| 语音播放失败 | 字幕继续显示，可手动重播，不阻塞业务 |
| 场景过大或加载失败 | 重试低精度成果或切换标明身份的全景视图 |
| 小车断连 | 标记最后更新时间，禁止新下发；由车端与人工接管停车 |
| 手持上传中断 | 保留临时块，恢复后校验再提交整批 |
| 清洗审核未通过 | 保留原数据和待办，阻止冻结训练版本 |
| 模型验证失败 | 显示未通过项，保留旧版本，允许选择通过案例重新演示 |
| 更新失败 | 保留日志和原版本，模拟与真实恢复分开处理 |
| 后台进程重启 | 恢复持久化记录，运行任务待人工继续，不自动恢复运动 |
| 资料未命中 | 返回无结果和筛选条件，禁止拼接其他项目资料 |
| 缺素材 | 控制台列出精确文件和受影响阶段，开演前修复 |

上传限制单文件类型与大小，对场景提供可配置大文件限额。压缩包解压检查目录穿越和解压后总大小；SVG、HTML等主动内容不直接作为任意附件执行。日志和音频不包含密钥。演示控制接口同样要鉴权，不能仅用前端隐藏。

## 18 开发分解与验收用例

### 18.1 实施顺序

第一阶段建立项目、会话、实体ID、种子和API骨架，先跑通历史查询至归档的纯离线业务。第二阶段完成五个重点页面、实际RAG、状态机、小木和三处经理校验。第三阶段接入真实高斯成果、机器人回放与手持文件导入，完善模拟训练部署。第四阶段接已有ROS与手持代理，保持回放分支可用。第五阶段多机联调、全程排练、故障恢复和素材替换。

不先投入真实大模型和训练服务器。开发量取决于可用场景素材、设备协议和界面现成组件，排期由团队按上述工作包估算。每阶段交付可启动版本、配置样例和对应验收记录，不能只交静态页面截图。

### 18.3 性能与交付要求

以下为待实测的验收目标，不是既有性能：四客户端下普通保存响应95%不超过1秒；小木本地检索通常2秒内返回；状态变更2秒内同步；三维低精度成果在预载后可及时切换。场景帧率目标不低于25fps，达不到时降低点数或分辨率，不影响证据操作。大文件上传和摘要计算展示进度，不套用普通接口时限。

交付包括前后端源代码、依赖锁文件、数据库迁移、完整种子、素材清单、启动脚本、环境配置样例、API说明、设备映射表、测试记录与一次完整操作录像。提供“正常全流程”“模型验证失败”“更新失败”三套可重复场景。开发完成标准是团队四人能够按剧本独立操作，不需要开发者临场修改数据库。

## 19 联调时补齐的参数

以下项目不阻碍首版开发，以配置项或适配器预留：小车实际Topic和导航接口、视频地址、地图坐标关系；手持原始数据级别和格式、配置确认协议、实际更新路径；MipMap导出格式与场景体积；最终寺院名称、年份、历史资料和音频；正式指标、标定曲线与回验输入。未补齐时按本文离线种子运行。

与现有剧本衔接时，只需统一几处运行身份：训练与部署采用演示产物时显示相应标志；天气使用归档资料时不说实时联网；小木使用工具编排与模板回复时不将固定回复称为实时大模型推理。本文不改动剧本文件，开发人员根据实际接入结果向团队提交最终运行模式表。

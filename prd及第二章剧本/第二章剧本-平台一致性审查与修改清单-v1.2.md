### 关于「禁止把占位数据当可烧录固件」——你的直觉没错

这句话的本意**不是**"不许演烧录"，而是防止一个具体的翻车场景：

> 有人拿一个 **8 KB 的占位文件**，把扩展名改成 `.bin`，就管它叫"设备固件"，然后声称做了真实刷写。**评委一看文件大小就露了。**

所以正确的做法是**把包做得像真的**，而不是不演：

| 要做 | 具体 |
|---|---|
| 文件名像真的 | `DEMO-M02b-mumai-scanner-v1.4.2.bin`（而不是 `demo-model.bin`） |
| **大小像真的** | 模型包做到**几 MB–几十 MB**量级（现在的演示包只有 8 KB，这个必须换） |
| 清单齐全 | `manifest.json` + 模型说明 + 预处理配置 + 示例验证结果 + **SHA-256** |
| 版本号能对上 | 写入前显示的版本 ≠ 写入后读回的版本，**有变化才像真烧录** |
| 进度与阶段文案 | 擦除 → 写入 → 校验 → 重启 → 读版本，**每段有耗时和百分比** |

**PRD 那句话建议改成**：「演示包的**字节内容可以与真实固件不同，但名称、体量、清单结构与摘要必须与真实交付物一致**；不得以明显失真的占位文件充当固件。」——**意思一样，但说的是"要做像"，不是"不许做"。** 这条建议一并改到 PRD 里去（见 M 类末条）。

### J-02　「指派」是项目经理**专属**权限，架构师没有

### J-04　「确认收到数据」这种人工 ACK 已被废止
- **剧本位置**：S02（行 53）饶「**确认收到数据！**我现在来审阅工单信息。」
